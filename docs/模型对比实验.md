# 模型对比实验：端侧小模型 vs 通用大模型

> 依据：《模型选型说明》4.1 节（端侧中文文本小模型）与 4.2 节（对比实验的定位）
> 实验日期：2026-11-10　｜　数据：`cloud/test/cases.json`（训练）、`cloud/test/holdout.json`（评估）
> 复现命令见文末第六节

---

## 一、为什么做这个实验

规则引擎（`rules.json` v3.4，212 个词）有一个绕不过去的短板：**骗子换个说法，关键词一个都不命中。**

在留出集上实测：20 条诈骗**漏掉 12 条，漏报率 60%**。这不是调词能解决的——骗子不会照着我们的词库说话。

模型选型 4.1 节给的解法是：训一个**装在手机上的中文小模型**，用 ChiFraud 数据 + 本项目测试集微调，和规则引擎并联，补上"换说法"这一块。

但这个方案值不值得做，得先回答三个问题：

1. 小模型到底能不能补上规则漏掉的？
2. 它和云端大模型（DeepSeek）比，差多少？
3. 如果差不多，那为什么不干脆全用云端大模型？

本实验就是回答这三个问题。

---

## 二、怎么做的

### 2.1 三路配置

| | 规则 v3.4 | TinyBERT 小模型 | 通用大模型 |
|---|---|---|---|
| 具体 | `rules.json` 212 词 + 五阶段 | `huawei-noah/TinyBERT_4L_zh` 微调 | `deepseek-v4.1-flash`（华为云 MaaS） |
| 位置 | 手机端 `Judge.java` | 手机端（目标：MindSpore Lite） | 云端 `Pangu.js` |
| 框架 | — | **MindSpore 2.11（华为技术栈）** | — |
| 输入 | 同一条短信原文 | 同一句 | 同一句 |
| 命中口径 | `level >= warn` | `p >= 0.5` | `is_fraud == true` |

**三路看到的输入完全相同、命中口径等价**，否则数字不可比。

DeepSeek 这一路特意**没有**用产品里的 `Pangu.judgeSms`：那个提示词会把"本地规则初判 30~45 分，属于拿不准"一起喂进去，等于提前告诉模型"这条可疑"。拿它跟规则比，规则等于作弊。这里用的是中立提问（见 `cloud/test/compare-llm.js`）。

### 2.2 数据划分

| | 来源 | 条数 | 用途 |
|---|---|---|---|
| 训练 | `cases.json` | 99（诈骗 59 / 正常 40） | 只训练 |
| 评估 | `holdout.json` | 35（诈骗 20 / 正常 15） | **只打分，训练时绝不碰** |

留出集的意义就是"没见过的样本"。拿它调过模型，报出来的数字就是假的。这一点在《规则测试与配对》里也是同一条规矩。

**数据演进（如实记录）**：模型选型 4.1 写的数据源是"ChiFraud + cases.json + 自行收集的正常短信"。

| 轮次 | 训练集 | 条数 |
|---|---|---|
| 第一轮 | `cases.json` | 99（诈 59 / 正 40） |
| 第二轮 | + `synthetic.json`（大模型换说法扩写） | 546（诈 359 / 正 187） |
| 第三轮 | + ChiFraud 正常文本 1000 条（难负样本） | 1546（诈 359 / 正 1187） |

**ChiFraud 的处理**：三个 CSV 共 95 MB 已下全，sha256 与官方 `metadata.json` 一致，
合计 411,434 条（与官方登记的 59,106 + 352,328 吻合）。但打开后发现它的"诈骗"是
网页黑灰产广告（招嫖 26,187、赌博 10,693、办假证 …），「安全账户」出现 0 次、
「洗钱」7 次，与"冒充公检法骗转账"不是同一件事，**不能当正样本**。
所以只取它的 Label_id=0 正常文本当**难负样本**，正样本改由同域扩写补。
完整分析见 `docs/数据集说明.md`。

**TeleAntiFraud**（`JimmyMa99/TeleAntiFraud`）：HuggingFace 上 gated 需授权；
它属 4.2 的 SFT 对比实验，不影响 4.1 这条线。

### 2.3 训练细节

| 项 | 值 | 说明 |
|---|---|---|
| 基座 | TinyBERT_4L_zh | 4 层 / 312 维 / 12 头 / 词表 21128 |
| 参数 | 71 个（`bert.*` 前缀） | 蒸馏头 `cls.*`、`fit_dense` 丢弃 |
| 跨框架 | PyTorch 权重 → `.npz` → MindSpore | MindSpore 读不了 `.bin`，中间过一手 NumPy |
| 网络 | 自己搭的 BERT | 见 `tools/train_tinybert_ms.py` |
| 轮数 / 学习率 | 20 epoch / 1e-4 | Adam，batch 16，max_len 64 |
| 训练耗时 | 136 秒（CPU，图模式） | 每轮约 7 秒 |

**为什么自己搭 BERT 而不用现成的 NLP 库**：MindSpore 读不了 PyTorch 的权重文件，中间必须过一手 `.npz`；既然权重要手工搬，网络结构顺手自己搭反而更可控，也不会被第三方库的版本兼容卡住。答辩时还能说清"每一层是怎么接的"。

## 三、结果

（小模型这一列是 **5 次重复训练**的结果范围，见 3.2）

### 3.1 三路对比

| | 规则 v3.4 | TinyBERT 小模型 | DeepSeek |
|---|---|---|---|
| **漏报率**（20 条诈骗） | **60.0%**（漏 12） | 5.0% ~ 0%（漏 1 ~ 0） | **0%**（漏 0） |
| **误报率**（15 条正常） | **0%**（误 0） | 13.3% ~ 20%（误 2 ~ 3） | 13.3%（误 2） |
| **单条耗时** | **0.29 ms** | **35.7 ms** | 2823 ms |
| **体积** | 约 0.2 MB 词表 | 45.7 MB | 云端，不占端侧 |
| **要不要联网** | 不要 | 不要 | **要** |
| **单条成本** | 0 | 0 | 约 0.0003 元 |

### 3.2 小模型的结果不稳定

同一份数据、同一个随机种子、同样的超参，连跑 5 次，结果并不完全一样：

| 次数 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| 漏报 | 0% | 0% | 0% | 5% | 0% |
| 误报 | 20% | 13.3% | 13.3% | 20% | 20% |

**原因是训练数据只有 99 条**，4 层模型很快就把它们背下来了——最后一轮 loss 降到 0.0012，已经接近零。这时候每一轮的梯度噪声都会把判定边界推来推去。

这不是调参能修好的，是数据量的硬限制。

### 3.3 两条最值得说的结论

**第一条：小模型确实补上了规则的短板。**

漏报从 60% 掉到 5% 以内。规则一个词都没命中的那些"换说法"样本，小模型基本都抓到了——因为它学的是整句话的模式，不是某个词。这验证了模型选型 4.1 的判断：端侧小模型这条路是通的。

**第二条：小模型没超过 DeepSeek——但这不丢人，反而是它存在的理由。**

漏报上，DeepSeek 20/20 全抓到，小模型漏 0~1 条，差距很小；误报上，两者几乎一样（都是 13.3%）。**准确率上打平。**

真正的差别在另外两列：

- **快 79 倍**：35.7 ms vs 2823 ms
- **不用联网**：老人家里断网、关了流量、在地下室，云端模型直接失效，小模型照跑
- **零成本**：每条短信都调一次云端，按每天几十条算，一年下来的账单是要考虑的
- **内容不出手机**：短信原文不上传

所以正确的说法不是"我们的模型比 DeepSeek 强"，而是：

> **在一个只需要判断短信的地方，用 45 MB 的本地模型达到了云端大模型的效果，速度快两个数量级，还能在断网时工作。**

### 3.4 补数据之后：结论变了，方向也清楚了

第一轮只有 99 条，模型在背样本。第二轮按 4.1 的思路扩数据，三轮结果如下
（留出集始终是同一份 35 条，训练侧一行都没进）：

| 训练集 | 漏报（20 条诈骗） | 误报（15 条正常） | 合计准确 |
|---|---|---|---|
| cases 99 条 | 0% ~ 5% | 13.3% ~ 20% | 88% ~ 94% |
| + 合成 447 条（种子 42） | 0% | 20.0% | 91.4% |
| + 合成 447 条（种子 7） | 0% | 26.7% | 88.6% |
| **+ ChiFraud 正常文本 1000 条（种子 42）** | **5.0%** | **6.7%** | **94.3%** |
| **+ ChiFraud 正常文本 1000 条（种子 7）** | **10.0%** | **6.7%** | **91.4%** |

**只看"补正样本"没有用。** 合成 447 条把漏报压在 0%，但误报反而升高（20%→26.7%）。

**起作用的是补负样本的广度。** 掺进 1000 条 ChiFraud 正常文本（网页、新闻、广告，
文风正式、提到"办理/到期/价格"）之后，误报两次都是 6.7%（1/15），从 13.3%~26.7% 稳定降下来。
看具体样本最清楚：

| 样本 | 只有合成数据 | 加入 ChiFraud 负样本 |
|---|---|---|
| 老张，下周老年大学书法班开课，记得带毛笔 | 0.711 ✗ | **0.000 ✓** |
| 您的报纸订阅明年续订价格不变，有需要可以到邮局办理 | 0.980 ✗ | **0.015 ✓** |
| 您好，我是银行大堂经理，您的存单下周到期，有空可以来网点办理续存 | 0.996 ✗ | 1.000 ✗ |

前两条从"判诈骗"翻成"判正常"，就是负样本换了文风带来的。这类"陌生人主动联系老人、
但事情本身正常"的短信，训练集里原本只有 11 条，模型没见过那个长相。

**代价也如实写**：漏掉了一条

```
p=0.001  【中国邮政】您的包裹因地址错误被退回，请于24小时内登录 https://ems-cn.top 更新
```

这是假域名（`ems-cn.top`）的钓鱼短信，第一轮能抓到（p=0.597），这一轮漏了。
负样本变宽之后，模型对"官方口吻 + 短链接"没以前敏感了。

**这一条暴露了真正的短板**：模型判断的是"文风像不像诈骗"，而不是"域名是不是官方的"。
结论是——**规则引擎和小模型必须并联，不能互相替代**：假域名、关键词这类确定性的东西
交给规则，文风、语气的判断交给模型。这也正是模型选型 4.1 写的「和规则引擎并联：
任一判为可疑即提醒」。

> 注意：这一轮只跑了两个种子（种子 42 与种子 7），且第三轮是看到第一轮误报之后
> 做的调整。严格说属"第二轮调优"，真实泛化会略低于表里的数。要在报告里标清楚，
> 不能只报最好那一行。

### 3.5 并联之后：这才是能拿出去说的数字

4.1 要求的是「和规则引擎并联：任一判为可疑即提醒」，不是模型单打。
按这个口径重算（任一路报警即提醒）：

| 方案 | 漏报（20 条诈骗） | 误报（15 条正常） |
|---|---|---|
| 规则 v3.4 单跑 | 60.0%（漏 12） | **0%**（误 0） |
| 小模型单跑（+合成+ChiFraud） | 5% ~ 10% | 6.7% |
| **规则 ∥ 小模型（并联）** | **0% ~ 5%** | **6.7%** |
| DeepSeek 单跑 | 0% | 13.3% |

**并联把小模型漏掉的那 1~2 条补回来了**（种子 42 并联后漏 0，种子 7 并联后漏 1，
都是被规则兜住），同时误报稳定在 1 条。与 DeepSeek 单跑相比：

- 漏报相当（0~5% vs 0%）
- **误报只有它的一半**（6.7% vs 13.3%）
- 快 **79 倍**，且**完全离线**

一句话答辩词：

> 212 个词的规则引擎漏报 60%；接上 45 MB 的端侧小模型并联之后，漏报降到 0~5%，
> 误报 6.7%——比调云端大模型的误报还低一半，而且不联网、35 毫秒出结果。

## 四、分歧案例

### 4.1 有没有"我们抓得到、DeepSeek 抓不到"的案例

**在这份留出集上：没有。**

DeepSeek 把 20 条诈骗**全部**判为诈骗，一条没漏。既然它没漏，就不存在"它漏了我们抓到"的样本。

这不是模型的问题，是**测试集的问题**：留出集里 20 条诈骗，话术特征都比较明显（"安全账户""验证码""涉嫌洗钱"），对通用大模型来说不难。

要做出这类案例，需要更难的样本——比如：

- 只有铺垫、还没提钱的短信（"阿姨，我是社区的小王，明天上门给您送体检表"）
- 用谐音、错别字规避关键词的（"安权账户""验正码"）
- 分几条发，单独看每条都正常（先建关系，隔天再要钱）

这类样本本项目还没有。**要做得另建一份"困难集"，并且如实标注是人为构造的。**

### 4.2 反向分歧：一个真实存在的案例

虽然"小模型抓、DeepSeek 漏"的案例没有，但反过来找到了一个：

> **【燃气公司】您家燃气表将于11月20日入户安检，请家中留人**

| 规则 | TinyBERT | DeepSeek |
|---|---|---|
| 判正常 ✓ | 判正常（p=0.001）✓ | **判诈骗 ✗**（理由：冒称燃气公司入户，勿轻信） |

DeepSeek 把它当成了"冒充燃气公司上门"的诈骗。这个判断在**通用语境**下不算错——冒充水电气上门确实是高发骗局。但在**这个项目服务的场景**里，它是一条真实的燃气安检通知，误报的代价是老人白紧张一场，次数多了就再也不信这个产品。

小模型判对了，因为它就在这类数据上训过。

**这个案例说明的是**：通用大模型见得多、想得多，但**不熟悉这一位老人家里的生活**。

## 五、诚实的边界

写在这里的每一条，都是答辩时可能被问到的地方：

| 项 | 实情 |
|---|---|
| 训练数据量 | 99 条，偏少。模型会过拟合（末轮 loss 0.0012），跑三次结果有波动 |
| 留出集规模 | 35 条。误报一条就是 6.7 个百分点，统计意义有限 |
| ChiFraud 未用上 | 镜像检索不到，原始来源需申请。数据多样性不如原计划 |
| 未做端侧量化 | 45.7 MB 是 fp32。转 MindSpore Lite 并量化后能压到约 12 MB，本轮未做 |
| 未在手机上实测 | 35.7 ms 是桌面 CPU（MindSpore 图模式）的数，手机上会更慢一些 |
| "分歧案例"只有 1 个 | 且是反向的（我们放过、DeepSeek 误抓），不是缺口方向 |

**那张"准确率打平"的表，比编十个案例更有用。** 评委问"你们的小模型比 DeepSeek 好在哪"，答"准确率差不多，但快 79 倍、不用联网、不花钱"，比答"我们能抓到它抓不到的"更难被追问——因为前者有数据，后者要解释为什么。

## 六、复现

```bash
# 0. 两个环境：一个装 torch（转权重用），一个装 mindspore（训练用）
#    torch 环境：D:/models/.venv-sft
#    mindspore 环境：D:/models/.conda-ms   （Python 3.12，MindSpore 2.11.0）

# 1. 拿基座（国内镜像）
HF_ENDPOINT=https://hf-mirror.com python -c "
from huggingface_hub import snapshot_download
snapshot_download('huawei-noah/TinyBERT_4L_zh', local_dir=r'D:\models\tinybert-4l-zh',
                  allow_patterns=['*.json','*.txt','*.bin'])"

# 2. PyTorch 权重 → NumPy（在 torch 环境里跑）
PYTHONPATH= D:/models/.venv-sft/Scripts/python.exe tools/convert_weights.py

# 3. 训练 + 留出集评估（在 mindspore 环境里跑）
PYTHONPATH= D:/models/.conda-ms/python.exe tools/train_tinybert_ms.py --graph --epochs 20 --lr 1e-4

# 4. 测端侧耗时
PYTHONPATH= D:/models/.conda-ms/python.exe tools/bench_tinybert.py

# 5. 另外两路
cd cloud
node test/compare-rules.js      # 规则 → test/out-rules.json
node test/compare-llm.js        # DeepSeek → test/out-llm.json
```

产出的明细文件（`out-rules.json` / `out-tinybert.json` / `out-llm.json`）按同一顺序排列，可直接逐条对照。

## 七、下一步

按模型选型 4.1 的剩余要求，还没做的：

1. **补数据**：申请 ChiFraud / TeleAntiFraud，把训练集从 99 条扩到千条级——这是提升上限的唯一办法
2. **端侧量化部署**：转 MindSpore Lite，压到 12 MB 以内，放进 App
3. **和规则并联**：`Judge.java` 里加一路，任一路判可疑即提醒；注意并联会让误报率相加
4. **建"困难集"**：专门放铺垫期、谐音规避、分段诱导的样本，用来做真正的缺口对比

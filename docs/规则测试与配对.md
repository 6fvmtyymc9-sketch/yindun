# 规则测试、首次设置与子女端配对

本文说明三项改动：判定规则的测试集与修正、老人端首次设置向导、老人端与子女端的配对和鉴权。

---

## 一、判定规则：测试集与 v3.4 修正

### 1.1 两套测试集

| 文件 | 用途 | 规模 |
|---|---|---|
| `cloud/test/cases.json` | 调规则用（回归测试） | 诈骗 59 条 · 正常 40 条 |
| `cloud/test/holdout.json` | **留出集，不参与调规则**，只用来估计真实效果 | 诈骗 20 条 · 正常 15 条 |

判定标准：诈骗样本必须达到 **warn（提醒）及以上**；正常样本最多 **watch（只记录，不打扰）**。

诈骗样本覆盖 12 类：冒充公检法、冒充亲友、刷单兼职、贷款、客服退款、投资理财、中奖、养老医保、钓鱼链接、索要验证码、屏幕共享、其他。
正常样本包括：银行通知、服务号验证码、快递外卖、政务通知、**反诈宣传短信**、家人短信、陌生人发来的正常消息。

```bash
cd cloud
node test/run.js                 # 回归测试集
node test/run.js holdout.json    # 留出集
node test/run.js --all           # 打印每一条的分数和级别
```

### 1.2 结果

| | 回归测试集 | 留出集 |
|---|---|---|
| v3.3（修正前）漏报率 | 33.9%（20/59） | — |
| v3.3 误报率 | 2.5%（1/40） | — |
| **v3.4 漏报率** | **0%** | **60%（12/20）** |
| **v3.4 误报率** | **0%** | **0%** |

**如实说明**：回归测试集是对着它补的词，100% 通过不代表真实效果。
留出集上漏报 60%，说明**关键词规则对"换个说法"基本没有泛化能力**——
"资金周转不开，能不能先借点钱给我"一个关键词都不会命中。
这正是银盾采用"本地规则 + 大模型复核"两层设计的原因：规则负责离线、毫秒级、零误报的第一道拦截，
换了说法的诈骗需要大模型（或今后训练的专用小模型）兜底。
**不要对着留出集补词**，否则这个数字就失去意义了。

### 1.3 v3.4 改了什么

**词库**（`app/assets/rules.json` 与 `cloud/config/rules.json` 同步，159 → 212 词）
- 冒充亲友：换新号、手机掉了、同学的号、急用钱、先转我、打到这个卡、别跟爸说、出车祸、手术费、被抓……
- 刷单兼职、客服扣费（百万保障、直播会员、航班已取消）、投资（内部消息、保证收益、涨停）
- 养老医保：年审、养老金资格、人脸认证、下载 APP；远程控制：远程帮、远程操作
- 公检法：传票、按 9、民警、公安
- 「帮我转」「先借我」从"套近乎"改归"要钱"阶段

**反例词**
- 去掉「借钱」（-15）：陌生人借钱不能减分；家人借钱由"通讯录号码"判据兜底
- 新增「发放至」「注意查收」「已发放」：政务部门的正常发放通知

**定级规则**（`Judge.js` 与 `Judge.java` 同步）
- "吓唬"阶段分数 ≥70 → 升为 high（原来一律 warn："涉嫌洗钱 + 配合调查 + 公安局"100 分也只是普通提醒）
- "套近乎"阶段分数 ≥45 → 升为 warn（原来一律只记录：多个弱信号叠加也不提醒）
- 陌生号码发来的验证码短信 +30 → +45（正规验证码只来自服务号）
- 云端改为不区分大小写匹配，与手机端一致

## 二、首次设置向导（老人端）

第一次打开银盾自动进入，也可从「设置 → 初始设置向导」重新进入。

| 步骤 | 是否必需 |
|---|---|
| 1 基础权限（短信、来电、通讯录、通知） | 必需 |
| 2 悬浮窗权限 | 必需 |
| 3 紧急联系人 | 必需 |
| 4 通知使用权（微信识别） | 推荐 |
| 5 使用情况访问权限（转账保护） | 推荐 |
| 6 电池优化白名单 | 推荐 |
| 7 子女端配对 | 推荐 |
| 8 发送测试预警 | 推荐 |

每一步实时显示状态，从系统设置页返回后自动刷新；三项必需完成后才能点「完成设置」。

**未设置紧急联系人时不再拨打演示号码**：原来真机上没绑号码会自动拨 13800138000（等于打给陌生人）。
现在只有模拟器保留演示号码；真机上红屏改为提示"尚未设置紧急联系人"，按钮打开拨号盘。

首页「防护项目」也改为逐项检查：微信识别看通知使用权，转账保护看使用情况访问权限，不再一律显示"已开启"。

## 三、老人端与子女端配对

### 3.1 原来的问题

所有设备都用 `elderId=demo`。任何人订阅 `/api/stream?elderId=demo` 都能实时看到这位老人的全部预警（含短信原文）；
`/api/config` 能被任何人调用，把大模型地址改成别人的服务器，API Key 和短信内容会被一起发过去。

### 3.2 现在的做法

```
老人手机第一次运行：生成 elderId（10 位）+ 密钥（32 位，只存本机）
        │  所有请求带 X-Yd-Elder / X-Yd-Key；云端第一次见到时登记密钥哈希
        ▼
向导第 7 步「获取配对码」 → POST /api/pair/start → 6 位数字，10 分钟有效、一次性
        │  老人把 6 位数字念给子女（电话里就能完成，不需要扫码）
        ▼
子女端「输入配对码」 → POST /api/pair/claim → 只读凭证（X-Yd-Child）
        ▼
子女端只能看到这一位老人的预警，不能替老人上报事件
```

| 场景 | 结果（已用命令行逐项验证） |
|---|---|
| 错误密钥 | 401 |
| 同一个配对码用第二次 | 失败 |
| 连续输错 5 次 | 锁定 10 分钟（429） |
| 子女端冒充老人上报预警 | 403 |
| 未认证读取某位老人的数据 | 401 |
| A 老人端在请求里写 B 的编号 | 预警只会记到 A 自己名下 |
| 改大模型配置 / 改规则 / 清数据 | 只允许本机，或设置 `YD_ADMIN` 后带 `X-Yd-Admin` 口令 |

配对数据保存在 `cloud/data/pairs.json`（已加入 `.gitignore`），云端只存密钥和凭证的哈希。

### 3.3 演示模式

模拟器默认使用公开编号 `demo`，不带密钥——投影上的网页子女端（订阅 `demo`）照常能看到演示数据，
学生原有的演示流程不受影响。真机默认关闭演示模式，使用独立编号。

### 3.4 其他

子女端网页把云端推送的标题、正文、AI 摘要先转义再显示，防止骗子通过短信内容在子女浏览器里执行脚本。

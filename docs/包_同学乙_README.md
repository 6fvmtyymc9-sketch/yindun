## 二、四个卡点的结论

### 1. 数据集：在我手上，包里和下载脚本都给了

`fraudr1.tar.gz` 直接解压就有。MagicData 那两份 300MB 太大，不塞包里，跑 `下载数据.sh` 自己下
（我实测过 ModelScope 通，你也说通）。两份都有 md5，对不上就是没下完整。

**你还要知道的三件事**（不然会白跑一天）：

- **不是 14 通，是 9 通。** accent 包是双路单轨——同一通对话，两个人各一个文件
  （`G0001_S0001_0_SPK002` 和 `SPK003` 末秒都是 1234.x）。全拼进去同一句算两遍，分数翻倍。
  按「一通对话」归并后：accent 5 通 + meeting 4 通 = **9 通**。
- **里面没有一句诈骗话术。** 一份是公司开会（聊租房、聊补贴），一份是重口音日常闲聊。
  只能当**负样本**测误报，不能当诈骗正样本，也凑不了「30 通真人录音」那个数。
- **每个 wav 旁边都有同名 `.txt`**，带时间戳和说话人。这就是第 3 条的关键。

### 2. 配额：是「每个 IP 每天」，不是每个老人账号

代码在 `cloud/src/RateLimit.js`，键是 `yindun:rl:report:{IP}:{北京日期}`，存 Redis，北京零点重置。
你一台机器跑就是 60 次/天，跟 `elderId` 传什么无关。

**已经提到 1200/天**（改的 `.env`，没动代码）。1,070 条一天能跑完，成本约 **¥0.75**（单次 ¥0.0007，封顶 ¥0.84/天）。
你「撞配额就停」的逻辑留着，不用改脚本。

### 3. 音频：不用装 Whisper，(a)(b)(c) 一个都不用选

**MagicData 自带转写稿**，直接把文本喂 `/api/report` 就能打分。我写好脚本了：

```bash
cd <仓库>/cloud
node test/eval-magicdata.js "D:/.../magicdata"
```

它会自动：找所有 `.txt` → 按「一通对话」归并（双路只留一路）→ 丢掉 `[ENS]` 噪声行
→ 拼文本 → 过规则引擎 → 输出每通的得分/级别/命中词 + **误报了几通**。退出码非 0 表示有误报，能直接进 CI。

**真要跑 ASR 也有现成通道**：`/api/callaudio`（不是 `/api/report`，也不是 `/api/voice`）。
它走华为云 SIS 一句话识别，`GET /api/callaudio/ping` 现在返回 `"asr":"sis"`，是真通的
（历史实测：42.8 秒录音转写 2.2 秒）。注意 25MB 体积上限在切段之前，30 分钟的 8k wav 约 28MB 会被 413 顶回来，
要先切成 3 分钟以内。

**建议**：全量用自带转写，另外抽 2~3 段切片走 `/api/callaudio` 真跑一次，留个「真录音→转写→判定」
的证据给答辩。两条都要，成本很低。

### 4. 你说的规则漏洞：确认存在，已修

同一句话换一个动词，跨两档：

| 文本 | 改前 | 改后 |
|---|---|---|
| 我是你领导，明天来我办公室，先帮我**转**笔钱给客户 | 45 block | 45 block |
| 我是你领导，明天上午九点来我办公室一趟，现在有个事需要你先帮我**垫**一笔钱 | **15 watch** | **90 block / S4** |
| 「领导让我明天去办公室开会」（正常） | 15 watch | 15 watch |
| 「我们领导说下周组织体检」（正常，通讯录） | — | **0 none** |

原因：词表有「帮我转」30 分、「垫付」30 分，唯独没有「帮我垫」——骗子说的恰恰是 `垫`。
身份词（「我是你领导」「来我办公室」）也一个都没有，所以身份信号是 0。

规则已从 **3.5 / 217 词** 升到 **3.6 / 220 词**，顺手把两个误报源降权了（`今天下午` 15→8、`急需` 20→12）。
双端规则文件已同步，`node test/run.js` 仍是 **诈骗 59 条 0 漏报 / 正常 40 条 0 误报**。

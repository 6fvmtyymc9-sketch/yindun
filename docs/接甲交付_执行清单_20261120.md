## 四、切 `.env`（两个必踩的坑）

```ini
RDS_HOST=<新内网IP>
RDS_PORT=3306
RDS_USER=yindun
RDS_PASSWORD=<yindun密码>
RDS_DATABASE=yindun

REDIS_URL=redis://:<密码>@<新内网IP>:6379/0
```

**坑 1：Redis 密码含 `#`，必须转义成 `%23`**，否则被当成 URL 锚点，鉴权直接失败。

**坑 2：切之前先 `cp .env .env.bak.20261120_<时分>`**。这几天的备份都留着，回滚就一条命令。

## 五、重启并验证（四条硬证据，缺一条不算成功）

```bash
systemctl restart yindun && sleep 3
```

| # | 证据 | 通过标准 |
|---|---|---|
| 1 | `/api/health` | `db: {rds:true, redis:true}`、`statsAll.alerts` = 迁移对数 |
| 2 | `ss -tnp \| grep node` | 出现 ESTAB → 新 RDS IP:3306、新 Redis IP:6379 |
| 3 | `mysql> SHOW PROCESSLIST` | 三个连接全部是 `yindun`，没有 root 残留 |
| 4 | 实跑一条判定 | 诈骗样本 `stage:4`，正常样本 `stage:0` |

第 2 条比 health 硬：health 只能说明配置读到了，`ss` 才能说明真的连上了新实例。
第 4 条不能省——**连着能查不代表判定链能跑**。

# 远程锁定转账（lock）—— 设计与实测

子女端在手机上按一个按钮，老人接下来 30 分钟内打开手机银行就会被拦一次。
这是"子女不在场时唯一能主动做的一件事"，也是赛题里"子女端干预"那一条的实际落点。

---

## 一、这条链路经过哪些环节

```
子女端按「锁定转账」
   ↓ POST /api/command  {action:'lock', minutes:30, from:'女儿'}
云端 server.js
   ├─ 存一份（老人手机不在线也能补发，见 /api/command/poll）
   ├─ SSE 推给在线的老人端
   └─ 返回 msg：在线就说"已送达"，不在线就说"联网后自动执行"——不谎报送达
   ↓
老人端 CommandLink.apply
   ├─ CallRecord.remoteLock(30, '女儿')  → 开一个到期时间戳
   ├─ TipBar 弹一条："女儿开启了转账保护 / 30 分钟内打开手机银行会先拦一下"
   └─ 上报一条 event 给子女端（她也知道自己这一步生效了）
   ↓
老人打开手机银行
   ↓ AppWatcher 扫到前台是银行类 App
   ↓ Guard.onBankForeground
   ├─ 判断：不在通话中 + 风险窗口内 + 屏还没盖着
   ├─ Shield.show → 红屏 + 持续振动 + 屏幕抖动
   ├─ 播放家人语音（云端存的那一句）
   ├─ 推 alert 给子女："妈妈在转账保护期内打开了手机银行"
   └─ 6 秒无人操作 → 自动拨给子女
```

## 二、几个刻意的设计

**只开窗口，不锁手机。**
`remoteLock` 只设一个到期时间戳，不改任何系统设置、不冻结 App。
老人照样能用手机、能看余额、能接电话；只有"打开银行"这一个动作会被拦一次。
理由：真锁死了，老人第一反应是以为手机坏了，会找人"修"——而帮她"修"的很可能就是骗子。

**文案不说没发生的事。**
远程锁开出来的红屏写「先别转账 / 家人暂时锁定了转账」，不写「刚才那通电话有诈」。
因为远程锁和"刚才那通电话"可能毫无关系，老人可能根本没在打电话。
两种情况在 `Guard.onBankForeground` 里靠 `riskFrom` 是否为空区分：
远程锁 `riskNumber = null`、`riskFrom = "女儿"`；录音复盘开的窗口正好相反。

**指令要落库，不能只靠推送。**
推送是尽力而为：老人手机可能在电梯里、后台被国产 ROM 杀了、SSE 断着。
子女按了按钮却什么都没发生，是最糟的体验——她以为"我已经提醒过妈妈了"，然后放心地不再打电话。
所以每条指令都存一份，老人端上线后用 `/api/command/poll?after=<lastId>` 补齐。
`after` 用最后处理过的 id，重复推送和轮询补齐靠 `id + at` 去重。

**时长夹在 5~120 分钟。**
太短起不到作用，太长等于把老人的手机锁死。子女端不填默认 30。

## 三、实测（2026-11-12 晚，模拟器 emulator-5554）

### 3.1 主链路：一次完整通过

下发（`online:1`，说明老人端 SSE 在线）：

```
POST /api/command {"elderId":"demo","action":"lock","minutes":30,"from":"女儿"}
→ {"ok":true,"id":1,"action":"lock","minutes":30,"online":1,"msg":"已送达老人手机"}
```

老人端日志：

```
20:08:14.288  收到子女指令 lock（来自 女儿）
20:08:14.289  子女远程锁定转账 30 分钟（女儿）
20:08:14.311  轻提醒已弹出（warn）：女儿开启了转账保护
20:08:35.979  前台出现银行类 App: 中国工商银行 (com.icbc.mobile)
20:08:35.980  子女远程锁定的窗口内打开银行 → 盖屏
20:08:36.002  屏幕已盖住
20:08:36.006  持续振动已开始（振 400 / 停 1200，循环），最长 120 秒
20:08:36.060  播放家人录音（本地缓存）：family.wav，来自 女儿
20:08:36.088  推给后端 /api/alert 结果 200
20:08:42.824  6 秒无人操作，自动拨给子女
```

结论：**下发 → 收到 → 开窗口 → 扫到银行 → 盖屏 → 振动 → 放语音 → 通知子女 → 自动拨号，整条通。**

### 3.2 同一次实测抓出来的 bug：银盾自己拨的电话被当成陌生来电

接着上面那条自动拨号，20:08:51 出现了这句：

```
20:08:51.091  通话开始 who=stranger num=13800138000 会话=cmwdi8f4ja0s6uf
20:08:51.093  级别升到 block（触发源=call）原因=通话中打开银行
20:08:51.102  请盘古解释：接到陌生号码来电，打开了手机银行，通话中打开银行
```

**这通电话是我们自己打的**。可它被判成了陌生来电，而银行还开在前台，
于是「通话中打开银行」这条最硬的阻断判据成立——又盖了一次屏，
还给正在接这通电话的女儿推了一条「妈妈正在进行高风险操作」。
这句话是假的，而且她看到只会更慌。

**根因**：`CallWatcher` 靠通话记录里的方向（`type==2` 呼出）区分呼入呼出，
但刚接通那一瞬间通话记录还没落盘，查到的是空；家人号码又不在通讯录里
（真机上女儿号码没存进通讯录的情况很常见），于是 `classify` 判成 `stranger`。

**修法**（不引入时间阈值，只补一个既定事实）：

| 文件 | 改动 |
|---|---|
| `Notifier` | 拨号前 `markSelfDial(num)` 记下"我刚拨了谁、什么时候"；`selfDialed(num)` 供查询，有效期 3 分钟，只比数字（忽略空格 / +86） |
| `CallWatcher` | 接通时若 `Notifier.selfDialed(num)`，按呼出处理 → `who=contact` |
| `Guard` | 记 `selfDialed` 标记；`evaluate()` 里这类通话的 `call / tick / bank` 三个触发源直接不判 |

**为什么只摘三个触发源**：短信、装外部 App、开无障碍照判。
正和女儿通着电话、同时收到验证码又开着银行，那是真危险，不能跟着一起吞掉。

## 四、还有两件事没验 / 没修

**① 30 分钟到期后自动失效 —— 未验。**
窗口是内存里的时间戳，要等 30 分钟或改代码。没造这个场景，不写"已验证"。

**② App 被杀后重启、老人正停在银行界面 —— 会漏判（已确认，未修）。**
`AppWatcher.foreground()` 只查"最近 10 秒内谁来到前台"。如果老人本来就停在银行里，
这 10 秒内没有新的 `ACTIVITY_RESUMED` 事件，查询结果为空，这一轮就当没看见。
实测复现：银行一直在最前时重发 `am start`，只打印"前台出现银行类 App"、不盖屏；
按 Home 再点进去（产生了新的前台事件）才盖。
真机上国产 ROM 杀后台很勤，"被杀→重启时老人正在银行"是真实场景，
建议在查不到事件时把窗口放宽到 60 秒兜一次。这条没有数据支撑改动效果，先记下来。

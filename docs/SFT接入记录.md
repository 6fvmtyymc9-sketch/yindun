# AntiFraud-SFT 接入记录

> 2026-11-18 接入并实测。模型跑在学校 AI 实训平台的 GPU 容器里，
> 地址只有校园网可达，**不写进本文件**（向运维要，或看部署机的 `.env`）。

## 一、它在判定链里的位置

三段通话复盘（`/api/callaudio`）现在有**三票**：

| 票 | 看什么 | 强项 | 弱项 |
|---|---|---|---|
| 规则引擎 `Judge` | 关键词 + 行为序列 | 离线、毫秒级、可解释 | 换个说法就漏 |
| 大模型 DeepSeek | 转写后的文字 | 读懂语义、给证据 | 文字丢了语气和背景声 |
| **AntiFraud-SFT** | **原始音频** | 语速、语气、逼问的节奏 | 只看前 30 秒，容易漏后文 |

第三个之所以必要：转写这一步会扔掉骗子最容易露馅的东西 ——
语速突然变快、反复催"你现在就去"、背景里另一个人在教他说什么。
这些都是声音里的，不是文字里的。

## 二、怎么接的

代码早就留好了口子，本次只是把线接上：

| 位置 | 改动 |
|---|---|
| `src/Sft.js` | 已存在（11-10 写），`riskAudio()` / `riskText()` / `ping()` |
| `src/CallAudio.js` | 已存在，第 97 行起并发发起第三票、融合、`/api/callaudio/ping` 报状态 |
| `src/server.js` | `new Sft()` 注入 `registerCallAudio`；`/api/health` 报 `sft` 状态 |
| `.env` | 新增 `SFT_URL` / `SFT_TIMEOUT` / `SFT_WAIT_MS` |

`SFT_URL` 留空 = 不启用：链路照常走规则 + 大模型，不报错、不降级、不拖时间。
这是刻意设计的 —— 校内 GPU 随时可能关容器，线上 ECS 又永远连不上它。

## 三、融合规矩：只抬不降

```
if (sft.p >= 0.85 && stage < 2) { stage = 2; basis += '+sft'; }
```

- **能抬**：p≥0.85 说明模型从声音里听出了转写稿没有的东西，
  这时哪怕规则和大模型都说没事，也该让子女知道一声（抬到 S2「吓唬」= warn）。
- **不能单独降**：模型只看前 30 秒，没听到"把钱转到安全账户"那一段就会给低分。
  让它拿低分否决另外两票，等于给骗子留后门。

阈值 0.85 不是拍的 —— 见下一节的实测：它对正常通话也会给出 0.70 左右的分数。

## 四、实测（2026-11-18，GPU 上单次推理约 150 ms）

样本是 `demo/calls/` 下三段真实录音，走完整 `/api/callaudio` 链路（SIS 转写 + DeepSeek + SFT）：

| 录音 | 实际 | 三票结论 | SFT p | SFT 耗时 | 总耗时 |
|---|---|---|---|---|---|
| 物业通知停水 | 正常 | **S0 / none** · 正常物业通知 | 0.706 | 115 ms | 2.8 s |
| 冒充孙子要钱 | 诈骗 | **S4 / block** · 冒充熟人 | 0.999 | 145 ms | 2.8 s |
| 冒充公安洗钱 | 诈骗 | **S4 / block** · 冒充公检法 | 0.997 | 147 ms | 4.7 s |

两段诈骗都判到最高档，`basis` 为 `ai`（DeepSeek 已经认定，SFT 只是印证）。

**最有价值的一条**：物业停水那段，SFT 给出 `p=0.706 / verdict=fraud`，也就是它**误判了**。
但因为 0.706 < 0.85，没有触发抬分，最终仍是 S0。
如果当初把阈值定成 0.5，或者让它单独有否决权，这条正常通话就会被推成"疑似诈骗"——
老人收到一次这样的误报，产品的信任就没了。

## 五、部署时要注意

1. **线上 ECS 必须留空 `SFT_URL`**。ECS 在校外，连不到校内地址；
   填了不会报错，但每通复盘都要白等满 `SFT_WAIT_MS`（默认 60 秒）才降级。
2. **地址会变**。容器关掉重开后外放端口就换一个，到平台容器页看新的 `port-8000:xxxxx`，
   改 `.env` 后重启服务，再查 `GET /api/callaudio/ping` 的 `sft.enabled` 是否为 `true`。
3. **地址不进仓库、不进公开文档**。`/api/health` 已不再回传 `SFT_URL`（那个接口没有鉴权）。
4. 模型只解码 mp3 / wav / flac / ogg。**m4a / aac / amr 解不开**（返回 400），
   而老人机通话录音常见 amr —— 走云端复盘时如果遇到 400，先转码。

## 六、还没做到的

- **样本太少**：只有 3 条，不能拿来说准确率。要做报告得跑 `cloud/test/holdout.json`
  的文本集（文本模式），并补一批真实录音。
- **只看前 30 秒**：长通话想全覆盖，要么切段多次调用，要么传整段转写（文本模式）。
- **没进实时拦截**：Android 9+ 拿不到通话中的实时录音，它只能做事后复盘。
  这是系统限制，不是实现取舍。

## 二、能做的五件事

### 1. 当短信链路的负样本回归集（最大价值）

这是**本机唯一一份规模够大的中文短信负样本**。此前试过的 `qgyd2021/spam_detect`
（127 MB）内容是微博/新闻碎句，带签名率仅 0.83%，补不了这个缺口；这份不一样，
是真实的运营商短信流。

**实测（规则 3.6/220 词，`who='stranger'`）**：

| who | none | watch | warn | high | block | **误报（warn+）** | 均分 |
|---|---|---|---|---|---|---|---|
| `'stranger'` | 1,031 | 14,697 | **1,031** | 88 | 201 | **1,320 = 7.7%** | 17.7 |
| `'service'` | 15,372 | 1,198 | 347 | 72 | 59 | 478 = 2.8% | 3.3 |
| `'contact'` | 16,716 | 320 | 0 | 0 | 12 | 12 = 0.1% | 0.8 |
| `''` | 15,362 | 1,205 | 349 | 73 | 59 | 481 = 2.8% | 3.3 |

**但 7.7% 只是上界，不是实测误报率。** 复核更正（详见第七节第 2 条）：

CSV 里没有发件号码，`who` 只能假设。真实值落在 **2.8% ~ 7.7%** 之间：

| 口径 | 误报 | 适用前提 |
|---|---|---|
| 全按 `'service'` | 478 = **2.8%** | 下界。运营商/银行/106 号段短信走 `NumberInfo.classify` 都会被判 service |
| 按签名加权 | 1,213 = **7.1%** | 折中：有【签名】的 2,062 条按 service（实为 4.7%），无签名的 14,986 条按 stranger（实为 7.5%） |
| 全按 `'stranger'` | 1,320 = **7.7%** | 上界。最保守口径 |

`NumberInfo.classify`（`app/.../guard/NumberInfo.java`）的规则是
「长度 ≤6 / 95 开头 / 106 开头 → service」，而 label0 里多数正是这三类，
**所以真实误报大概率靠近 2.8% 那一侧，7.7% 是保守上界。**

报告里建议写成「**2.8%~7.7%（陌生号最坏口径）**」，别只报 7.7%——
报上界等于把自己的产品说得比实际差，评委一问"你的服务号白名单呢"就答不上。

**两个数必须一起报，单独报任何一个都可疑：**

> 规则在 11,253 条公开诈骗话术上召回 98.3%（其中直接 block 25.4%），

只有召回数是「宁可错杀」的自证；只有误报数是「什么都不拦」的自证。

## 三、不能做的五件事

### 1. 补不了音频 —— 一个字节声音都没有

老师 `docs/SFT下一步计划.md` 第 3 步要的「诈骗通话 60~100 条，一半从 TeleAntiFraud 里抽」，
**TeleAntiFraud 的音频不在老师发的这 8 个 CSV 里**，还得单独找他要 `audio.zip`。

### 2. 不能当评估集

- **是独白，不是对话**：每条形如「您好，我是XX客服……」，没有对方应答，也没有
  「老人说了什么」这一侧。真实的诈骗通话是双向的，我们的产品监听的是双向。
- **大模型生成腔明显**：书面语、标点规整、逻辑链条过于完整，跟真人口语差很远。
  拿它评 DeepSeek 等于评「像不像模板」，不是「骗不骗」。
- **七类里三类跟独居老人弱相关**：交友 627、游戏 1,499、贷款征信 2,017。
  老人被骗的主流入口是冒充公检法、冒充子女/熟人、保健品、冒充客服退款。

### 3. 不能直接当训练数据 —— label0 有 63.0% 被脱敏成占位符

口径：子串匹配 `x{3,}|X{3,}|NAME|PLACE|DIGIT|PHONE|URL`。
**不能用 `\b` 词边界**——占位符常与中文连写（`DIGIT块NAME机芯`、`NAMEPLACE演唱会`），
中文在 Unicode 下算词字符，加 `\b` 会让匹配率从 63.0% 掉到 44.2%（第一稿复核时踩过这个坑）。

| 文件 | 含占位符 | 比例 | 不含占位符（可用） |
|---|---|---|---|
| **label0** | **10,735 / 17,048** | **63.0%** | 6,313 |
| label5 刷单兼职 | 844 / 2,759 | 30.6% | 1,915 |
| label4 领导熟人 | 266 / 1,533 | 17.4% | 1,267 |
| label1 公检法 | 111 / 1,415 | 7.8% | 1,304 |
| label2 贷款征信 | 96 / 2,017 | 4.8% | 1,921 |
| label3 冒充客服 | 110 / 1,403 | 7.8% | 1,293 |
| label6 交友 | 28 / 627 | 4.5% | 599 |
| label7 游戏 | 70 / 1,499 | 4.7% | 1,429 |
| **合计** | **12,260 / 28,301** | **43.3%** | 16,041 |

具体占位符（label0 内）：`xxx` 6,854 条、`DIGIT` 约 4,205 处、`PLACE` 1,749 处、
`NAME` 1,608 处、`URL` 1,196 处、`PHONE/CELLPHONE` 522 处。

#### 为什么必须过滤 —— 风险是「漏报」，不是「误报」（19:45 用户纠正）

> **第一稿这里写反了。** 原来写「直接喂会教出『看见 XXX 就是诈骗』」，
> 方向搞错了。实测打码分布是**正常短信里远多于诈骗**：

口径 `[xX]{2,}`（任意两个以上连续 x 或大写 X）：

| 类别 | 含打码 | 比例 |
|---|---|---|
| **label0 正常** | **8,093 / 17,048** | **47.5%** |
| label5 刷单兼职 | 922 / 2,759 | 33.4% |
| label4 领导熟人 | 380 / 1,533 | 24.8% |
| label2 贷款征信 | 171 / 2,017 | 8.5% |
| label3 冒充客服 | 118 / 1,403 | 8.4% |
| label1 公检法 | 117 / 1,415 | 8.3% |
| label7 游戏 | 70 / 1,499 | 4.7% |
| label6 交友 | 29 / 627 | 4.6% |

**正常 47.5%，五类诈骗只有 4.6%~8.5%。** 所以模型最可能学到的捷径是
**「有打码 = 正常」**——方向指向**漏报**（把诈骗放过去），不是误报。

漏报在这个产品里是最严重的错：误报的代价是老人多点一次确认，
**漏报的代价是钱没了**。

#### 更细一层：两边的 XXX 根本不是同一个东西

| | 打码的是什么 | 例子 |
|---|---|---|
| label0 正常 | 数字、链接、日期、号码 | `流量已用DIGIT` / `点击URL` / `x月xx日` |
| label4 领导熟人 | **人名** | `我是XXX，现在在美国遇到麻烦` |
| label5 刷单兼职 | **公司名** | `我是XX公司的招聘人员` |

正常短信的 XXX 落在「数字位」，诈骗的 XXX 落在「人称位」。
模型只学「有没有 XXX」学不到东西，但一旦学成「XXX 出现在数字位=正常」，
那个把 XXX 用在人称位的冒充熟人诈骗就会被放过。

#### 结论：过滤的做法不变，但理由要换

- ❌ 旧理由：防误报 —— **错，方向反了**
- ✅ 新理由：占位符是**伪特征**。真实场景里老人的短信不会有 `DIGIT`/`NAME` 这种字符串，
  模型学到的是脱敏流水线的痕迹，不是诈骗特征。留着它只会让模型抓错线索、
  在真实数据上漏掉打码位置不同的那批。
- 过滤口径：只取不含占位符的部分 —— label0 剩 6,313 条，8 类合计剩 16,041 条。
- 如果想保住数量，就先按占位符类型还原成合理实体（数字位→具体数字、链接→假域名、
  人称位→常见姓氏），**还原时必须区分位置**，别把「我是XXX」也填成数字。

### 4. 测不了跟 `who` 有关的判据

表里只有 `content,label` 两列，**没有主叫号码**。所以：

- `who` 只能假设。上面那 7.7% 是假设「陌生号发来」的结果，假设 `service` 就降到 2.8%
- 陌生号 `+15` 底分在 7.7% 里贡献最大 —— 而真实场景中老人手机上的银行/运营商短信
  本该走白名单，这批数据没有号码，测不出白名单该覆盖到哪

### 5. 不能证明「没漏报」

98.3% 是「规则打到了 ≥watch」，不是「拦住了」。拆开看：

- **block 只占 25.4%**（盖红屏的）
- warn 21.9% + high 6.3% 在 App 上只是弹一条提示，**不盖屏**
- 剩下 1.7%（196 条）完全没反应

报告里写「召回 98.3%」时，必须带上 block 25.4% 这个数，否则是把提示当拦截。

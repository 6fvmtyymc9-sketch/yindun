这是新发现的问题，**乙那边不知道**。

`server.js:40`：

```js
const REPORT_PER_DAY = Number(process.env.RATE_REPORT_PER_DAY || 60);
```

你线上 `.env` 里这个值是 **1200**，health 里 `limits.reportPerDay:1200` 就是它。
而 `RateLimit.js` 是按 **IP + 北京时间日切** 计数的，**`dryRun` 照样计次** ——
这是代码里刻意的设计（`server.js:564` 注释：「不然谁加个 dryRun 就能无限刷模型调用」）。

乙明天要跑 **1,070** 条。1,070 / 1,200 = **89%**，只剩 130 次余量。
并发 4 下只要有一批请求失败重试，就会在最后几十条撞上 429，
表现是「前面 900 多条都有分，后面一片失败」——**分母不全，整张表作废**。

操作（`ssh ops@123.249.25.139` 之后）：

```bash
sudo cp /opt/yindun/.env /root/env.bak.$(date +%F_%H%M)
sudo sed -i 's/^RATE_REPORT_PER_DAY=.*/RATE_REPORT_PER_DAY=3000/' /opt/yindun/.env
grep RATE_REPORT_PER_DAY /opt/yindun/.env      # 确认改成 3000 了
sudo systemctl restart yindun
curl -s localhost:8080/api/health | grep -o '"limits":{[^}]*}'
# 要看到 reportPerDay:3000
```

> `.env` 里如果**没有** `RATE_REPORT_PER_DAY` 这一行，就手动加一行 `RATE_REPORT_PER_DAY=3000`。

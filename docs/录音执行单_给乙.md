## 一、先纠正一个误解：不用真骗，也不用 30 个人

老师写"真人录音、不许 TTS"，要的是**真人说话的声音**（真实麦克风、真实 8k 通话音质），
不是"真实发生过的诈骗案件"。照稿子演完全合格。

**30 通 ≠ 30 个人。** 三个人两两组合就够：

```
你 ↔ 队友A      10 通（5 骗 + 5 正常）
你 ↔ 队友B      10 通（5 骗 + 5 正常）
队友A ↔ 队友B   10 通（5 骗 + 5 正常）
```

每通 30–90 秒，来回 3–5 轮就停。**两个人两小时能录 20 通以上。**

## 二、录制步骤（每通都要照做）

1. A 用手机打给 B 的手机（**真拨号，走运营商链路**，不要用微信语音——
   微信走的是编解码完全不同的通道，声学特征和真实来电不一样）。
2. B 开**免提**，旁边放另一台手机开录音（或用系统通话录音）。
3. **每通开头先说一句编号口令**，比如：
   > "第 007 通，冒充公检法，张三演骗子，李四接，红米 K60，11 月 20 日。"
   这句后期必须剪掉，但**没有它，30 个文件对不上 labels，全废**。
4. 按台词演 3–5 轮，正常挂断。
5. 立刻存成 `rec-007.wav`（连续编号，不要用"新录音(3).m4a"这种）。

## 四、录完怎么交

### 目录结构

```
真人录音_2026112x/
  rec-001.wav
  rec-002.wav
  ...
  labels.json
```

### labels.json 格式

```json
[
  {"id": "rec-001", "audio": "rec-001.wav", "label": 1,
   "type": "冒充公检法", "text": "通话转写全文",
   "note": "张三演骗子/李四接/红米K60/iPhone13/2026-11-20/室内安静"},
  {"id": "rec-002", "audio": "rec-002.wav", "label": 0,
   "type": "日常", "text": "...", "note": "..."}
]
```

- `label`：**1 = 诈骗，0 = 正常**
- `text` 必须填。我们训练走的是**文本模式为主**，没有转写就用不了
- `note` 里写清：谁演、谁接、什么设备、哪一天、什么环境。**别嫌麻烦，
  这是答辩时证明"数据是真的"的唯一凭据**

## 五、先交 3 通试打，别一次录完 30 通

录完前 3 通立刻发我，我要确认四件事：

1. **时长**：单通 > 25 秒、< 90 秒。太短信息不够，太长要切片
2. **格式**：wav 最好，m4a/amr 也能收（我们会转）
3. **开场白没混进台词**：编号口令要剪掉，否则模型会学到"第几通"这种垃圾特征
4. **`text` 转写质量**：自己听一遍，错别字别太多

这四条过不了，30 通全白录。**先打样，再量产。**

## 六、几个会毁掉整批录音的坑

| 坑 | 后果 |
|---|---|
| 用微信语音通话 | 编解码和真实来电不同，测出来的东西没意义 |
| 一口气录 30 通不编号 | 文件与标签对不上，全部作废 |
| 背景有电视/风扇/马路 | 模型学到的是噪声特征，不是话术特征 |
| 两个人离麦克风远近差太多 | 一方声音几乎听不见，转写残缺 |
| 演得太假（笑场、念稿腔） | 评估集不反映真实场景，答辩会被问穿 |
| 全部用同一个手机、同一个人 | 声纹单一，泛化性无从谈起——**换设备、换人** |

# 请审查一段 Android + Node.js 的判定链路（只出意见，不要改代码）

## 一、这是什么

「银盾」是一个面向独居老人的反诈 App，双端一云：

- **老人端**：Android 原生（纯 Java 手写 View，无 XML 布局），包名 `com.yindun.guard`
- **子女端**：另一个独立安装的 Android App，通过 SSE 长连接收预警
- **云端**：Node 18 + Express，部署在华为云 ECS

老人端的判定是**三层串联 + 只升不降**：

```
第一层 本地规则（离线，159 条诈骗特征词 + 31 条反例，加权打分，五级）
          ↓ 分数落在"没到 warn"的区域
第二层 端侧小模型 TinyBERT-4L（离线，44MB MindSpore Lite，输出可疑概率）
          ↓ 仍然没到 warn，且满足门限
第三层 云端大模型（DeepSeek，走华为云 MaaS）复审
```

**产品上的硬约束（这是本次审查最关心的东西）：**

1. **宁可多报，不可错放。** 模型说"不是诈骗"时，绝不撤回本地已经报出的警报。
2. **「认识」不能关防护。** 老人在弹卡上点"我认识这个人"，只代表"这一次我认了"，
   绝不能换来一段时间的免打扰窗口——以前有这个窗口，骗子 15 分钟足够把话说完。
3. **误报的代价与漏报不对称。** 误报一次，老人会认为这软件爱冤枉人，然后卸载；
   漏报一次，钱就没了。但目前的设计选的是"宁可多报"，所以误报率必须被压住，
   不能靠"多报没关系"糊过去。

### A1. 金标尺：本地规则打分（App 端）

`Judge.java` 第 267~433 行　—— 问题 1、2：误报和漏报的源头都在这

```java
    // ==========================================================
    //  六、短信判定
    // ==========================================================
    /**
     * 判一条短信。
     *
     * @param body  正文
     * @param who   号码身份 contact / service / stranger
     * @param isCode 是不是验证码短信
     * @return 判定结果
     */
    public Result judgeSms(String body, String who, boolean isCode) {
        Result r = new Result();
        if (!loaded) {
            r.stage = "S0";
            r.level = "none";
            r.why = "规则未加载：" + loadError;
            return r;
        }
        if (body == null) body = "";
        String text = body.toLowerCase();

        // ---------- 1. 逐词打分 ----------
        int score = 0;
        StringBuilder hits = new StringBuilder();
        // 2026-11-04 新增：一边打分一边记下"命中的最高阶段词"。
        // 阶段判定已从"总分落桶"改为"最高命中阶段词"——分数衡量可疑度，
        // 阶段问的是"骗子走到第几步"，两件事必须分开算。
        String topStage = "S0";
        int topRank = 0;
        for (Word w : words) {
            // 已经是"验证码短信"时，「验证码」这个词必然出现，第 4 步会按发送方单独处理，
            // 词库不再重复计分 —— 否则银行正常验证码短信会被 "验证码+S4" 直接推到盖屏。
            if (isCode && "验证码".equals(w.text)) continue;
            if (text.contains(w.text.toLowerCase())) {
                score += w.weight;
                if (hits.length() > 0) hits.append("、");
                hits.append(w.text).append("(+").append(w.weight).append(")");
                if (w.stage != null && w.weight > 0) {
                    int rk = stageRankOf(w.stage);
                    if (rk > topRank) {
                        topRank = rk;
                        topStage = w.stage;
                    }
                }
            }
        }

        // ---------- 2. 反例扣分 ----------
        for (Word w : negatives) {
            if (text.contains(w.text.toLowerCase())) {
                score += w.weight;      // weight 是负数
                if (hits.length() > 0) hits.append("、");
                hits.append(w.text).append("(").append(w.weight).append(")");
            }
        }

        // ---------- 3. 号码身份加权 ----------
        // 同样的内容，陌生人发的比服务号发的危险。
        // 这一步不写在 rules.json 里，因为它不是"词"，是"身份"。
        if ("stranger".equals(who)) {
            score += 15;
            if (hits.length() > 0) hits.append("、");
            hits.append("陌生号码(+15)");
        } else if ("contact".equals(who) && score > 0) {
            // 通讯录里的号码 = 已知熟人，给 −20 基础信任分。
            // 「妈，把身份证号发给我，我帮你订票」这类家常请求和套信息句式高度相似，
            // 光靠词库分不开，只能用身份分兜底。只在本来就有可疑分时才打折，避免负数脏数据。
            score -= 20;
            if (hits.length() > 0) hits.append("、");
            hits.append("通讯录号码(-20)");
        }
        // ---------- 3.5 链接特征 ----------
        // 【为什么单独立一条，不写进词库】
        //   钓鱼短信的核心动作是"让你点一个链接"。域名每天换、短链天天新，
        //   词库永远穷举不完。所以这里认的是"形式"而不是"内容"：
        //   只要正文里出现一个可点的网址，不管它长得像不像官方，都算钓鱼入口。
        //
        // 【为什么不联网核验"这域名是不是真的工商银行"】
        //   短信到达的那一秒来不及查，而且离线也必须能判。
        //   我们只回答一个问题：这条短信在催你点链接吗？是，就加分。
        //
        // 【2026-11-09 加】实测：'您的ETC已停用，请点击 t.cn/Etc9 认证'
        //   词库只给 55 分，因为骗子故意避开'点击链接'四个字。补上形式特征才抓得住。
        Matcher um = URL_PATTERN.matcher(body);
        if (um.find()) {
            score += 20;
            if (hits.length() > 0) hits.append("、");
            hits.append("含链接(+20)");
            if (stageRankOf("S2") > topRank) {
                topRank = 2;
                topStage = "S2";
            }
        }

        // 验证码短信要按"谁发的"区别对待：
        //   服务号（95588、银行、平台）发验证码 = 正常业务，不加分
        //   陌生号码发验证码 = 极不正常，重罚
        //
        // 为什么这么判：验证码的正常来源只有服务号。陌生人给你发"验证码"，
        // 只可能是钓鱼（让你点链接、或者冒充客服要你念出来）。
        if (isCode) {
            if ("service".equals(who)) {
                if (hits.length() > 0) hits.append("、");
                hits.append("服务号验证码(+0)");
            } else {
                // v3.4：+30 → +45，与云端 Judge.js 一致
                score += 45;
                if (hits.length() > 0) hits.append("、");
                hits.append("非服务号发验证码(+45)");
                // 与云端 Judge.js 对齐：这个信号在 JS 里是 tag:'S4'，这边也要参与定阶段
                if (stageRankOf("S4") > topRank) {
                    topRank = 4;
                    topStage = "S4";
                }
            }
        }

        // ---------- 4.5 官方宣传短信免打扰 ----------
        // 与云端 Judge.js 的 noticeOf() 逐条对齐：来源 service + 命中≥2个宣传标记 + 无任何 veto 词。
        String noticeWhy = noticeOf(text, who);
        if (noticeWhy != null) {
            r.score = score;
            r.stage = "S0";
            r.level = "none";
            r.exempt = "publicity";
            r.why = noticeWhy + "，判为官方宣传短信，不打扰";
            r.hint = hintOf("S0");
            return r;
        }

        // 【2026-11-04】原来这里把负分夹到 0。已去掉：云端 Judge.js 从不夹，
        // 两端分数不一致会让对拍工具（tools/modelcheck）永远对不上。
        // 负分只表示"比基准更不像诈骗"，阶段/等级都已经是 S0/none，不影响任何行为。

        // ---------- 4. 定阶段、定级别 ----------
        r.score = score;
        r.stage = stageOf(score, topStage, topRank);
        r.level = levelOf(score, r.stage);
        // 通讯录里的号码最多"提醒"，不盖屏 —— 除非已经明确走到要钱(S4)。
        if ("contact".equals(who) && !"S4".equals(r.stage) && levelRank(r.level) > levelRank("watch")) {
            r.level = "watch";
        }
        r.why = hits.length() == 0 ? "没命中任何可疑词" : hits.toString();
        r.hint = hintOf(r.stage);

        // ---------- 5. 端侧小模型并联 ----------
        // 放在官方宣传豁免之后：运营商的反诈宣传短信本身就是满屏高危词，
        // 先让 noticeOf 把它摘出去，模型才不会每周来打扰一次。
        return withTinyBert(r, body, who, isCode);
    }

    // ==========================================================
    //  六之二、端侧小模型并联（docs/模型选型.md 4.1「部署」）
    // ==========================================================
    /**
     * 规则和小模型并联：<b>任一判为可疑即提醒</b>。
     *
     * <p>为什么要并联：规则在留出集上漏报 60%，骗子换个说法关键词就一个都不中；
     * 小模型看整句语义，能补这一块。但小模型也会误报（留出集 6.7%），
     * 所以它<b>只能往上抬，不能往下压</b> —— 模型说"不像"，不能推翻规则已经抓到的证据。

     *
     * @param isCode 服务号发来的验证码是正常业务，不让模型参与，否则银行每天几条全被误伤
     */
```


### A2. 端侧小模型并联（App 端）

`Judge.java` 第 434~461 行　—— 问题 3：模型是加分还是覆盖？会不会把正常短信推过线

```java
    private Result withTinyBert(Result r, String body, String who, boolean isCode) {
        if (body == null || body.length() == 0) return r;
        if (isCode && "service".equals(who)) return r;

        float p = TinyBert.score(body);
        r.modelScore = p;
        if (p < 0) return r;                       // 模型缺席：保持规则结论
        if (p < TinyBert.threshold()) return r;    // 模型也认为不可疑，什么都不改

        // 规则已经判到 warn 及以上，说明证据更硬，保留原判（不重复抬高、也不降级）
        if (levelRank(r.level) >= levelRank("warn")) return r;

        r.level = "warn";
        if (r.score < lvWarn) r.score = lvWarn;
        // 模型只给"这句话不对劲"的可疑度，说不出"骗子走到第几步"。
        // 规则停在 S0/S1 时保守记为 S1（可疑接触），不往 S2 以上编。
        if ("S0".equals(r.stage) || "S1".equals(r.stage)) {
            r.stage = "S1";
            r.hint = hintOf(r.stage);
        }
        r.byModel = true;

        String head = (r.why == null || r.why.length() == 0 || "没命中任何可疑词".equals(r.why))
                ? "规则没命中关键词" : r.why;
        // 用向下取整而不是四舍五入：0.998 显示成 99% 而不是 100%，不把概率说满
        r.why = head + "；端侧小模型判为可疑（" + (int) (p * 100) + "%）";
        return r;
    }
```

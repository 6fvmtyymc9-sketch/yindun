## 二、参赛作品简介

### 赛题

赛题 1：基于华为云产品打造 AI 创新应用（中国区）

### 作品名称

**银盾 · 反诈守护**

### 应用领域

生活应用 —— 面向独居老人的反诈防护（老人端实时拦截 + 子女端远程知晓）

### 应用技术

本项目使用 **华为云码道 CodeArts 代码智能体** 完成老人端演示页的增量改造：先由人工把需求拆成 5 组可执行的补丁清单（附三条硬约束：不得重写整个文件、不得改动既有配色与尺寸、不得引入外部 CDN），再交由智能体按清单逐组修改，产出 563 行 / 27.7KB 的单文件页面，无外链、断网可用；此后经 11 月多轮迭代（新增通话复盘、演练对练、事件时间轴），当前为 2,587 行 / 132KB，仍保持单文件、零外链。问题修复环节中，页面「熟人询问」弹层被 15 分钟免打扰窗口误挡的缺陷（现象：点第 6 步无反应；根因：`go('aq')` 走 `showAcquaint()` 被 `knownMark` 抑制逻辑拦截）也由智能体参与定位并修复。

云端服务部署于 **华为云 ECS**（Ubuntu 22.04，Node 18）：MySQL 8 与 Redis 6 以容器外自建方式运行于同一台 ECS，并提供 `/api/health` 健康检查（自报各依赖连接状态）。方案支持华为云 **RDS for MySQL** 与 **DCS for Redis**：开发期已在同一 VPC 内完成开通、数据迁移与回迁验证——迁移前后七表逐行一致、业务代码零改动，仅切 `RDS_HOST` / `REDIS_URL` 两个环境变量；为控制按需计费成本，演示环境当前使用 ECS 同机 MySQL / Redis，迁移脚本与连接参数保留在仓库中。

大模型能力通过 **华为云 MaaS（ModelArts Studio）** 调用 DeepSeek-V4.1-Flash（OpenAI 兼容接口），用于短信灰区复审、通话复盘、演练对练三处。

### 作品介绍

#### 1、方案的背景和价值（500 字以内）

电信网络诈骗的受害主体正在老化。独居老人接到的往往不是"一眼假"的短信，而是冒充公检法、冒充客服退款、冒充子女求助的完整话术：先制造恐慌或亲情压力，再用"安全账户""验证码""点链接核验身份"把人一步步推向转账。这类骗局的共同点不是话术拙劣，而是**它要求受害者在情绪被牵动的状态下自己做判断**——而人在恐慌中恰恰最不擅长判断。

现有防护产品的两个断点：一是把判断责任交回给老人（弹一个"这是诈骗吗？"的确认框）；二是只在事后提醒，钱已经出去了。

银盾的做法是**不要求老人判断，只截住资金动作**：

- **老人端**：监听短信、微信通知、通话状态与银行 App 启动。短信与微信内容先在本地用 220 条诈骗特征词 + 33 条反例打分，落进灰区再交给云端大模型判性质；一旦判定命中，直接在屏幕上盖一层红色拦截页，并把「这通电话/这条消息像什么骗局」用大白话写清楚。
- **子女端**：同一时刻，子女手机上收到一条真实推送（不是演示动画），带原文、等级与时间，可以立刻打电话回去。

价值在于**把防线从"教育老人别上当"挪到"系统替她挡住"**：老人不需要理解什么叫"安全账户"，她只需要看到"这是诈骗，别转账"。

（约 400 字）

#### 2、华为云产品的使用价值（1000 字以内）

**需求理解环节。** 项目的需求不是一句"做个反诈 App"，而是三端联动、四级风险、可现场演示的一整套行为。我们把它拆成 8 个主任务 / 16 个子任务写进 `tasks.md`，再把前端那一块单独拆成 5 组增量补丁（含验收标准与"做不了清单"必填项），交给码道 CodeArts。这一步的价值不在"让 AI 写代码"，而在**把模糊需求转成智能体能执行的规格**——补丁清单本身就成了一份可核对的契约。

**代码生成环节。** 码道按清单产出单文件演示页（563 行 / 27.7KB，内联 CSS/JS、零外链、断网可用），保留既有配色与 375×667 手机模拟框；新增熟人询问弹层、反例按钮、按住 3 秒放行等交互。之所以坚持"增量改造而非重写"，是因为重写会丢掉已经验收过的状态机。

**问题修复环节。** 上线自测时发现：走到第 1 步后点第 6 个按钮没有反应。码道定位到根因——手动弹层走的是 `showAcquaint()`，而该函数受 15 分钟免打扰窗口（`knownMark`）抑制，因此被静默拦截；修复方式是手动入口直接强制弹层、自动入口仍受窗口限制，两者语义分开。这类"功能其实没坏、只是被另一条规则挡住"的缺陷，靠人肉读代码很费时间，交给智能体定位是真实提效。

**部署上线环节。** 云端为 Node 18 + Express 服务，部署在华为云 ECS，systemd 托管、开机自启，对外提供 `/api/health`（自报规则版本、RDS/Redis/模型三项连接状态）与 SSE 长连接推送。当前 MySQL 8 与 Redis 6 与业务同机部署；**RDS for MySQL / DCS for Redis 已完成开通与迁移验证后回迁**，连接串切换只涉及 `RDS_HOST` / `REDIS_URL` 两个环境变量，业务代码零改动。

**AI 能力环节。** 通过华为云 MaaS 调用 DeepSeek-V4.1-Flash，用在三处：短信灰区复审（本地 30–45 分的模糊区间）、通话动作序列复盘、演练对练。选型为**非思考型模型**，实测 1,079 条真实请求：中位 42 ms、P90 1,174 ms、P99 1,705 ms，单条成本约 ¥0.00091，适合"拦截页必须秒出"的场景。

**一句总结：** 智能体承担的是"把规格变成代码"和"定位被规则挡住的缺陷"，人承担的是"决定拦什么、放什么"——后者是产品的判断，不能外包。

（约 780 字）

### 技术方案介绍

#### 1、整体技术方案介绍

双端一云：老人端与子女端是两个独立安装的原生 App（`com.yindun.guard` / `com.yindun.child`），
中间靠华为云 ECS 上的一个 Node 服务通信；高风险判定在手机本地完成，所以断网也拦得住，
云端只负责三件事——把告警实时推给子女、做灰区的模型复审、存历史记录。

```
                    ┌──────────────── 华为云 ────────────────┐
  老人端 App         │  ECS · Node 18 + Express              │   子女端 App
  (com.yindun.guard) │  ├─ /api/event     事件上报            │  (com.yindun.child)
        │            │  ├─ /api/stream    SSE 实时推送        │        ▲
        │  HTTPS     │  ├─ /api/rules     规则热更新          │        │ SSE
        └───────────▶│  ├─ /api/report    截图复审            │────────┘
                     │  └─ /api/health    依赖自检            │
                     │  MySQL 8（告警/事件/演练记录）         │
                     │  Redis（限流计数、在线状态）           │
                     │  MaaS · DeepSeek-V4.1-Flash           │
                     └───────────────────────────────────────┘
```

#### 2、关键技术模块介绍

**模块 1 本地判定引擎：220 条特征词的加权打分（不联网也能跑）**

- 规则表 **220 条**诈骗特征词 + **33 条**反例 + **11 条**组合规则 + **3 条**永不告警白名单（银行服务号等），双端同源（`app/assets/rules.json` 与 `cloud/config/rules.json`），可热更新。
- **四级风险**（`watch` 关注 / `warn` 警告 / `high` 高危 / `block` 阻断，阈值 25 / 45 / 70 / 90）+ **五档行为阶段**（S0 接触 → S1 建立信任 → S2 引导动作 → S3 索要资金 → S4 实施转账）。分数衡量"有多可疑"，阶段回答"骗子走到第几步"，两者分开算。不同级别对应不同强度的界面反馈（浮条 / 卡片 / 全屏盖屏）。
- 链接形式识别在**引擎层**而非词库层：识别 `http(s)://`、`www.`、`t.cn/xxx` 裸短链，命中即 +20 分并升到"提示"级——这一条覆盖了"话术干净但带链接"的变种。

关键代码片段（`Judge.java`）。这段是整个引擎里最值钱的一条，因为它认的是**形式**而不是**内容**：

```java
// 钓鱼短信的核心动作是"让你点一个链接"。域名每天换、短链天天新，词库永远穷举不完，
// 所以这里认"有没有一个能点的网址"，不管它长得像不像官方：
//   ① 带协议头的完整网址（http:// https:// www.）
//   ② 不带协议头的短链（t.cn/xxx、bit.ly/xxx）——骗子最常用
// 实测：'您的ETC已停用，请点击 t.cn/Etc9 认证' —— 骗子避开"点击链接"四个字，
//      词库只给 55 分；补上形式特征后 63 分（警告级仍不盖屏）；
//      再补 3.7「停用类通知 + 链接」判据后 78 分，才到阻断级。
private static final Pattern URL_PATTERN = Pattern.compile(
        "(?:https?://|www\\.)[a-z0-9\\-._/?=&%#:@+~]+"
                + "|\\b(?:t\\.cn|bit\\.ly|dwz\\.cn|url\\.cn|s\\.cn|w\\.cn|"
                + "rb\\.gy|suo\\.im|6url\\.cn|tinyurl\\.com|j\\.mp)/[a-z0-9\\-._/?=&%#]+",
        Pattern.CASE_INSENSITIVE);

Matcher um = URL_PATTERN.matcher(body);
if (um.find()) {
    score += 20;                          // 命中即 +20
    if (hits.length() > 0) hits.append("、");
    hits.append("含链接(+20)");
    if (stageRankOf("S2") > topRank) {    // 同时把"骗子走到第几步"推进到 S2
        topRank = 2;
        topStage = "S2";
    }
}
```

另外两个设计点，都来自踩过的坑：

- **分数与阶段分开算**。分数衡量"可疑度"，阶段回答"骗子走到第几步"，两件事不能混在一个桶里（早期版本用总分反推阶段，导致银行正常验证码短信被"验证码 + S4"直接推到盖屏）。
- **陌生号码 +15 / 通讯录号码 −20**。同样一句话，陌生人发的和熟人发的危险程度不同。「妈，把身份证号发给我，我帮你订票」和套信息句式高度相似，光靠词库分不开，只能用身份分兜底。

**模块 2 三路事件监听：安卓给的真实边界**

- 短信：`SMS_RECEIVED` 广播接收，读原文与发信方。
- 微信：`NotificationListenerService` 读取 `com.tencent.mm` 的通知标题与正文（安卓不允许读聊天记录，只能读通知）。
- 通话：监听通话状态与时长，**读不到通话内容**——这是安卓 9 起的硬限制，因此电话侧的风险输入只能是"动作序列"（陌生号、通话时长、通话中收验证码、随后打开银行 App）。
- 去重：指纹包含 `postTime`，避免重复投递同一条通知造成误报（漏掉这个字段时，重跑演示脚本会被全部判为重复而静默丢弃）。

**模块 3 双端实时联动：SSE 长连接与断线回填**

- 云端用 SSE（`/api/stream?elderId=`）长连接推送，读超时 45 秒、断线 3 秒重连，重连后用 `/api/alerts?limit=20` 回填断线期间的告警。
- 子女端为原生 App（非 WebView），前台服务保活，高优先级通知 + 振动。
- 老人端首页持久化"最近一次提醒"，进程被杀后重进仍能看到记录。

**模块 4 云端 AI 复审**

- 短信灰区（本地 30–45 分且非服务号）送 MaaS 复审；**规则只升不降**——模型说可疑就升级，说正常绝不撤回已报出的警报。
- 演练对练：基于 12 类高发骗局生成多轮对话，训练老人识别话术。
- 成本护栏：`/api/report` 与 `/api/drill/turn` 按 IP 每日限额（线上配置 1,200 / 300 次，代码默认 60 / 300，`.env` 可调），超额返回 200 + `RATE_LIMITED` 而不是 429，保证客户端能弹出真实原因。

## 05 项是怎么补到的（不是改阈值造假）

触发条件只有一个：**陌生号通话满 5 分钟**。代码里对模拟器有 20 倍速
（`Guard.java` 的 `IS_EMULATOR`：真实 1 秒判作 20 秒喂给判级，显示给人的时长仍是真实值），
所以模拟器上真拨约 **15 秒**就走到阈值，不需要陪聊 5 分钟。做法：

```bash
adb emu gsm call 19900001234          # 陌生号码来电
adb shell input keyevent KEYCODE_HEADSETHOOK   # 接听
adb logcat | grep "第二次询问"          # 等这行日志
adb exec-out screencap -p > 05.png
```

本次实测日志（2026-11-20 23:46）：

```
I YinDun : 通话开始 who=stranger num=19900001234
I YinDun : 通话满 5 分钟 → 第二次询问（持续振动，点按钮才停）
I YinDun : 级别升到 watch（触发源=tick）原因=陌生号码通话时间偏长
I YinDun : 通话复问卡已弹出：19900001234（持续振动，点按钮才停）
I YinDun : 持续振动已开始（振 400 / 停 1200，循环），不自动停
```

⚠️ **这张图的边界，用的时候要如实说**：

- 背景是**系统拨号盘**，不是通话界面——模拟器（无窗口模式）不渲染 InCallUI，
  卡片本身是银盾的悬浮窗，所以背景上是哪个页面都正常。真机上它盖在通话页之上。
- 卡片上的「5 分钟」是**判级时长**（20 倍速换算），状态栏没有通话计时可比对，看不出来，但这不是造假：
  走的是代码里本就存在的模拟器倍速，**没有临时改阈值**。
- 真机版仍可补（拨陌生号等真 5 分钟，用另一台手机拍），补到就替换本图，图注改为真机实拍。

**旁证仍在**：`09-child-call-list-5min-recheck.png` 里 21:46 那条
「妈妈确认通话对方为熟人（通话已超过 5 分钟）…妈妈选择了"认识"」，
是 11-17 那次回归里复问卡触发并推到子女端的留痕，和本图互相印证。

## 微信这条链的证据边界

微信是老人被骗的主战场，但也是**证据最难拍**的一块。现状如下，别搞混：

| 环节 | 有证据吗 | 在哪 |
|---|---|---|
| 真微信的消息能被读到 | ✅ 有 | `realdevice/rd01`（真机，真微信，warn 级「急事借300」→ 底部浮条，正文仍可见） |
| 老人端浮条长什么样 | ✅ 有 | 同上（真机）；第 11 项（模拟器） |
| 判到 block 会撤掉通知栏那条 | ✅ **动作已实证** | 见下方日志与命令输出；**但没有画面**，原因见下 |
| 子女端收到「已拦截」 | ✅ 有 | 第 06 项（模拟器） |

### 撤通知这件事，为什么没有图

2026-11-20 23:54 在模拟器上跑通并发四步话术，第 4 条（含 `t.cn/Yb9K2`）判 **72 分 / block**，
随后通知栏那条被撤。证据是命令输出，不是截图：

```
I YinDun : 微信消息 from=张主任 分数=72 阶段=S3 级别=block
           原因=逾期(+15)、注销(+12)、认证(-5)、陌生号码(+15)、含链接(+20)、停用通知带链接(+15)
I YinDun : 阻断级：已从通知栏清掉这条微信消息
```

```
$ adb shell dumpsys notification | grep -A2 "pkg=com.tencent.mm"
  id=2004  android.text=String (这个事您先不要告诉家里人…)   ← 第 3 条，在
  id=2003  android.text=String (系统显示您的医保卡被他人冒用…) ← 第 2 条，在
  id=2002  android.text=String (小李啊，我是社保局这边…)        ← 第 1 条，在
  （id=2005 第 4 条「您现在点这个链接完成认证 t.cn/Yb9K2」不在其中）
```

拍不出画面的原因：假微信壳的通知渠道是 `IMPORTANCE_LOW`，在 Android 11 通知栏里被系统
归入静默/折叠区，"撤掉前"和"撤掉后"在截图上看不出差别。真机上的真微信是正常渠道，
**能拍**——所以这一张留给真机补：

> 队友（或另一个微信号）给真机发一条「手机丢了换号了，急用钱先转我2000」这类索款消息
> → 银盾判 block、底部浮条弹出 → 下拉通知栏，微信那条不在。拍浮条和通知栏两张。
> 不需要改代码，也不需要连电脑。

### 第 11 项为什么不能当材料用图

1. **气泡方向不对**：真微信里绿色是"自己发的"（靠右），对方发来是白色（靠左）。
   演示壳把对方消息画成绿色靠左。懂微信的人一眼能看出来。
2. **底部绿条是演示控制条**，写着"脚本已播完（共 4 条）"。这是 2026-11-09 有意做的取舍：
   不把它伪装成微信输入框，评委一眼能看出这是演示控件，而不是以为我们在偷偷放按钮。
3. 因此第 11 项只用来证明"链路真的跑通、判定真的分四档"，对外用图仍用 rd01 + 06。

### 顺带查出的一个误报（待改，未动代码）

第 1 条单独出现时被判 **50 分 / warn**：

```
「小李啊，我是社保局这边负责您片区的，工号 0371」
→ 分数=50 原因=工号(+20)、社保局(+15)、陌生号码(+15)
```

真客服/社区网格员打电话也是这么开场。一句自我介绍就弹浮条，属于误报。
根因是「工号」+20 与「社保局」+15 叠得太高，缺"有没有索要动作"这道闸门——
和 3.6 步（冒充子女索款）用的是同一个思路，可以照那个补一条"机构自称 + 无索要动作 → 压分"。

# ECS 安全加固记录（2026-11-18）

## 一、为什么要做

`/var/log/auth.log` 里累计 **42,984 次失败登录**（当天白天是 42,686，几小时新增 298 次），
来源集中在 `109.160.32.0/24`（单个 IP 1,286 次）和 `77.239.124.143`。

加固前状态：

| 项 | 值 | 风险 |
|---|---|---|
| `PermitRootLogin` | `yes` | root 可直接用密码登录 |
| `PasswordAuthentication` | `yes` | 允许密码认证，暴力破解在理论上可行 |
| `fail2ban` | 未安装 | 扫描器可以无限次尝试 |
| `ufw` | 未启用 | 见第四节的不启用理由 |

## 二、做了什么（三项）

### 1. 关闭 root 密码登录，保留密钥

```bash
sed -i 's/^PermitRootLogin yes/PermitRootLogin prohibit-password/' /etc/ssh/sshd_config
sed -i 's/^PasswordAuthentication yes/PasswordAuthentication no/'          /etc/ssh/sshd_config
```

**为什么不直接 `PermitRootLogin no`**：本机没有 `yindun` 系统账号（`ssh yindun` 只是本地
`~/.ssh/config` 里给 `root@123.249.25.139` 起的别名），`ops` 账号的私钥在同学甲手上。
关死 root 会把队长自己锁在外面，所以采用「禁密码、留密钥」。

实测生效值：

```
permitrootlogin without-password    # 与 prohibit-password 同义，sshd -T 的写法
passwordauthentication no
```

### 2. 安装 fail2ban 并封禁扫描源

- 版本 `0.11.2`，配置见 `deploy/fail2ban/jail.local`
- `bantime 1h` / `findtime 10m` / `maxretry 5`
- 白名单：`127.0.0.1/8`、`117.139.198.0/24`、`171.218.0.0/16`、`111.9.0.0/16`
  （本机 + 队长与同学常用出门 IP，防客户端异常重试把自己封了）

### 3. 入侵体检

| 检查项 | 结果 |
|---|---|
| 成功登录记录（`Accepted`） | 全部来自 `117.139.198.x` / `171.218.x` / `111.9.49.8`，无境外 IP |
| 计划任务 | 仅系统默认 `e2scrub_all` 与 apt/logrotate 等标准 timer |
| `authorized_keys` | root 1 把（队长）、ops 1 把（同学甲）、tunnel 1 把（带 `restrict`） |
| `/tmp` `/dev/shm` `/var/tmp` 可执行文件 | 无 |
| 外联连接 | 仅华为云 `uniagentd`、node:8080 业务连接、sshd 会话 |

**结论：没有一次外部登录成功过，未被攻破。**

## 三、验证方法（可复现）

```bash
# 1. 配置生效
sshd -T | grep -E '^(permitrootlogin|passwordauthentication)'

# 2. 密码认证被拒（应输出 Permission denied (publickey)）
ssh -o PreferredAuthentications=password -o PubkeyAuthentication=no \
    -o BatchMode=yes root@127.0.0.1 true

# 3. fail2ban 真能封（用保留测试网段，封完解封）
fail2ban-client set sshd banip 203.0.113.66
iptables -S f2b-sshd        # 应出现 REJECT 规则
fail2ban-client set sshd unbanip 203.0.113.66
```

第 3 步是本轮最关键的验证：`f2b-sshd` 链在**第一次封禁之前是不存在的**，
如果只看 `iptables -L` 会误判成"没生效"。

## 四、刻意没有做的三件事及原因

| 没做 | 原因 |
|---|---|
| **不开 ufw** | 对外只有 22 和 8080，3306/6379/8099 都只监听 `127.0.0.1`，云安全组已有一层。再开 ufw 只会在排障时添乱，同学甲迁移那天还可能挡住连 RDS 的路 |
| **不删 root 密码** | 华为云控制台 VNC 登录仍需要它，这是密钥失效时的唯一救援通道 |
| **不改 `MaxAuthTries`** | 密码认证已关，降低尝试次数对密钥爆破没有实际意义 |

## 五、回滚方法

```bash
cp -a /root/sshd_config.bak.20261118_2223 /etc/ssh/sshd_config
systemctl reload ssh
systemctl disable --now fail2ban        # 如需连 fail2ban 一起撤
```

执行时曾挂过一个 200 秒自动回滚保险（`systemd-run --unit=sshd-rollback`），
确认新连接可用后已取消。若以后再改 SSH 配置，建议沿用这个做法：
**先起定时回滚，再 reload，用 `-o ControlPath=none` 强制新连接验证，通过后再取消保险。**

## 六、对交付的意义

赛题要求里没有单列"安全"，但这份记录可以在答辩时回答两个必问的问题：

1. **"你们的数据和服务器安全吗？"** —— 有具体数字（42,984 次攻击、0 次成功）、有措施、有验证命令。
2. **"密钥怎么管理？"** —— 三个账号职责分离：root 仅队长、ops 给同学甲且 `NOPASSWD` sudo、
   tunnel 仅限 `permitlisten="127.0.0.1:8099"` 无法开 shell。这一点在答辩里比"我们都用 root"强得多。

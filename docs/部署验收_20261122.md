### 4.5 部署有没有漏文件

把线上文件 `scp` 回本地，与仓库逐字比对（忽略换行符差异）：

```
diff --strip-trailing-cr cloud/public/index.html  index.online.html   → 无差异
diff --strip-trailing-cr cloud/src/Guard.js       Guard.online.js    → 无差异
```

同时确认 `/opt/yindun/.env` 未被覆盖（1043 字节，权限 600，`RDS_HOST`、`REDIS_URL` 均在）。

## 六、诚实边界

以下几点必须说清楚，答辩时不回避：

1. **RDS 开通那一刻没有截到图。** 用户是以文字形式把实例信息发过来的，事后补的是 `hcloud` 只读清单（图 12）。清单能证明实例存在、规格、地址、创建时间，但证明不了「是码道开的」——那一环靠图 08 的同类证据（DCS）和码道的 Token 消耗记录。
2. **`rds:true` / `redis:true` 是连接可达 + 一条真实写入验证的结果**，不是压力测试结论。没有做并发、故障切换、慢查询这类验证。
3. **演示环境数据是空的。** 清理测试数据后 `events/alerts/reports` 全为 0，页面首屏两个手机框为空。这是真实状态，没有为了好看预先灌数据。
4. **RDS/DCS 是按需计费，长期保留成本约 21 元/天。** 演示期结束后会主动释放，释放前先导出数据与截图，不依赖它们长期存在。
5. **部署由码道智能体执行，但校验由人工完成。** 码道自报「三项验证通过」，本记录第三节的四项核对（逐字比对、`.env` 完好、公网 health、短信实测）是独立复验，不采信自报结论。

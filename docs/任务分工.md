## 一、原则

**判定逻辑自己写，流程性工作外包。**

- 判定链不外包：答辩时"这条为什么判成诈骗"必须能当场讲透，改坏了要能改回来。
- 云服务开通、部署脚本、录屏取证、数据整理可以外包：照着文档做，有明确验收标准，做错了代价可控。
- 每块工作**只动自己那几个文件**，避免 git 冲突。

**三人版的关键设计**：同学的活尽量互相不卡。同学甲有一部分不依赖 ECS 权限（写部署脚本），
所以即使 ECS 一时进不去，他也有事可做；同学乙的活零依赖，今天就能开工。

## 五、包 B：部署脚本（同学甲，先做，不依赖权限）

**为什么先做这块**：它不碰服务器、不碰代码判定逻辑，纯粹是"把部署过程写成脚本"。
ECS 权限还没下来的这几天，正好用来做这个，不浪费时间。

**做什么**
1. 参考赛事示例（`auto-deploy-case-study.md`），让 CodeArts 生成部署脚本，提交到仓库 `deploy/` 目录
2. 脚本要覆盖：装 Node 18 → 拉代码 → `npm install --production` → 写 systemd 服务
   （参照 `cloud/README.md` 251~290 行）→ 启动 → 健康检查
3. 幂等：重复跑不报错，已装好的不重装
4. 补上文档提到但仓库里缺的 `step1.sh`
5. 脚本要能接受"全新机器"这个前提：不假设已有 Node、已有目录、已有用户

**交付**
- `deploy/install.sh`：一条命令从裸机到服务起来
- `deploy/README.md`：写清前置条件（系统版本、需要开放哪些端口、`.env` 必填项）
- 脚本里**不能出现任何密码、Key、IP 里的私密部分**

**铁律**
- `.env` 由人工在服务器上填，脚本只检查"有没有填"，不代填、不生成
- 必须等队长说"代码冻结"再把脚本固化进录像

**做什么**
1. 用 CodeArts 智能体 + Skills 开一台按需 ECS（2核4G、40G 系统盘、1M 按流量）

5. 在全新机器上跑 `deploy/install.sh`，**全程录屏**
6. 验证：`/api/health` 返回 `ok:true`、`storage.rds/redis` 都为 true、子女端网页能打开
7. 数据：`mysqldump` 从旧机器导一份到新库，否则演示时页面是空的
8. 录完、演示完**释放实例**（不是停止——按需实例停止仍收存储费）

**交付**

  必须靠队长包 E 的隧道才能通。**录屏时如实说明，不要伪造"已接入"**

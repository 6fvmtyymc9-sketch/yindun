# 请审查一个 Android + Node.js 项目的构建配置与部署脚本（只出意见，不要改代码）

## 一、这是什么

「银盾」是一个面向独居老人的反诈 App。一次交付里有两类产物：

**1. 安卓端**（`com.yindun.guard`，纯 Java 手写 View，无 XML 布局）
- 采用**双构建并存**：
  - **A 路 Gradle**：`app/build.gradle` + `app/settings.gradle`，AGP 8.7.3 / Gradle 8.11.1
  - **B 路手搓**：`app/build2.sh`，直接调 `aapt2 compile/link` → `javac` → `d8` → `zipalign` → `apksigner`
- 为什么留两条路：B 路是本机最早跑通的构建（不依赖 Gradle 网络），
  A 路是为了让评委/老师能用 Android Studio 标准方式打开、构建、调试。
  **两条路的产物必须能互相覆盖安装**（签名必须同一把钥匙）。

**2. 云端服务**（`cloud/`，Node 18 + Express）
- 部署到华为云 ECS（Ubuntu 22.04），systemd 托管
- `deploy/install.sh` 是一键部署脚本：装 Node → 建用户 → 拉代码 → npm install → 检查 .env → 写 systemd 单元 → 启动 + 健康检查

## 二、本次审查的背景

这是第 4 批，也是最后一批。前三批审过：
- 第 1 批：HTML 前端页面
- 第 2 批：事件回放 + 专属演练（`CallSession` / `Notifier` / `Guard` 等）
- 第 3 批：判定链核心（`SmsReceiver` / `Judge` / `Acquaint` / 云端判分）

**这一批只审构建与部署**，不涉及业务逻辑。

## 四、请逐条回答的 10 个问题

### 问题 1｜双构建是否应该收敛成一套

两条路产物功能一致、签名一致、版本一致，但**存在差异**：
- `compileSdk`：Gradle 明确写 34；`build2.sh` 的 `aapt2 link` **没有传 `--compile-sdk-version`**，
  `aapt2 dump badging` 读出来的编译 SDK 与 Gradle 产物不一致
- Java 版本：Gradle 用 `sourceCompatibility 17`，`build2.sh` 用 `javac -source 8 -target 8`
- 依赖：Gradle 走 `implementation files('libs/mindspore-lite-java.jar')`，`build2.sh` 直接塞 `-classpath`

**问**：这份双构建长期维护的风险有多大？是否应该收敛成一套（哪一套）？
如果保留两套，最该补的一致性检查是什么？

### 问题 2｜手搓构建有没有漏掉 Gradle 会做的事

`build2.sh` 的流程是 `aapt2 compile → aapt2 link → javac → d8 → 打 zip → zipalign → apksigner`。

**问**：这个流程相比 AGP 的完整打包，漏掉了哪些**会影响真机安装或运行**的步骤？
（例如 resources.arsc 压缩策略、`--no-compress` 参数、v4 签名、`d8` 的 desugaring、
debug 符号表、`META-INF` 冲突处理。）在国产 ROM（EMUI / MIUI）上是否有额外的安装失败风险？

### 问题 3｜extractNativeLibs 与 useLegacyPackaging

`AndroidManifest.xml` 里写了 `android:extractNativeLibs="true"`（MindSpore Lite 的 `.so` 要在运行期解压加载），
`build.gradle` 里对应补了 `packagingOptions { jniLibs.useLegacyPackaging = true }`。

**问**：这个组合是否正确？对安装体积和冷启动时间有什么代价？
`build2.sh` 走的是**手工把 `lib/<abi>/*.so` 塞进 zip**，没有声明 `extractNativeLibs` 的对应处理——
这条路上 `.so` 能被正确解压吗？

### 问题 4｜危险权限清单是否过宽

清单里这些是"危险权限或特殊权限"：

| 权限 | 我们的理由 |
|---|---|
| `READ_SMS` + `RECEIVE_SMS` | 诈骗短信拦截的唯一入口 |
| `READ_CALL_LOG` + `READ_CONTACTS` | 只判断"这个号是不是陌生人" |
| `SYSTEM_ALERT_WINDOW` | 阻断级要盖住整屏 |
| `PACKAGE_USAGE_STATS` | 发现"老人打开了手机银行" |
| `ANSWER_PHONE_CALLS` | 红屏上要能挂断（`TelecomManager.endCall()`） |
| `MANAGE_EXTERNAL_STORAGE` | 读系统"通话自动录音"文件做挂断后复盘 |
| `QUERY_ALL_PACKAGES` | 判断"这个 App 是不是从应用商店装的" |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | 保活 |

**问**：
1. 哪几条可以用更小的权限或更窄的替代方案（例如 `QUERY_ALL_PACKAGES` 换成 `<queries>` 显式声明）？
2. `MANAGE_EXTERNAL_STORAGE` 在 Android 11+ 上除了"所有文件访问"还有别的合法路径吗？
3. 安卓 14 起 `FOREGROUND_SERVICE_DATA_SYNC` 的声明方式是否正确？
4. 这份清单在国内分发（应用市场）会遇到什么审核阻力，哪些必须能自圆其说？

### 问题 5｜明文 HTTP 的边界

`AndroidManifest.xml` 是 `android:usesCleartextTraffic="true"`，即**全应用允许明文**。
实际只连一个地址：`http://123.249.25.139:8080`（华为云 ECS，无域名、无证书）。
其中有一条 **SSE 长连接**（子女端收预警）。

**问**：是否应该改成 `networkSecurityConfig`，只对该 IP 放行明文、其余禁止？
这样做对 SSE 长连接、对 WebView 内加载的本地页面有没有副作用？
在"没有域名、没有证书"的现实约束下，还有没有更好的做法（自签证书 / IP SAN）？

### 问题 6｜短信接收器的广播保护是否正确

```xml
<receiver android:name=".SmsReceiver"
    android:exported="true"
    android:permission="android.permission.BROADCAST_SMS">
  <intent-filter android:priority="999">
    <action android:name="android.provider.Telephony.SMS_RECEIVED" />
  </intent-filter>
</receiver>
```
`priority=999` 是为了抢在系统短信 App 之前处理，`permission=BROADCAST_SMS` 是为了防止其他 App 伪造短信广播。

**问**：这个组合在 Android 12+ 上是否真的能挡住伪造？`BROADCAST_SMS` 是系统签名权限，
**普通应用声明它作为发送方限制**是否有效？有没有更标准的写法（`exported=false` 是否可行）？

### 问题 7｜systemd 单元没有指定运行用户（我认为这是一个真实缺陷）

`install.sh` 里建了 `yindun` 系统用户，并对 `/opt/yindun` 做了 `chown -R yindun:yindun`，
但生成的单元文件是：

```ini
[Service]
Type=simple
WorkingDirectory=/opt/yindun
ExecStart=/usr/bin/node src/server.js
Restart=always
RestartSec=3
LimitNOFILE=65535
```

**没有 `User=` / `Group=`，服务实际以 root 运行。**

**问**：
1. 这是否必须修？以 root 跑 Node 服务在这种场景下的实际风险有多大？
2. 如果加 `User=yindun`，需要注意哪些地方？这个服务会往工作目录下写文件
   （`data/` 存配对关系、`voice/` 存语音、`drill/` 存演练状态），
   还有 `Voice.js` 会 `mkdirSync` 子目录——`chown -R` 一次够不够？后续新建的目录归谁？
3. 除了 `User=`，还建议补哪些加固项（`NoNewPrivileges` / `ProtectSystem` / `PrivateTmp`）？
   哪些会**破坏**这个服务（它要读 `/opt/yindun/.env`、要写工作目录、要联网）？

### 问题 8｜rsync 不带 --delete 会不会导致旧文件残留

```bash
rsync -a --exclude '.env' --exclude '.git' "$pick"/ "$APP_DIR"/
```

**问**：没有 `--delete`，意味着新版本删掉的文件在服务器上仍然存在。
对这个项目最危险的残留是什么？
（我担心的是 `config/rules.json` 这类"改名或拆分"的情况：旧文件还在 `require` 路径上，
可能导致线上实际加载的规则版本与 `install.sh` 打印的版本号不一致。）
是否应该加 `--delete`？加了会不会误删 `.env` 或运行期生成的数据目录？

### 问题 9｜Restart=always 没有速率限制

ECS 只有 1 核 2 GB，可用内存约 1.2 GB。

**问**：
1. `Restart=always` + `RestartSec=3`，如果服务**启动即崩**（例如 `.env` 写错、端口被占），
   会不会无限重启？要不要加 `StartLimitIntervalSec` / `StartLimitBurst`？
2. 要不要加 `MemoryMax`？如果加，设多少合适（服务正常占用约 150~300 MB，峰值会跑模型调用）？
   超过限制时 systemd 会 OOM kill，这比整机卡死更好还是更坏？
3. 健康检查现在是"60 秒内 `/api/health` 返回 `ok:true`"，但对 `rds:false` / `redis:false`
   **只 warn 不失败**。这个策略对吗？

### 问题 10｜.env 加载语义与检查逻辑是否自洽

项目**没有用 `dotenv` 库**，`cloud/src/env.js` 是自己实现的：

```js
if (m && process.env[m[1]] === undefined) process.env[m[1]] = m[2];
```

**同一键出现两次时，取第一个值**（标准 `dotenv` 是后者覆盖前者，正好相反）。

`install.sh` 的检查用的是：

```bash
val="$(sed -n "s/^${k}=//p" "$ENV_FILE" | head -1 | tr -d ' \t\r\"')"
```

**问**：
1. 这两处的"取第一个值"是自洽的，但这种**与主流库相反**的语义是否应该改？
   风险是什么？（实际已经踩过一次：同事追加了一行同名配置，重启后仍是旧值，排查半天。）
2. `install.sh` 只检查 `RDS_HOST` / `RDS_PORT` / `RDS_USER` / `RDS_PASS` / `RDS_DB` / `REDIS_URL` 六项
   **非空**，不校验格式、不校验连通性。这个检查强度够吗？
3. 脚本"只检查、绝不代填"的设计（密码不进脚本、不进 git）是否还有改进空间？

```groovy
// 银盾 · 根工程
// 单模块：这个目录本身就是 app 模块，源码目录沿用原来的布局（src / assets / res / AndroidManifest.xml），
// 一个文件都不搬 —— 手搓的 build2.sh 还能照旧跑，Studio 也能认。

plugins {
    id 'com.android.application' version '8.7.3'
}

// ---- 签名信息从 local.properties 读，密码不写进版本库 ----
// local.properties 已被 .gitignore 排除；缺项时直接报错，避免静默用错钥匙
def localProps = new Properties()
def localPropsFile = rootProject.file('local.properties')
if (localPropsFile.exists()) {
    localPropsFile.withInputStream { localProps.load(it) }
}
['yd.storePassword', 'yd.keyPassword'].each { k ->
    if (!localProps.getProperty(k)) {
        throw new GradleException(
                "缺少签名配置 ${k}：请在 local.properties 中补齐\n" +
                        "  yd.storeFile=yindun.jks\n" +
                        "  yd.storePassword=<your password>\n" +
                        "  yd.keyAlias=<your alias>\n" +
                        "  yd.keyPassword=<your password>")
    }
}

android {
    namespace 'com.yindun.guard'
    compileSdk 34

    defaultConfig {
        applicationId "com.yindun.guard"
        minSdk 24
        targetSdk 34
        versionCode 1
        versionName "1.0"
    }

    // 关键：把 Gradle 的默认目录映射回现有结构
    sourceSets {
        main {
            manifest.srcFile 'AndroidManifest.xml'
            java.srcDirs = ['src']
            assets.srcDirs = ['assets']
            res.srcDirs = ['res']
            // 端侧模型的原生库（MindSpore Lite 2.11，只放推理用的 .so，训练库不需要）
            jniLibs.srcDirs = ['jniLibs']
        }
    }

    signingConfigs {
        // 复用 build2.sh 用的那把钥匙，保证两种构建方式装出来是同一个签名（可以直接覆盖安装）
        // 具体值在 local.properties（不进版本库）
        yindun {
            storeFile file(localProps.getProperty('yd.storeFile', 'yindun.jks'))
            storePassword localProps.getProperty('yd.storePassword')
            keyAlias localProps.getProperty('yd.keyAlias', 'yindun')
            keyPassword localProps.getProperty('yd.keyPassword')
        }
    }

    buildTypes {
        debug {
            signingConfig signingConfigs.yindun
            // 演示用：装得快，不做混淆
            minifyEnabled false
        }
        release {
            signingConfig signingConfigs.yindun
            minifyEnabled false
        }
    }

    compileOptions {
        sourceCompatibility JavaVersion.VERSION_17
        targetCompatibility JavaVersion.VERSION_17
    }

    // manifest 里写了 extractNativeLibs="true"（MindSpore Lite 的 .so 要能被解压出来加载），
    // AGP 8 要求这里显式声明同一个意思，否则打包时刷一条警告。
    // 2026-11-19 补：原来只有警告、不影响产物，但警告会让人以为配置写错了。
    packagingOptions {
        jniLibs.useLegacyPackaging = true
    }

    // 纯 Java 手写 View，没有 XML 布局，不需要 buildFeatures
    lint {
        abortOnError false
    }
}

dependencies {
    // MindSpore Lite 的 Java 接口（com.mindspore.Model / MSTensor / MSContext…）。
    // 它不在 libs 之外的地方，原生库在 jniLibs/ 下，两者版本必须对应同一个 Lite 版本。
    implementation files('libs/mindspore-lite-java.jar')
}
```

### C2. 手搓构建（`app/build2.sh`）

```bash
#!/bin/bash
# 无删除版构建：不 rm 任何目录，每次编译到一个新的时间戳目录。
# 原 build.sh 第一步是 rm -rf build，会触发删除守卫，所以这里单独开一份。
set -e
cd "$(dirname "$0")"

SDK="D:/Android"
BT="$SDK/build-tools/35.0.1"
PLATFORM="$SDK/platforms/android-34/android.jar"
JDK="D:/Java/bin"
OUT="build_$(date +%m%d_%H%M%S)"

# 【2026-11-09】签名密码不再写死在这里。
# 源码要进版本库，密码跟着进去就等于把钥匙挂在门上；
# 统一从 local.properties 的 yd.storePassword 读（该文件已被 .gitignore 排除）。
read_prop() { grep -E "^$1=" "local.properties" 2>/dev/null | head -1 | cut -d= -f2- | tr -d '\r'; }
KS_PASS=$(read_prop yd.storePassword)
if [ -z "$KS_PASS" ]; then
  echo "✗ local.properties 里没有 yd.storePassword，无法签名"
  exit 1
fi

mkdir -p $OUT/compiled $OUT/classes $OUT/gen $OUT/dex

echo "[1/6] 编译资源 ..."
"$BT/aapt2.exe" compile --dir res -o $OUT/compiled

echo "[2/6] 链接资源 + 打包 assets ..."
"$BT/aapt2.exe" link \
  -o $OUT/base.apk \
  -I "$PLATFORM" \
  --manifest AndroidManifest.xml \
  -A assets \
  --java $OUT/gen \
  --min-sdk-version 24 \
  --target-sdk-version 34 \
  $OUT/compiled/*.flat

echo "[3/6] 编译 Java ..."
find src $OUT/gen -name "*.java" > $OUT/sources.txt
"$JDK/javac.exe" -encoding UTF-8 -source 8 -target 8 \
  -bootclasspath "$PLATFORM" \
  -classpath "libs/mindspore-lite-java.jar" \
  -d $OUT/classes \
  @$OUT/sources.txt

echo "[4/6] 转 dex ..."
find $OUT/classes -name "*.class" > $OUT/classlist.txt
# MindSpore Lite 的 Java 接口也要一起转进 dex，否则运行期找不到 com.mindspore.Model
"$BT/d8.bat" --lib "$PLATFORM" --min-api 24 --output $OUT/dex \
  @$OUT/classlist.txt libs/mindspore-lite-java.jar

echo "[5/6] 打包 dex 与原生库进 APK ..."
OUT=$OUT PYTHONPATH= python - <<'PY'
import os, zipfile, shutil
out = os.environ['OUT']
shutil.copy(out + '/base.apk', out + '/app-unsigned.apk')
with zipfile.ZipFile(out + '/app-unsigned.apk', 'a', zipfile.ZIP_DEFLATED) as z:
    z.write(out + '/dex/classes.dex', 'classes.dex')
    # 端侧模型的原生库（MindSpore Lite）。必须放在 lib/<abi>/ 下，系统才知道按 ABI 解压。
    for abi in ('arm64-v8a', 'armeabi-v7a'):
        d = os.path.join('jniLibs', abi)
        if not os.path.isdir(d):
            continue
        for f in sorted(os.listdir(d)):
            z.write(os.path.join(d, f), 'lib/%s/%s' % (abi, f))
            print('   打包 lib/%s/%s' % (abi, f))
print('   完成')
PY

"$BT/zipalign.exe" -f 4 $OUT/app-unsigned.apk $OUT/app-aligned.apk

echo "[6/6] 签名 ..."
"$BT/apksigner.bat" sign \
  --ks yindun.jks \
  --ks-pass "pass:$KS_PASS" \
  --key-pass "pass:$KS_PASS" \
  --out Yindun.apk \
  $OUT/app-aligned.apk

echo ""
echo "成功！产物：$(pwd)/Yindun.apk"
ls -lh Yindun.apk | awk '{print " 大小：" $5}'
```

### C3. 权限与组件清单（`app/AndroidManifest.xml`）

```xml

<!--
  银盾 · 安卓端清单文件

  每一条权限后面都写了为什么需要，答辩时可以逐条念。
  ============================================================
-->
<manifest xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:tools="http://schemas.android.com/tools"
    package="com.yindun.guard"
    android:versionCode="1"
    android:versionName="1.0">

    <!-- ==================== 权限区 ==================== -->

    <!-- 收短信。这是整个 App 的命门：没有它，诈骗短信我们根本不知道来过 -->
    <uses-permission android:name="android.permission.RECEIVE_SMS" />
    <uses-permission android:name="android.permission.READ_SMS" />

         注意：这个权限只能知道"在通话"，听不到任何内容。 -->
    <uses-permission android:name="android.permission.READ_PHONE_STATE" />

    <uses-permission android:name="android.permission.READ_CALL_LOG" />

         这是特殊权限，要去系统设置里手动开，不能弹窗要。 -->

        android:name="android.permission.PACKAGE_USAGE_STATS"

    <uses-permission android:name="android.permission.VIBRATE" />

    <!-- 安卓 14 起前台服务必须声明类型，dataSync 是最贴近"后台持续工作"的一类 -->
    <uses-permission android:name="android.permission.FOREGROUND_SERVICE_DATA_SYNC" />

         TelecomManager.endCall() 给了普通应用挂断的能力，凭这条权限。
         这是危险权限，要运行时申请；个别 ROM 只放行默认拨号器，那时会如实失败。 -->
    <uses-permission android:name="android.permission.ANSWER_PHONE_CALLS" />

    <!-- 引导用户把我们从电池优化名单里去掉（真正保命的一步） -->
    <uses-permission android:name="android.permission.REQUEST_IGNORE_BATTERY_OPTIMIZATIONS" />

    <!-- 开机自启：手机重启后守护要自己站起来。
         少了这一条，老人只要重启一次，银盾就成了一张摆在那儿的图标。 -->
    <uses-permission android:name="android.permission.RECEIVE_BOOT_COMPLETED" />

    <!-- 查询已安装应用：判断"这个 App 是不是从应用商店装的" -->
    <uses-permission
        android:name="android.permission.QUERY_ALL_PACKAGES"
        tools:ignore="QueryAllPackagesPermission" />

    <!-- 联网：调用华为云 ModelArts Studio（盘古大模型）。
         创新赛道要求用华为技术栈，这个权限就是那条链路。
         注意：只有"灰区复审"和"生成子女摘要"会走网络，
         实时拦截（盖屏）永远是本地判断，断网照样能用。 -->
    <uses-permission android:name="android.permission.INTERNET" />

    <!-- 读系统通话录音（挂断后复盘用，老人在首页手动开启才生效）。
         我们自己不录音——安卓 9 起第三方 App 录不了通话。读的是系统电话
         "自动通话录音"生成的文件（荣耀/华为/小米等国行机型自带）。
         安卓 10 及以下用 READ_EXTERNAL_STORAGE，安卓 11+ 用"所有文件访问"。 -->
    <uses-permission
        android:name="android.permission.READ_EXTERNAL_STORAGE"
        android:maxSdkVersion="32" />
    <uses-permission
        android:name="android.permission.MANAGE_EXTERNAL_STORAGE"
        tools:ignore="ScopedStorage" />
    <uses-permission android:name="android.permission.ACCESS_NETWORK_STATE" />

    <!-- ==================== 应用本体 ==================== -->
    <application
        android:label="@string/app_name"
        android:icon="@drawable/ic_launcher"
        android:allowBackup="false"
        android:usesCleartextTraffic="true"
        android:requestLegacyExternalStorage="true"
        android:extractNativeLibs="true"
        android:supportsRtl="true"
        android:theme="@android:style/Theme.Material.Light.NoActionBar">

        <!-- 唯一的主界面。
             exported=true 必须写：Android 12+ 不写就装不上。
             它里面只有一个 WebView，界面是我们已经做好的 index.html。 -->
        <activity
            android:name=".MainActivity"
            android:exported="true"
            android:launchMode="singleTop"
            android:configChanges="orientation|screenSize|keyboardHidden"
            android:windowSoftInputMode="adjustResize">
            <intent-filter>
                <action android:name="android.intent.action.MAIN" />
                <category android:name="android.intent.category.LAUNCHER" />
            </intent-filter>
        </activity>

        <!-- 短信接收器。
             priority=999：在系统短信 App 之前收到，才来得及盖屏。
             permission=BROADCAST_SMS：只允许系统发这个广播，防止别的 App 伪造诈骗短信骗我们的引擎。
             exported=true：Android 12+ 不写就收不到广播。 -->
        <receiver
            android:name=".SmsReceiver"
            android:exported="true"
            android:permission="android.permission.BROADCAST_SMS">
            <intent-filter android:priority="999">
                <action android:name="android.provider.Telephony.SMS_RECEIVED" />
            </intent-filter>
        </receiver>

        <!-- 装包广播：老人自己装了个软件时叫醒我们。
             data scheme="package" 必须写，否则收不到。 -->
        <receiver
            android:name=".InstallReceiver"
            android:exported="true">
            <intent-filter>
                <action android:name="android.intent.action.PACKAGE_ADDED" />
                <action android:name="android.intent.action.PACKAGE_REPLACED" />
                <data android:scheme="package" />
            </intent-filter>
        </receiver>

        <!-- 守护服务：前台服务，状态栏常驻"银盾守护中"。
             有这个，界面关了、屏幕黑了两小时，监听还在跑。 -->
        <service
            android:name=".GuardService"
            android:exported="false"
            android:foregroundServiceType="dataSync" />

        <!-- 通知守护：盖屏期间清掉通知栏（否则验证码会从短信通知里漏出来）。
             需要用户在「设置 → 通知使用权」里手动勾选，不能静默获取。 -->
        <service
            android:name=".NotiGuard"
            android:exported="true"
            android:label="银盾（盖屏时清通知）"
            android:permission="android.permission.BIND_NOTIFICATION_LISTENER_SERVICE">
            <intent-filter>
                <action android:name="android.service.notification.NotificationListenerService" />
            </intent-filter>
        </service>

        <!-- 反诈演练：原生页面，不套 WebView（老人要看清字，字号得能直接控）。
             独立 Activity，从主界面按钮、桌面图标、演练通知三个地方都能进来。 -->
        <activity
            android:name=".DrillActivity"
            android:exported="false"
            android:label="反诈演练"
            android:configChanges="orientation|screenSize|keyboardHidden"
            android:theme="@android:style/Theme.Material.NoActionBar" />

        <!-- 上报可疑信息：同样是原生页。
             老人收到诈骗短信，两步就能甩进来让 AI 看，不用截图再去微信里转。
             windowSoftInputMode=adjustResize：键盘弹起来时输入框不能被盖住。 -->
        <activity
            android:name=".ReportActivity"
            android:exported="false"
            android:label="上报可疑信息"
            android:configChanges="orientation|screenSize|keyboardHidden"
            android:windowSoftInputMode="adjustResize"
            android:theme="@android:style/Theme.Material.NoActionBar" />

        <!-- 定期演练提醒：每周一 10:00 由 AlarmManager 拉起，App 被杀也能响 -->
        <receiver
            android:name=".DrillReceiver"
            android:exported="false">
            <intent-filter>
                <action android:name="com.yindun.guard.DRILL_REMIND" />
            </intent-filter>
        </receiver>

        <!-- 开机自启：手机重启后把守护服务拉起。
             exported=true 是必须的 —— 系统发的广播来自别的进程，
             写成 false 就永远收不到（Android 12 起不写也会被判收不到）。
             QUICKBOOT_POWERON 是小米/vivo/OPPO 那几家自己的"快速开机"广播，
             标准 BOOT_COMPLETED 在它们身上有时不发，补这两条兜住。 -->
        <receiver
            android:name=".BootReceiver"
            android:exported="true"
            android:enabled="true">
            <intent-filter>
                <action android:name="android.intent.action.BOOT_COMPLETED" />
                <action android:name="android.intent.action.QUICKBOOT_POWERON" />
                <action android:name="com.htc.intent.action.QUICKBOOT_POWERON" />
            </intent-filter>
        </receiver>

    </application>
</manifest>
```

### C4. 一键部署脚本（`deploy/install.sh`，含 systemd 单元生成）

```bash
#!/usr/bin/env bash
#===============================================================================
# 银盾服务一键部署脚本（裸机 -> 服务可用）
#
# 用法：
#   方式A 从 git 仓库拉代码（仓库私有，需要有权限的账号）：
#     sudo bash install.sh --repo https://github.com/6fvmtyymc9-sketch/yindun.git [--branch main]
#   方式B 从本地目录拷代码（scp 上传后指定目录，兼容仓库 cloud/ 子目录）：
#     sudo bash install.sh --src /root/yindun-cloud
#   代码已经在 /opt/yindun 里时（如 scp 直接传到 /opt/yindun）：
#     sudo bash install.sh
#
# 铁律（队长交接书约定）：
#   1. 脚本内绝不出现任何密码/Key/AK/SK。.env 由人工在服务器上填写，
#      本脚本只检查"有没有填"，绝不代填。
#   2. 幂等：重复跑不报错，已装好的不重装。
#   3. 不假设任何东西已存在：没有 Node/目录/用户都能自己搞定。
#===============================================================================
set -euo pipefail

APP_DIR="/opt/yindun"
APP_USER="yindun"
SERVICE_NAME="yindun"
REPO_URL=""
SRC_DIR=""
BRANCH=""

log()  { echo -e "\033[32m[install]\033[0m $*"; }
warn() { echo -e "\033[33m[warn]  \033[0m $*"; }
die()  { echo -e "\033[31m[error]\033[0m $*" >&2; exit 1; }

#---------------- 参数解析 ----------------
while [[ $# -gt 0 ]]; do
  case "$1" in
    --repo)   REPO_URL="$2"; shift 2 ;;
    --branch) BRANCH="$2"; shift 2 ;;
    --src)    SRC_DIR="$2"; shift 2 ;;
    *) die "未知参数: $1 （支持 --repo --branch --src）" ;;
  esac
done

#---------------- 步骤0：权限检查 ----------------
if [[ $EUID -ne 0 ]]; then
  if command -v sudo >/dev/null 2>&1; then
    exec sudo -E bash "$0" "$@"
  fi
  die "请用 root 或 sudo 运行本脚本"
fi

#---------------- 步骤1：检查系统 ----------------
[[ -r /etc/os-release ]] || die "读不到 /etc/os-release，不是标准 Linux 发行版"
. /etc/os-release
case "${ID:-}" in
  ubuntu|debian) ;;
  *) die "仅支持 Ubuntu 20.04+ / Debian 11+，当前系统: ${ID:-unknown}" ;;
esac
if [[ -n "${VERSION_ID:-}" ]]; then
  MAJOR="${VERSION_ID%%.*}"
  if { [[ "$ID" == "ubuntu" ]] && [[ "$MAJOR" -lt 20 ]]; } || \
     { [[ "$ID" == "debian" ]] && [[ "$MAJOR" -lt 11 ]]; }; then
    die "$ID $VERSION_ID 版本过低，要求 Ubuntu 20.04+ / Debian 11+"
  fi
else
  warn "未识别到版本号（可能是 sid），继续执行"
fi
log "系统检查通过: ${PRETTY_NAME:-$ID}"

#---------------- 步骤2：安装基础工具 ----------------
if ! command -v curl >/dev/null 2>&1 || ! command -v rsync >/dev/null 2>&1 \
   || ! command -v git >/dev/null 2>&1; then
  log "安装基础工具 curl/git/rsync ..."
  apt-get update -y || warn "apt-get update 失败（网络原因），尝试继续"
  DEBIAN_FRONTEND=noninteractive apt-get install -y curl ca-certificates git rsync gnupg
else
  log "基础工具已齐，跳过安装"
fi

#---------------- 步骤3：Node.js 18+（幂等，已有则跳过）----------------
need_node=1
if command -v node >/dev/null 2>&1; then
  NODE_MAJOR="$(node -p 'process.versions.node.split(".")[0]' 2>/dev/null || echo 0)"
  if [[ "$NODE_MAJOR" -ge 18 ]]; then
    need_node=0
    log "Node $(node -v) 已安装，跳过"
  else
    warn "Node $(node -v) 版本低于 18，重新安装"
  fi
fi
if [[ $need_node -eq 1 ]]; then
  log "通过 NodeSource 安装 Node.js 18 ..."
  curl -fsSL https://deb.nodesource.com/setup_18.x | bash -
  DEBIAN_FRONTEND=noninteractive apt-get install -y nodejs
fi
NODE_BIN="$(command -v node)"
[[ -x "$NODE_BIN" ]] || die "安装后仍找不到 node 可执行文件"
log "使用 Node: $NODE_BIN ($(node -v))"

#---------------- 步骤4：建目录、建运行用户 ----------------
id -u "$APP_USER" >/dev/null 2>&1 || useradd --system --create-home --shell /usr/sbin/nologin "$APP_USER"
mkdir -p "$APP_DIR"
log "目录 $APP_DIR 与用户 $APP_USER 就绪"

#---------------- 步骤5：拉代码（git clone 或本地拷，两种都支持）----------------
# 说明：仓库里服务代码在 cloud/ 子目录（cloud/src/server.js），自动识别。
copy_code() {
  local src_root="$1"
  local pick=""
  if   [[ -d "$src_root/cloud/src" ]]; then pick="$src_root/cloud"
  elif [[ -d "$src_root/src"     ]]; then pick="$src_root"
  else die "$src_root 里既没有 cloud/src 也没有 src，代码路径不对？"
  fi
  log "从 $pick 拷贝代码到 $APP_DIR（.env/.git 不会覆盖）"
  rsync -a --exclude '.env' --exclude '.git' "$pick"/ "$APP_DIR"/
}

if [[ -n "$SRC_DIR" ]]; then
  [[ -d "$SRC_DIR" ]] || die "--src 目录不存在: $SRC_DIR"
  copy_code "$SRC_DIR"
elif [[ -n "$REPO_URL" ]]; then
  TMP="$(mktemp -d)"
  log "git clone $REPO_URL ..."
  git clone --depth 1 ${BRANCH:+-b "$BRANCH"} "$REPO_URL" "$TMP/repo"
  copy_code "$TMP/repo"
  rm -rf "$TMP"
else
  [[ -f "$APP_DIR/src/server.js" ]] || die "未指定 --repo/--src，且 $APP_DIR/src/server.js 不存在"
  log "使用 $APP_DIR 里已有代码"
fi

#---------------- 步骤6：npm install --production（幂等）----------------
cd "$APP_DIR"
if [[ ! -d node_modules ]] || [[ -n "${FORCE_INSTALL:-}" ]]; then
  log "npm install --production（等价 --omit=dev）..."
  npm install --omit=dev --no-audit --no-fund
else
  log "node_modules 已存在，跳过 npm install（FORCE_INSTALL=1 可强制重装）"
fi
chown -R "$APP_USER:$APP_USER" "$APP_DIR"

#---------------- 步骤7：检查 .env（只检查，绝不代填）----------------
ENV_FILE="$APP_DIR/.env"
REQUIRED_KEYS=(RDS_HOST RDS_PORT RDS_USER RDS_PASS RDS_DB REDIS_URL)
[[ -f "$ENV_FILE" ]] || die "缺少 $ENV_FILE 。请手工创建并填写（该文件不进 git）：\n      RDS_HOST=  RDS_PORT=3306  RDS_USER=  RDS_PASS=  RDS_DB=yindun\n      REDIS_URL=redis://:<密码>@<Redis内网地址>:6379/0  TZ=Asia/Shanghai"

# 常见拼写错误当场拦截：键名必须是 RDS_PASS，写成 RDS_PASSWORD 会静默降级成内存存储
if grep -q '^RDS_PASSWORD=' "$ENV_FILE"; then
  die "$ENV_FILE 里写的是 RDS_PASSWORD，正确键名是 RDS_PASS（少个 WORD）！改完再跑"
fi
missing=()
for k in "${REQUIRED_KEYS[@]}"; do
  val="$(sed -n "s/^${k}=//p" "$ENV_FILE" | head -1 | tr -d ' \t\r\"')"
  [[ -z "$val" ]] && missing+=("$k")
done
if [[ ${#missing[@]} -gt 0 ]]; then
  die "以下必填项缺失或为空: ${missing[*]}\n      请手工编辑 $ENV_FILE 填好后重新运行本脚本（脚本不代填）"
fi
grep -q '^TZ=' "$ENV_FILE" || warn ".env 里没有 TZ，建议加 TZ=Asia/Shanghai"
log ".env 检查通过（必需项齐全）"

# 把实际部署的规则版本打出来。录屏、答辩、以及"以为推了新规则其实推了旧代码"
# 这三种场合都用得上 —— 版本号是唯一能三秒内自证的凭据。
if [[ -f "$APP_DIR/config/rules.json" ]]; then
  RULE_VER="$("$NODE_BIN" -p "require('$APP_DIR/config/rules.json').version" 2>/dev/null || echo '?')"
  RULE_KW="$("$NODE_BIN" -p "(require('$APP_DIR/config/rules.json').sms_keywords||[]).length" 2>/dev/null || echo '?')"
  log "代码里的规则版本: $RULE_VER · 关键词 $RULE_KW 条"
fi
APP_PORT="$(sed -n 's/^PORT=//p' "$ENV_FILE" | head -1 | tr -d ' \t\r\"')"
APP_PORT="${APP_PORT:-8080}"

#---------------- 步骤8：写 systemd 服务单元（模板来自线上机器，勿改结构）----------------
# 差异说明（队长交接书）：
#   - ExecStart 用 NODE_BIN 动态取，兼容 apt 装（/usr/bin）与 NodeSource/手工装（/usr/local/bin）
#   - 不加 EnvironmentFile：cloud/src/env.js 自己解析 /opt/yindun/.env，两套加载会打架
#   - Description 与线上一致，方便 journalctl / grep 对照，别自己改名字
#
# 【2026-11-18 改：本机依赖改成运行时探测】
#   原来固定写 After/Wants=mysql.service redis-server.service —— 那是"数据库和代码装在
#   同一台 ECS"阶段的写法。迁到 RDS / DCS 之后要 systemctl stop mysql redis-server，
#   可只要这两个单元还挂在 Wants 里，重启 yindun 就会把它们一起拉起来：
#   停掉的 mysql 又活了、又吃四百兆内存，而它的数据已经不该再被写。
#   所以现在：本机真有这俩服务才写依赖；没有（新机器直连 RDS）就只依赖 network。
LOCAL_DEPS=""
for u in mysql.service mariadb.service redis-server.service redis.service; do
  if [[ -n "$(systemctl list-unit-files "$u" --no-legend 2>/dev/null || true)" ]]; then
    LOCAL_DEPS="$LOCAL_DEPS $u"
  fi
done
LOCAL_DEPS="$(echo "$LOCAL_DEPS" | sed 's/^ *//; s/ *$//')"
DEP_AFTER="network.target"
DEP_WANTS=""
if [[ -n "$LOCAL_DEPS" ]]; then
  DEP_AFTER="network.target $LOCAL_DEPS"
  DEP_WANTS="Wants=$LOCAL_DEPS"
  log "检测到本机数据库服务: $LOCAL_DEPS（会写进 After/Wants）"
else
  log "本机没有 mysql/redis 服务，单元只依赖 network（直连 RDS/DCS 的正常形态）"
fi

cat > /etc/systemd/system/${SERVICE_NAME}.service <<EOF
[Unit]
Description=Yindun Anti-Fraud Cloud Service
After=${DEP_AFTER}
${DEP_WANTS}

[Service]
Type=simple
WorkingDirectory=${APP_DIR}
ExecStart=${NODE_BIN} src/server.js
Restart=always
RestartSec=3
LimitNOFILE=65535

[Install]
WantedBy=multi-user.target
EOF
log "已写入 /etc/systemd/system/${SERVICE_NAME}.service (ExecStart=$NODE_BIN)"

#---------------- 步骤9：启动并健康检查 ----------------
systemctl daemon-reload
systemctl enable --now "$SERVICE_NAME"
log "服务已 enable --now，等待健康检查..."

resp=""
for i in $(seq 1 30); do
  sleep 2
  resp="$(curl -fsS "http://localhost:${APP_PORT}/api/health" 2>/dev/null || true)"
  if echo "$resp" | grep -q '"ok"[[:space:]]*:[[:space:]]*true'; then break; fi
  resp=""
done
[[ -n "$resp" ]] || {
  warn "健康检查 60 秒内未通过，排查命令："
  warn "  systemctl status $SERVICE_NAME"
  warn "  journalctl -u $SERVICE_NAME -n 50 --no-pager"
  exit 1
}
log "健康检查通过: $resp"
echo "$resp" | grep -q '"rds":true'   || warn "rds 尚为 false —— 检查 .env 键名是否为 RDS_PASS、RDS 是否同 VPC"
echo "$resp" | grep -q '"redis":true' || warn "redis 尚为 false —— 检查 REDIS_URL 格式: redis://:<密码>@<地址>:6379/0"

cat <<EOF

============================================================
```

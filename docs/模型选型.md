# 模型选型说明

银盾用到的"模型"分三层：**本地规则引擎**（不是机器学习模型，但承担第一道判定）、**云端大模型**（复核与讲解）、**语音识别**（通话录音转文字）。
另有两项计划中的专用模型。本文说明每一层用什么、为什么、怎么配置、下一步怎么做。

---

## 一、总览

| 层 | 现在用的 | 运行位置 | 状态 |
|---|---|---|---|
| 规则引擎 | `rules.json` v3.4（212 个关键词 + 33 个反例词，S0～S4 阶段） | 手机端 `Judge.java` + 云端 `Judge.js` | ✅ 已上线，有测试集 |
| 文本 / 截图复核 | 华为云 MaaS **DeepSeek-V4.1-Flash** | 云端 `Pangu.js` | ✅ 短信、截图复审为原有功能；**通话复盘已用真实接口跑通（2026-11-11）** |
| 通话语音识别 | 华为云 **SIS 一句话识别**（`chinese_8k_common`），或任意 OpenAI 兼容接口（默认 `whisper-1`） | 云端 `Asr.js` + `HwSign.js` + `AudioSplit.js` | ✅ **已用真实账号跑通（2026-11-11）**：AK/SK 签名鉴权，三段样例录音 1.4~2.2 s/段；长录音按 55 s 切段后逐段识别再拼接 |
| 端侧文本小模型 | `huawei-noah/TinyBERT_4L_zh`（4 层，自搭网络，45.7 MB）。数据 = `cases.json` + 合成样本 + ChiFraud 难负样本 | MindSpore 训练（✅）；MindSpore Lite 上手机（📋 未做） | ✅ 训练与留出集评估已完成：并联后漏报 0~5%、误报 6.7%，35.7 ms/条。**待转 Lite 部署** |
| 电话诈骗专用模型 | AntiFraud-SFT（Qwen2-Audio-7B）第三票 | 云端 GPU | ⚠️ 代码已接入 `CallAudio.js`（并行、60 s 上限、只抬不降），本机内存不足未能实跑，线上如实报 `sft.enabled:false` |

**判定链路**：手机端规则先判（离线、毫秒级）→ 落在"拿不准"区间的送云端大模型复核 → 大模型给出结论、诈骗阶段、给老人的话。
通话录音则是：系统录音 → 云端语音识别 → 规则 + 大模型 → 推回老人端和子女端。

## 二、云端大模型：DeepSeek-V4.1-Flash（华为云 MaaS）

### 2.1 为什么选它

代码里已写明选型结论（`cloud/src/Pangu.js` 第 22～26 行）：

- **非思考型**：约 2 秒出结果，适合实时预警，不会花时间在长思考链上；
- **价格低**：比 GLM-5.2 便宜约 4 倍（单价表见 `Pangu.js` 的 `PRICE`，闲时 21:00～07:59 五折）；
- **中文好**，并且**挂在华为云 MaaS 上**（满足赛题对华为云的要求）；
- 需求方明确**不用盘古**。文件名 `Pangu.js` 是历史遗留，实际调用的是 MaaS 上的 DeepSeek。
- 支持图片输入（`image_url`），所以截图复审也用同一个模型。

备选：`openpangu-2.0-flash`（最便宜，仅应急）；`glm-5.2`（贵且慢，已弃用）。

### 2.2 用在哪里

| 功能 | 接口 / 位置 | 什么时候调用 |
|---|---|---|
| 短信复核 | 手机端 `SmsReceiver.java` → 云端 | 本地规则 30～45 分（拿不准）时 |
| 截图复审 | `POST /api/report` | 老人或子女上传可疑截图 |
| 演练对练 | `POST /api/drill/turn` | 演练模式里扮演骗子 |
| 通话复盘 | `POST /api/callaudio`（`CallAudio.js` → `Pangu.judgeCall()`） | 每通陌生来电挂断后 |

通话复盘的提示词要求大模型**只能引用转写稿里真实出现的句子**作为证据，`CallAudio.js` 会再过滤一遍，防止大模型编造"骗子说过的话"。

### 2.3 配置

在 `cloud/.env`（从 `.env.example` 复制）里填：

```bash
MAAS_URL=https://api.modelarts-maas.com/v2/chat/completions
MAAS_KEY=你的 API Key          # ModelArts Studio →「在线推理」开通模型后获取
MAAS_MODEL=deepseek-v4.1-flash
MAAS_TIMEOUT=20000
```

不填 `MAAS_KEY` 也能跑，只是退化为"只用规则"。检查是否配好：`GET /api/callaudio/ping`，返回里的 `llm` 字段就是当前模型名。

## 三、语音识别（通话录音转文字）

`Asr.js` 支持三种方式，按顺序自动选：

1. **华为云 SIS 一句话识别**（✅ 2026-11-11 已用真实账号跑通）：
   填 `SIS_PROJECT_ID` + 鉴权三选一 —— **AK/SK（推荐，`HW_AK`/`HW_SK`）**、`SIS_TOKEN`、或 IAM 账号密码。
   参数 `SIS_PROPERTY=chinese_8k_common`：电话录音是 8kHz 采样，用 8k 模型更准。
   ⚠️ `chinese_8k_general` 这个名字在一句话识别里**不存在**（那是实时语音识别的取值），填了会报 `SIS.0032`。
2. **OpenAI 兼容接口**：填 `ASR_URL`、`ASR_KEY`、`ASR_MODEL`（默认 `whisper-1`），可接自建 Whisper 或其他平台。
3. **演示模式**：都不填时，读取录音旁边同名的 `.txt` 转写稿，结果会标注"演示文本"。

**60 秒限制：已解决（2026-11-11）**。实测边界：42.8 秒 / 128 KB 正常，128.3 秒 / 376 KB 返回
`SIS.0032 data element too large`。做法是**云端按帧边界切段**（`AudioSplit.js`，支持 mp3/amr/wav，
不转码、零音质损失），`Asr.viaSisChunked()` 默认 55 秒一段、逐段识别后拼接 —— 比"上传 OBS 走录音文件识别"
少一个存储依赖，也不用改 App。128 秒实测切 3 段全部识别成功，拼回 559 字连贯无缺。
m4a/aac 等容器格式无法无损切段，会如实报错并提示改用 mp3。
详见 [SIS 接入记录](SIS接入记录.md)。

## 四、计划中的专用模型

### 4.1 端侧中文文本小模型（优先做）

**要解决的问题**：规则在留出集上漏报 60%——骗子换个说法，关键词就一个都不命中（见 [规则测试与配对](规则测试与配对.md)）。
大模型能兜底，但要联网、有成本。一个装在手机上的小分类模型可以离线补上这一块。

| 项目 | 建议 |
|---|---|
| 基座模型 | `huawei-noah/TinyBERT_4L_zh`（华为出品，约 4 层，适合端侧）或 `hfl/rbt3`（3 层中文 RoBERTa） |
| 训练数据 | ChiFraud 中文诈骗文本数据集 + 本项目 `cloud/test/cases.json` 的样本 + 自行收集的正常短信 |
| 训练框架 | MindSpore（华为技术栈，答辩加分） |
| 部署 | 转 MindSpore Lite，放进 App，和规则引擎并联：任一判为可疑即提醒 ✅ **已完成（2026-11-11）**，见 [端侧模型部署记录](端侧模型部署记录.md) |
| 评估 | **必须用 `cloud/test/holdout.json` 评估**，并和规则 v3.4 的数字对比（漏报 60% / 误报 0%）。训练时不能用留出集 |

工作量主要在整理、清洗、标注数据，模型训练本身不难。

### 4.2 电话诈骗专用模型：TeleAntiFraud（对比实验）

- 模型：TeleAntiFraud 项目的 **AntiFraud-SFT**，基于 Qwen2-Audio-7B 微调，Apache 2.0 许可。
- 特点：直接"听"录音判断，不需要先转文字，能利用语气、语速等信息。
- 限制：约 17GB，**只能放云端，需要 GPU**（建议华为云 ModelArts 上的 GPU/昇腾实例）。手机端不可能部署。
- 数据集 `JimmyMa99/TeleAntiFraud` 在 Hugging Face 上需要先申请访问权限。
- 建议定位：作为**对比实验**放进报告——"语音识别 + 通用大模型" vs "专用语音模型"，比较准确率、延迟和成本。不建议替换主链路。

## 五、下一步（按优先级）

1. **用真实账号跑通通话复盘**：开通 SIS 和 MaaS，`GET /api/callaudio/ping` 确认两项都已配置，再用一段真实录音（或 `demo/calls/` 里的样例）走一遍。
   - MaaS：✅ 已开（`.env` 有 key，`deepseek-v4.1-flash`，对比实验中已真实调用）
   - SIS：✅ **已开通并跑通（2026-11-11）**。鉴权走 **AK/SK 签名**（`cloud/src/HwSign.js`），
     不用账号密码 —— IAM 用户开了登录保护（MFA）后，纯密码换 token 一律返回 401，
     而且报错文案和"密码错误"完全一样，白折腾了 6 次。
     实测 `demo/calls/` 三段真实电话录音全部识别成功，延迟 1.4~2.2 秒/段，
     识别结果与演示转写稿基本逐字吻合（如"喂，阿姨，您好，我是小区物业的小张…"）。
     踩坑过程与实测数字见 [SIS 接入记录](SIS接入记录.md)。
2. **解决 60 秒限制**：改用录音文件识别或分段。
   - ✅ **已完成（2026-11-11）**，走的是**分段**：`cloud/src/AudioSplit.js` 在**帧边界**上切，
     不转码、零音质损失，支持 mp3 / amr / wav（手机录音机常见格式）；
     云端 `Asr.viaSisChunked()` 默认按 55 秒切，逐段识别后拼接。
   - **实测的真实上限**：128 秒 / 376 KB 的 mp3 整段送，返回 `SIS.0032 data element too large`；
     42 秒 / 128 KB 正常。所以限制是实打实存在的，不切就丢内容。
   - **实测效果**：128 秒合成录音 → 切 3 段（54.9 / 54.9 / 18.4 秒）→ 三段全部识别成功，
     拼回 559 字，内容连贯、无整句丢失；接口返回里 `asr.parts=3`、`asr.durationSec=128` 如实带上。
   - **顺带修掉的一个连带问题**：切段后转写稿从 200 字级涨到 500~1000 字，
     大模型判定在 20 秒超时（实测 559 字的稿子会超）。`MAAS_TIMEOUT` 已调至 40 秒；
     超时也不会失败整次复盘，只会退回纯规则判定（`basis=rule`），这条降级路径实测有效。
   - **仍有边界**：m4a / aac / 3gp / ogg 容器带全局索引，纯字节切割会切坏，
     这类格式超过 60 秒时会如实报错并提示改格式，不假装已处理。
3. **扩大大模型复核范围**：留出集漏掉的大多是只命中"陌生号码"的 15 分短信，把送复核的下限从 30 分适当下调，并记录成本变化。
   - ✅ 已完成（2026-11-10）。门限改为「非服务号 + 本地未到 warn +（陌生号 或 正文 ≥15 字）」；
     放宽前用 `cloud/test/ai-review.js` 实测：诈骗 12 条全抓回、正常 9 条误判 1 条；约 0.0006 元/条。
4. **训练端侧小模型**（4.1），用留出集评估并写进答辩材料。
   - ✅ 训练与评估完成（2026-11-10，数据见 [模型对比实验](模型对比实验.md)）
   - ✅ 答辩材料已写：一句话答辩词、分歧案例、诚实的边界
   - ✅ **转 MindSpore Lite 上手机、与规则引擎并联（2026-11-11 完成）**：
     MindIR → `.ms`（44 MB）→ 打进 APK（assets + `jniLibs/`），
     `TinyBert.java` 负责分词与推理，`Judge.withTinyBert()` 做并联（只抬不降）。
     模拟器实测：模型分与 PC 端一致（0.7620 vs 0.762770），
     规则判 5 分/不打扰的样本被模型抬到 warn 并弹出提醒。
     踩坑与验证方法见 [端侧模型部署记录](端侧模型部署记录.md)
5. **TeleAntiFraud 对比实验**（4.2），时间充裕再做。⚠️ 代码已接，等 GPU

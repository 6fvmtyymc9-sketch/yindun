# 短文本-100 写作说明（第四轮考题·人工撰写）

> 依据：[`SFT接入计划.md`](SFT接入计划.md) 第 140 行。
> 这张表**只能人写，不能 AI 生成**；也**不能照着 holdout 漏掉的那 4 条改写**（否则就是对着考题训练）。
> 空表：`cloud/test/lora_20261123/r4/短文本100_填写表.csv`　自检：`tools/check_short100.py`

---

## 一、这套题解决什么问题

第三轮暴露的两类错，**都出在短句上**：

| 错法 | 第三轮例子 | 对应本套题库 |
|---|---|---|
| 漏报：只有钩子、不索款的短句 | 宝妈兼职、老年理财、数币内测名额、屏幕录制退款 | **A 组 50 条诈骗** |
| 误报：含高危词但合法 | 反诈宣传、微信验证码、社区网格员、"您孙女的同学" | **B 组 50 条正常** |

长录音（TAF-200）测不出这两类，因为真实诈骗短信**第一条就是不索款的**——索款要等你聊进去。

## 二、结构：50 + 50 = 100

### A 组 · 诈骗 50 条（只有诱饵，不索款）

**判据：看得出是诈骗意图，但正文里没有转账、汇款、验证码、链接、下载、扫一扫、共享屏幕这些"下一步动作"。**

建议按下面分配（可调整，但请保证 6 类以上都有）：

| 编号 | 类型 | 条数 |
|---|---|---|
| A01–A08 | 兼职刷单 / 刷信誉 | 8 |
| A09–A16 | 投资理财 / 荐股 / 内幕消息 | 8 |
| A17–A22 | 贷款 / 提额 / 额度异常 | 6 |
| A23–A28 | 冒充平台客服（退款、理赔、会员、注销） | 6 |
| A29–A34 | 冒充公检法 / 税务 / 社保 / 医保 | 6 |
| A35–A40 | 冒充熟人 / 领导 / 老师 | 6 |
| A41–A45 | 中奖 / 积分 / 名额 / 红包 | 5 |
| A46–A50 | 婚恋交友 / 杀猪盘开场 | 5 |

### B 组 · 正常 50 条（含高危词但完全合法）

**判据：正文里必须出现至少 1 个高危词**（验证码、转账、汇款、冻结、解冻、安全账户、额度、卡号、密码、退款、理赔、链接、二维码、涉案、立案、传票、保证金……），**但整件事是合法的日常事务**。

| 编号 | 场景 | 条数 |
|---|---|---|
| B01–B08 | 银行验证码 / 交易提醒 | 8 |
| B09–B16 | 支付、电商订单与退款 | 8 |
| B17–B22 | 快递 / 外卖 / 物流 | 6 |
| B23–B28 | 运营商 / 宽带 / 套餐 | 6 |
| B29–B36 | 亲友家人传话（含"转个钱""发卡号"） | 8 |
| B37–B44 | 单位 / 学校 / 社区通知 | 8 |
| B45–B50 | 反诈宣传 / 公安提醒 | 6 |

## 三、写作规则（硬性）

1. **长度 15~60 字**（正文，标点算）。少于 10 字或超过 80 字自检会报错。
2. **一条只写一件事**，不要把两条短信拼在一起。
3. **A 组不许出现**：转账、汇款、转钱、打款、付款、验证码、安全账户、冻结、解冻、点击、链接、二维码、扫码、下载、APP、共享屏幕、保证金、密码、卡号。
   → 钩子可以用：名额、返利、稳赚、内部、内测、加我、私聊、回复、领取、优先、包过。
   → **链接和二维码也算"下一步动作"，A 组不要写**；写了规则引擎会直接命中，就测不出难度了。
4. **B 组必须做到两件事**：含 ≥1 个高危词；同时写出"这件事为什么合法"的线索（比如尾号、官方号码、无需回复、可到店核实）。
5. **不许照抄 holdout 漏掉的那 4 条**，也不许只换几个词。
6. **不许用 AI 生成**。真实素材优先。
7. **脱敏**：真手机号、真卡号、真姓名、真单位名一律换成 X 或化名。

## 四、什么算"写坏了"

| 情况 | 为什么不行 |
|---|---|
| A 组里写了"请转账""把验证码发我" | 变成索款类，不是 A 组的题 |
| A 组写成完整通顺的长段（有称呼、有背景、有结尾） | 真实诈骗短句是破碎、突兀、缺前因的，写太完整就测不出真实场景 |
| B 组只是正常短信，一个高危词都没有 | 测不出误报，等于白填 |
| B 组里带催促、威胁、陌生链接 | 你自己就判错了，标签会是错的 |
| 同一条换个词复制 5 遍 | 去重会挂，而且 100 条里有 20 条是同一个模板，结论就不可信了 |
| 正文里塞了备注、解释 | 评测时会把备注也送进模型，污染结果 |

## 五、素材从哪来

| 来源 | 怎么用 | 注意 |
|---|---|---|
| **自己手机短信** | 银行验证码、运营商套餐、快递通知——B 组最好的一手来源 | 脱敏后可用，删掉真实尾号和姓名 |
| **12321 举报公示 / 运营商拦截通报** | 诈骗短信原文，把最后索款那句删掉，只留前面的钩子 → 正好是 A 组 | 只留钩子，别把整段抄进来 |
| **公安 / 反诈中心通报的案例** | 常见话术提炼 | 通报是转述，要改成短信口吻 |
| **微信群 / 短信里收到过的** | A 组的主要来源 | 记不清原文就按意思重写，别硬编 |
| **自己编** | 允许，但要在"素材来源"列注明"自编" | 自编比例别过半 |

## 六、表怎么填

列一共 7 列，`编号 / 分组 / 类型 / 正文 / 判断依据 / 素材来源 / 备注`。

一行示例（**占位符，照格式填，别照着内容写**）：

```
A01,诈骗,兼职刷单,【填短信正文，15~60字，不要带引号】,【一句话说明为什么这是诈骗】,自编,
B01,正常,银行验证码,【填短信正文，必须含高危词】,【一句话说明为什么这件事合法】,自己手机,
```

填的时候注意：

- **正文里不要用英文双引号 `"`**，用中文引号「」或直接不用。CSV 遇到英文引号会解析错。
- **正文里不要用英文逗号**，用中文逗号；非要用就整格用英文双引号包起来。
- Excel 直接另存为 CSV 也行，脚本能读 GBK 和 UTF-8 两种编码。
- 判断依据写给自己看，防止事后标错——它不会送进模型。

## 七、填完怎么自检

```bash
python3 tools/check_short100.py cloud/test/lora_20261123/r4/短文本100_填写表.csv
```

会查这些：条数是否 50/50、编号是否连续、字数、A 组禁词、B 组高危词覆盖、组内重复、判断依据是否空。全部通过会打印 `PASS`。

加上 `--train` 还能查和第三轮训练集有没有撞车：

```bash
python3 tools/check_short100.py <表路径> --train "D:/华为ict/_训练数据备份_20261124/r3/data/train.jsonl"
```

通过后转成评测输入：

```bash
python3 tools/check_short100.py <表路径> --emit-jsonl cloud/test/lora_20261123/r4/short100.jsonl
```

然后跑基线（原始模型）：

```bash
python3 tools/eval_judge.py --url http://127.0.0.1:8000 \
    --input cloud/test/lora_20261123/r4/short100.jsonl \
    --out cloud/test/lora_20261123/r4/base_short100.jsonl --workers 3
```

按老师说，短文本-100 **只用文字模式**，不用录音。判据是：训练后召回不低于原始模型、误报不高于原始模型。

## 八、为什么卡在这一步

这不是技术卡点。TAF-200 那边我已经用官方真值 + 整批排除做完并跑了基线，机器能做的都做完了。
短文本这套是**唯一必须由人提供的内容**：用 AI 写，写出来的句子会带着和训练数据同一套语言习惯，模型答对了也说明不了它能认出真实短信——等于自己给自己发合格证。

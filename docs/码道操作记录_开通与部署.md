### 1.1 前置：IAM 子用户 `yindun-codearts`（队长在控制台做，不在码道里）

甲用的是队长账号的权限，而**主账号密钥能改 IAM、能开 ECS、能删库，不能外传**。所以开实例用的是专用子用户。

| 项 | 值 | 理由 |
|---|---|---|
| 用户名 | `yindun-codearts` | 与 MySQL 账号 `yindun` 区分开，CTS 审计里一眼能认 |

| 用户组 | `yindun-rds-dcs`（专用组） | 实测：新版 IAM 的授权方式只有「继承所选用户组的策略」，**不支持给用户直接授策略** |

## 七、已知的两个坑（实测，不是推测）

### 7.1 `--password` 与 KooCLI 系统参数同名

RDS 和 DCS 的创建接口都有 `password` 参数，KooCLI 自己也有一个系统参数叫 `password`。
直接写 `--password=xxx` 会立刻退出：

```
目标API中存在与KooCLI系统参数password同名的参数,无法识别--password的位置.
```

**解法**：用 `--cli-jsonInput=<file>` 把整个 body 传进去。

### 7.2 DCS 的可用区参数名是 `az_codes`

写成 `available_zones` 会报 `DCS.4042 This AZ does not exist`——
**报错说可用区不存在，其实是字段名错**，换哪个可用区都一样报。

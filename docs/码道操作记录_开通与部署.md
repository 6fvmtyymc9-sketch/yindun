| 步骤 | 命令 / 动作 | 结果 |
|---|---|---|
| 建库建表 | `mysql < sql/schema.sql`（需先去掉开头 `CREATE DATABASE` / `USE`，见下方注 1） | |
| **event 迁移（必须）** | `mysql < sql/migrate_20261111_event.sql`，`Db.js` 依赖它加的 `call_id` / `kind` | |
| 导旧数据 | `mysqldump --single-transaction --no-tablespaces --no-create-info` | |
| 导入并逐表对数 | `COUNT(*)`：alert / report / drill / event / user / known | |
| 建 `yindun` 库账号 | `CREATE USER 'yindun'@'%'` + 只授权 `yindun.*` | |
| 改 `.env` | `RDS_HOST` / `RDS_USER=yindun` / `RDS_PASS` / `REDIS_URL` / `TZ=Asia/Shanghai` | |
| 重启并验证 | `ss -tnp` 见真实 ESTAB；外网冒烟；`statsAll` 不变 | |
| 停卸自装服务 | 先改 systemd 单元去掉 `Wants=mysql/redis`，再 `systemctl disable --now` | |

**注 1**：仓库路径是 `cloud/sql/schema.sql`，部署机上是 `/opt/yindun/sql/schema.sql`
（`install.sh` 把 `cloud/` 下的内容同步到 `/opt/yindun/` 根）。照抄仓库路径会在服务器上 `No such file`。

**注 2**：`RDS_CA` 这个键在 `.env.example` 里有（`RDS_DB=yindun`），但 `cloud/src/server.js` 的
`createPool` **完全没有读它**，是历史遗留占位。填不填都不影响连接，别把它当有效配置写进材料。

## 七、已知的两个坑（实测，不是推测）

### 7.1 `--password` 与 KooCLI 系统参数同名

RDS 和 DCS 的创建接口都有 `password` 参数，KooCLI 自己也有一个系统参数叫 `password`。
直接写 `--password=xxx` 会立刻退出：

```
目标API中存在与KooCLI系统参数password同名的参数,无法识别--password的位置.
```

**解法**：用 `--cli-jsonInput=<file>` 把整个 body 传进去。

### 7.2 DCS 的可用区参数名是 `az_codes`

写成 `available_zones` 会报 `DCS.4042 This AZ does not exist`——
**报错说可用区不存在，其实是字段名错**，换哪个可用区都一样报。

## 一、`stats` 的口径我说错了，你照抄进去了

你 v2 第 2 条写：

> `health` 里 `stats:{alerts,reports}` 是**推送统计口径**，不是总条数

**这句是我 11-19 上午说的，是错的，我已经更正。** 真实情况看 `Db.js:426`：

```js
const [[al]] = await this.pool.execute(
  `SELECT COUNT(*) AS n FROM yd_alert WHERE elder_id=?`, [elderId]);
```

它就是 `COUNT(*)`，只是**加了 `WHERE elder_id='demo'`** —— 只统计 `demo` 这一个老人，
不是「推送统计」，也不是「Redis 缓存延迟」。

**你自己的基线文件正好把这个证明出来了**：

```
SQL:      alerts 1581   reports 1219
health:   alerts 1520   reports 1219
          ↑ 1581 − 1520 = 61 = 非 demo 的告警条数
```

`reports` 两个口径相等，因为 1225 条上报**全部**是 `demo`；`alerts` 差 61，因为历史上有
61 条其它 `elder_id` 的告警。全部对得上，跟缓存没有任何关系。

**正确的说法**（答辩和截图都写这句）：

> `/api/health` 的 `stats` 是 `WHERE elder_id='demo'` 的计数；
> 核对总数一律用不带 `WHERE` 的 `SELECT COUNT(*)`。

# 请审查一段 Android + Node.js 的判定链路（只出意见，不要改代码）

## 一、这是什么

「银盾」是一个面向独居老人的反诈 App，双端一云：

- **老人端**：Android 原生（纯 Java 手写 View，无 XML 布局），包名 `com.yindun.guard`
- **子女端**：另一个独立安装的 Android App，通过 SSE 长连接收预警
- **云端**：Node 18 + Express，部署在华为云 ECS

老人端的判定是**三层串联 + 只升不降**：

```
第一层 本地规则（离线，217 条诈骗特征词 + 33 条反例，加权打分，五级）
          ↓ 分数落在"没到 warn"的区域
第二层 端侧小模型 TinyBERT-4L（离线，44MB MindSpore Lite，输出可疑概率）
          ↓ 仍然没到 warn，且满足门限
第三层 云端大模型（DeepSeek，走华为云 MaaS）复审
```

**产品上的硬约束（这是本次审查最关心的东西）：**

1. **宁可多报，不可错放。** 模型说"不是诈骗"时，绝不撤回本地已经报出的警报。
2. **「认识」不能关防护。** 老人在弹卡上点"我认识这个人"，只代表"这一次我认了"，
   绝不能换来一段时间的免打扰窗口——以前有这个窗口，骗子 15 分钟足够把话说完。
3. **误报的代价与漏报不对称。** 误报一次，老人会认为这软件爱冤枉人，然后卸载；
   漏报一次，钱就没了。但目前的设计选的是"宁可多报"，所以误报率必须被压住，
   不能靠"多报没关系"糊过去。

### A1. 金标尺：本地规则打分（App 端）

`Judge.java` 第 324~493 行 + 第 170~178 行　—— 问题 1、2、9：误报和漏报的源头都在这

```java
    public Result judgeSms(String body, String who, boolean isCode) {
        Result r = new Result();
        if (!loaded) {
            r.stage = "S0";
            r.level = "none";
            r.why = "规则未加载：" + loadError;
            return r;
        }
        if (body == null) body = "";
        String text = body.toLowerCase();

        // ---------- 1. 逐词打分 ----------
        int score = 0;
        StringBuilder hits = new StringBuilder();

        // 【2026-11-17 修】同一个说法只能算一次。
        // 词表里"我是警察"(+30) 与"警察"(+20)、"点击链接"(+20) 与"点击"(+8)、
        // "不要告诉子女"(+45) 与"不要告诉"(+25) 都是包含关系 ——
        // 一条"我是警察，你别告诉子女"会被算成 120 分，其实只有两个意思。
        // 分数虚高比漏报更危险：它会把这个阈值上的每一条判定都变得不可信，
        // 而且真机实测过"请及时取件"靠模型分堆到 94% 那种事故。
        // 所以先收集命中词，被更长的命中词吞掉的短词不再计分（取最具体的那个说法）。
        List<Word> hitList = new ArrayList<Word>();
        for (Word w : words) {
            // 已经是"验证码短信"时，「验证码」这个词必然出现，第 4 步会按发送方单独处理，
            // 词库不再重复计分 —— 否则银行正常验证码短信会被 "验证码+S4" 直接推到盖屏。
            if (isCode && "验证码".equals(w.text)) continue;
            if (text.contains(w.text.toLowerCase())) hitList.add(w);
        }

        // 2026-11-04 新增：一边打分一边记下"命中的最高阶段词"。
        // 阶段判定已从"总分落桶"改为"最高命中阶段词"——分数衡量可疑度，
        // 阶段问的是"骗子走到第几步"，两件事必须分开算。
        String topStage = "S0";
        int topRank = 0;
        for (Word w : hitList) {
            if (swallowedByLonger(w, hitList)) continue;
            score += w.weight;
            if (hits.length() > 0) hits.append("、");
            hits.append(w.text).append("(+").append(w.weight).append(")");
            if (w.stage != null && w.weight > 0) {
                int rk = stageRankOf(w.stage);
                if (rk > topRank) {
                    topRank = rk;
                    topStage = w.stage;
                }
            }
        }

        // ---------- 2. 反例扣分 ----------
        for (Word w : negatives) {
            if (text.contains(w.text.toLowerCase())) {
                score += w.weight;      // weight 是负数
                if (hits.length() > 0) hits.append("、");
                hits.append(w.text).append("(").append(w.weight).append(")");
            }
        }

        // ---------- 3. 号码身份加权 ----------
        // 同样的内容，陌生人发的比服务号发的危险。
        // 这一步不写在 rules.json 里，因为它不是"词"，是"身份"。
        if ("stranger".equals(who)) {
            score += 15;
            if (hits.length() > 0) hits.append("、");
            hits.append("陌生号码(+15)");
        } else if ("contact".equals(who) && score > 0) {
            // 通讯录里的号码 = 已知熟人，给 −20 基础信任分。
            // 「妈，把身份证号发给我，我帮你订票」这类家常请求和套信息句式高度相似，
            // 光靠词库分不开，只能用身份分兜底。只在本来就有可疑分时才打折，避免负数脏数据。
            score -= 20;
            if (hits.length() > 0) hits.append("、");
            hits.append("通讯录号码(-20)");
        }
        // ---------- 3.5 链接特征 ----------
        // 【为什么单独立一条，不写进词库】
        //   钓鱼短信的核心动作是"让你点一个链接"。域名每天换、短链天天新，
        //   词库永远穷举不完。所以这里认的是"形式"而不是"内容"：
        //   只要正文里出现一个可点的网址，不管它长得像不像官方，都算钓鱼入口。
        //
        // 【为什么不联网核验"这域名是不是真的工商银行"】
        //   短信到达的那一秒来不及查，而且离线也必须能判。
        //   我们只回答一个问题：这条短信在催你点链接吗？是，就加分。
        //
        // 【2026-11-09 加】实测：'您的ETC已停用，请点击 t.cn/Etc9 认证'
        //   词库只给 55 分，因为骗子故意避开'点击链接'四个字。补上形式特征才抓得住。
        Matcher um = URL_PATTERN.matcher(body);
        if (um.find()) {
            score += 20;
            if (hits.length() > 0) hits.append("、");
            hits.append("含链接(+20)");
            if (stageRankOf("S2") > topRank) {
                topRank = 2;
                topStage = "S2";
            }
        }

        // 验证码短信要按"谁发的"区别对待：
        //   服务号（95588、银行、平台）发验证码 = 正常业务，不加分
        //   陌生号码发验证码 = 极不正常，重罚
        //
        // 为什么这么判：验证码的正常来源只有服务号。陌生人给你发"验证码"，
        // 只可能是钓鱼（让你点链接、或者冒充客服要你念出来）。
        if (isCode) {
            if ("service".equals(who)) {
                if (hits.length() > 0) hits.append("、");
                hits.append("服务号验证码(+0)");
            } else {
                // v3.4：+30 → +45，与云端 Judge.js 一致
                score += 45;
                if (hits.length() > 0) hits.append("、");
                hits.append("非服务号发验证码(+45)");
                // 与云端 Judge.js 对齐：这个信号在 JS 里是 tag:'S4'，这边也要参与定阶段
                if (stageRankOf("S4") > topRank) {
                    topRank = 4;
                    topStage = "S4";
                }
            }
        }
```

```java
    /** 累计结果 */
    public static class Verdict {
        /** 窗口内这个号码一共发了几条（含本条） */
        public int count = 1;
        /** 各条「实质分」之和。实质分 = 单条总分扣掉陌生号码那个 +15，避免重复白送 */
        public int sum = 0;
        /** 连发加成 */
        public int bonus = 0;
        /** 各条里最高的阶段序号 0..4，取最高就是「骗子走到的最远那一步」 */
        public int topRank = 0;
        /** 是否构成连发（>= MIN_BURST 条） */
        public boolean burst = false;

        /** 合并后这一组短信的分数。base 是号码身份分（陌生 +15） */
        public int pooled(int base) {
            return base + sum + bonus;
        }
    }

    public static synchronized Verdict record(Context ctx, String from,
                                              int substantive, int rank,
                                              String body, long now) {
        Verdict v = new Verdict();
        v.sum = Math.max(0, substantive);
        v.topRank = clampRank(rank);

        // 没有发件号码就不累计：系统推送、运营商通知都长这样，
        // 把它们混在一个桶里，攒到三条就能凭空判成诈骗。
        if (from == null || from.length() == 0) return v;

        final int hash = (body == null) ? 0 : body.hashCode();
        SharedPreferences sp = ctx.getSharedPreferences(PREF, Context.MODE_PRIVATE);

        String key = K + norm(from);
        String raw = sp.getString(key, null);

        int count = 0, sum = 0, topRank = 0, lastHash = 0;
        long first = now, last = 0;

        if (raw != null) {
            String[] p = raw.split(",");
            if (p.length >= 6) {
                try {
                    first = Long.parseLong(p[0]);
                    last = Long.parseLong(p[1]);
                    count = Integer.parseInt(p[2]);
                    sum = Integer.parseInt(p[3]);
                    topRank = Integer.parseInt(p[4]);
                    lastHash = Integer.parseInt(p[5]);
                } catch (NumberFormatException e) {
                    count = 0;
                    sum = 0;
                    topRank = 0;
                }
            }
        }

        // 窗口过期，或者系统时间被往回调过，都从头算
        boolean expired = last > 0 && (now - last > WINDOW_MS || now < last);
        if (expired) {
            count = 0;
            sum = 0;
            topRank = 0;
            lastHash = 0;
            first = now;
        }

        // 同一条短信重复广播：不计数、不改分，原样返回
        if (count > 0 && last > 0 && (now - last) < DUP_MS && hash == lastHash) {
            v.count = count;
            v.sum = sum;
            v.topRank = topRank;
            v.bonus = bonusOf(count);
            v.burst = count >= MIN_BURST;
            return v;
        }

        count += 1;
        sum += Math.max(0, substantive);
        if (clampRank(rank) > topRank) topRank = clampRank(rank);

        v.count = count;
        v.sum = sum;
        v.topRank = topRank;
        v.bonus = bonusOf(count);
        v.burst = count >= MIN_BURST;

        sp.edit()
                .putString(key, first + "," + now + "," + count + "," + sum + "," + topRank + "," + hash)
                .apply();

        prune(sp, key, now);

        android.util.Log.i(TAG, "短信累计 " + norm(from) + " 第 " + count + " 条，"
                + "实质分和=" + sum + " 加成=" + v.bonus + " 构成连发=" + v.burst);
        return v;
    }

    private static int bonusOf(int count) {
        return count >= MIN_BURST ? (count - MIN_BURST + 1) * PER_EXTRA : 0;
    }
```

```javascript
    }
    for (const k of matched) {
      const swallowed = matched.some(o =>
        o !== k && o.word.length > k.word.length && o.word.includes(k.word));
      if (swallowed) continue;
      score += k.weight;
      hits.push({ word: k.word, weight: k.weight, tag: k.tag });
    }

    // ---------- 2. 反例词减分（压低误报的关键） ----------
    for (const k of this.negatives) {
      if (text.includes(k.word)) {
        score += k.weight; // weight 本身是负数
        hits.push({ word: k.word, weight: k.weight, tag: null });
      }
    }

    // ---------- 3. 号码身份加权 ----------
    // 同样的内容，陌生人发的比服务号发的危险。这是"身份"不是"词"，所以不写在 rules.json 里。
    if (who === 'stranger') {
      score += 15;
      hits.push({ word: '陌生号码', weight: 15, tag: null });
    } else if (who === 'contact') {
      // 通讯录里的号码 = 已知熟人。给 −20 的基础信任分（比陌生号的 +15 更重），
      // 因为「妈，把身份证号发给我，我帮你订票」这类家常请求本身句式和套信息高度相似，
      // 光靠词库分不开，只能用身份分兜底。实测这条原来被判 S3/high。
      // 只在"本来就有可疑分"时才打折，否则无命中短信会被扣成负数，脏了展示用的分数。
      if (score > 0) {
        score -= 20;
        hits.push({ word: '通讯录号码', weight: -20, tag: null });
      }
    }

    // ---------- 3.5 链接特征（与 App 端 Judge.java 逐行对齐） ----------
    // 钓鱼短信的核心动作是"让你点一个链接"。域名每天换、短链天天新，词库穷举不完，
    // 所以这里认的是"形式"而不是"内容"：正文里出现可点的网址就算钓鱼入口。
    // 实测：'您的ETC已停用，请点击 t.cn/Etc9 认证' 只给 55 分，
    // 因为骗子故意避开'点击链接'四个字 —— 补上形式特征才抓得住。
    if (URL_PATTERN.test(text)) {
      score += 20;
      hits.push({ word: '含链接', weight: 20, tag: 'S2' });
    }

    // ---------- 4. 验证码按发送方区别对待 ----------
    // 这条是实测踩出来的坑：原来统一 +10，导致银行正常验证码被判成预警。
    // 老人一天收三条验证码，每条都报警，子女三天就卸载了。
    if (isCode) {
      if (who === 'service') {
        hits.push({ word: '服务号验证码(+0)', weight: 0, tag: null });
      } else {
        score += 30;
        hits.push({ word: '非服务号发验证码', weight: 30, tag: 'S4' });
      }
    }

    // ---------- 5. 官方宣传短信免打扰 ----------
    // 放在最后：先把分数和命中算全（留档给子女端看原因），再整体降级为 S0。
    const noticeWhy = this.noticeOf(text, who);
    if (noticeWhy) {
      return {
        score,
        hits,
        stage: 'S0',
        stageName: (this.stages.S0 || {}).name || '',
        level: 'none',
        exempt: 'publicity',
        why: `${noticeWhy}，判为官方宣传短信，不打扰`,
      };
    }

    const stage = this.stageOf(score, hits);
    let level = this.levelOf(score, stage);

    // 通讯录里的号码最多"提醒"，不盖屏 —— 除非已经明确走到要钱(S4)。
    // 老人手机里 80% 的短信来自家人，任何一条家常短信盖屏都会让产品被卸载。
    if (who === 'contact' && stage !== 'S4' && rank(level) > rank('watch')) {
      level = 'watch';
    }

    return {
      score,
      hits,
      stage,
      stageName: (this.stages[stage] || {}).name || '',
      level,
      why: hits.length
        ? hits.map(h => `${h.word}(${h.weight > 0 ? '+' : ''}${h.weight})`).join(' + ')
        : '无命中',
    };
  }
```

### B2. 云端级别映射

`Judge.js` 第 290~342 行　—— 问题 2 的后半：分数到级别的阈值

```javascript
  /**
   * 风险等级：产品行为的开关（盖不盖屏 / 推不推送 / 打不打电话 / 要不要调模型做摘要）
   *
   * 【2026-11-04 修正】原来纯按分数落桶，结果和阶段倒挂：
   *   A 线 30 条里 5 条"要钱"短信没有一条盖屏（3 条 warn、2 条 high），
   *   反倒 2 条"只是吓唬"的盖了屏。根因还是同一个——
   *   分数衡量"这条短信有多可疑"，不衡量"骗子走到哪一步"。
   *
   * 新规则：等级跟着阶段走。分数只在 S3 上做一次加严判断，
   * 因为"隔离"是本产品的核心观测点（老人答应不告诉家人之后，就没人能拦住）。
   *
   *   S4 要钱    → block  一律盖屏，骗子开始动钱没有商量余地
   *   S3 隔离    → 分数够高就 block，否则 high（最该介入，但不必每条都盖屏）
   *   S2 吓唬    → warn
   *   S1 套近乎  → watch
   *   S0         → none
   *
   * @param {number} score 总分
   * @param {string} stage 阶段。缺省时退回旧的分数落桶逻辑。
   */
  levelOf(score, stage) {
    const L = this.levels;
    // 兼容：没有阶段信息时仍按分数落桶
    if (!stage) {
      if (score >= L.block) return 'block';
      if (score >= L.high) return 'high';
      if (score >= L.warn) return 'warn';
      if (score >= L.watch) return 'watch';
      return 'none';
    }
    switch (stage) {
      case 'S4': return 'block';
      case 'S3': return score >= (L.high || 70) ? 'block' : 'high';
      // v3.4：同一阶段里信号叠得多，也要升级 —— 只按阶段定级会让
      //   "涉嫌洗钱+配合调查+公安局"（100 分、还在吓唬阶段）只得到一个普通提醒，
      //   "换手机号+猜猜我是谁+有急事"（多个弱信号）完全不提醒。
      case 'S2': return score >= (L.high || 70) ? 'high' : 'warn';
      case 'S1': return score >= (L.warn || 45) ? 'warn' : 'watch';
      default: return 'none';
    }
  }
```

### B4. 云端风险概率接口

```javascript
  /**
   * 一键上传：可疑短信（文字或截图）→ 结构化研判结论。
   * 这是"上传 / 识别 / 查询结论"三个核心 API 里的"识别"。

   * @param {{text?:string, imageBase64?:string, mime?:string}} input
   * @returns {Promise<null|{isFraud,stage,stageName,type,reason,advice,signals}>}

    if (!text && !imageBase64) return null;

    const sys = [
      '你是反电信诈骗研判器，服务中国老年用户及其子女。',
      '输入可能是一条短信的文字，也可能是一张短信截图（需要你自己看图）。',

    ].join('\n');

        { maxTokens: 400, temperature: 0.1 }

      if (!m) return null;

      const stage = Math.max(0, Math.min(4, Number(o.stage) || 0));

      return null;
    }
  }
```

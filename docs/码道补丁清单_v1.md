## 第 1 组：现有 5 个步骤的文案修正（5 处）

### 1.1 子女端第 1 张卡（`go(1)` 里的 `addNoti`）

**现在：**
```
addNoti('l1','父亲接听陌生来电','+1 202 555 0137 · 不在通讯录，已自动标记关注。');
```

**改成：**
```
addNoti('l1','父亲接听陌生来电','+1 202 555 0137 · 不在通讯录，已开始关注。');
```

原因：原来写"已自动标记关注"，语义别扭；而且绝不能说"无关"或"可疑"，此时只应陈述事实。

### 1.2 左屏浅色提示（步骤 2 的 `hintEl`）

保持现在的位置和样式，只把文字改成：

```
这个号码不在你通讯录里
```

下面加一行更小的字：

```
你认识就点「认识」，不点也没关系
```

原因：老人端不能出现"风险""可疑"这类判断词，她不信软件，她只信事实。

### 1.3 子女端第 4 张卡去掉重复的回拨提示（`go(4)`）

**现在：**
```
addNoti('l5','⚠️ 父亲正在操作手机银行','通话中切换至银行 APP，高度疑似转账诈骗，已触发阻断。','已自动回拨，接通中');

**改成（去掉第 4 个参数）：**

addNoti('l5','⚠️ 父亲正在操作手机银行','通话中打开银行 APP，已盖住屏幕。','');

**改成：**

```

### 1.5 左屏红屏（`blockEl`）里那行小字

**现在：**
```
系统检测到您正在通话中操作手机银行
这符合电信诈骗的典型特征
```

**改成：**
```
你正在边打电话边转钱
```

原因有三：
- 原来的字太小，老人看不清
- "这符合电信诈骗的典型特征"是**辩解**，不是**提醒**，老人这时候听不进术语
- 骗子正在耳朵里说话，我们只有一句话的机会，必须最短、最直白

这行字**字号要放大到现在的 1.4 倍**，并且居中。

## 第 2 组：新增「陌生号码但是熟人」弹层（最重要）

### 场景

陌生人打电话来，但可能真是熟人（老同事换号、亲戚换号）。**不能让老人觉得这软件冤枉人，也不能让她自己关掉防护。**

### 2.1 触发时机

在**步骤 1 之后 2 秒**自动弹出（模拟来电后系统询问），也可以作为第 6 个按钮手动触发。

### 2.2 弹层长什么样

盖住左屏（老人端）**下半屏**，不是顶部一行小字：

```
┌──────────────────────────────┐
│                              │
│   这个号码不在通讯录里        │
│                              │
│     是你认识的人吗？          │
│                              │
│    ┌────────┐  ┌────────┐    │
│    │  认识   │  │ 不认识  │    │
│    └────────┘  └────────┘    │
│                              │
└──────────────────────────────┘
```

### 2.3 四个硬要求（违反任一条算做错）

1. **挡住半屏**，不是一行字。字号要比老人端其他文字大。
2. **两个按钮完全一样大、一样颜色、一样字号。** 绝不能把"认识"做得更显眼——那等于帮她做决定。
3. **不点就不消失。** 没有关闭手势，没有点遮罩关闭，没有 × 按钮。
4. 点"认识"→ 弹层消失，左屏顶部出现一行小字：`已记录：你认识这个号码（15 分钟内不再询问）`

### 2.4 【铁律】点"认识"绝对不能关掉防护

这是全项目最重要的设计约束，必须严格遵守：

**点"认识"之后：**
- ✅ 老人端不再弹这个询问（15 分钟内）
- ✅ 子女端**照样收每一条预警卡，一条不少**
- ✅ 之后打开银行 App，**红屏照样盖上来，一样拦**
- ❌ **绝对不许出现**「因为点了认识，所以不显示红屏」这种逻辑

**判断标准**：在代码里搜 `known` 或 `acquaint` 这类变量，如果它出现在红屏的显示条件里，就是做错了。

### 2.5 子女端对应的一张卡

点"认识"之后，子女端推送一张卡：

```
标题：父亲说这个陌生号码是熟人
正文：138****6621 · 通话 3 分钟 · 他点了「是认识的」
      —— 但仍请您确认一下
```

加上 `extra` 那一行时**不要写"已自动回拨"**，此时还没到阻断级。

## 第 3 组：新增「正常转账不拦」的反例按钮

### 场景

老人给自己交水电费，或者跟儿子打着电话转账。**如果这也拦，老人会觉得被冤枉，然后卸载 App。**

### 3.1 顶部控制条追加两个按钮

在第 5 个按钮之后、重置之前，插入：

```
<button class="btn" data-step="g1"><span class="n">A</span>反例：独自转账</button>
<button class="btn" data-step="g2"><span class="n">B</span>反例：和儿子通话中转账</button>
```

### 3.2 点击后的行为

**A：独自转账（没有通话）**
- 左屏出现一条浅色事件：`有人在用手机银行`（不是红色，是灰色或淡蓝）
- 左屏**不盖屏**，什么都不拦
- 子女端**不推送任何卡**
- 页面底部弹一行灰色小字（3 秒后消失）：`无通话 + 打开银行 → 不触发。正常人也会自己转账。`

**B：和儿子通话中转账**
- 左屏通话状态显示：`儿子（通讯录）· 通话中`
- 左屏出现事件：`有人在用手机银行`
- 左屏**不盖屏**
- 子女端**不推送任何卡**
- 底部弹一行灰色小字：`联系人 + 打开银行 → 不触发。号码在通讯录里。`

### 3.3 为什么必须有这两条

评委一定会问：**"你们是不是只要有人打开银行就报警？那老人正常转账怎么办？"**

这两颗按钮就是当场给出的答案：**只有"陌生号码通话中"和"打开银行"同时成立才拦。** 两个条件叠加，误报几乎消失。

事件要用**灰色/淡色**，不能用红色。这两条是"不报警"的证明，视觉上必须是安静的。

## 第 4 组：红屏加「按住 3 秒放行」

### 4.1 位置

红屏（`blockEl`）里，在「打给女儿」按钮下方，加一行提示文字和一个不太显眼的按钮：

```
[小字] 如果你确定没问题
[次要按钮，描边样式] 我知道自己在做什么（按住 3 秒）
```

### 4.2 行为

- 必须**按住 3 秒并显示进度**（圆环或填充条），松手就重置
- 3 秒满了才放行，红屏消失
- 放行后**子女端仍然收到一张卡**：
  ```
  标题：父亲自己解除了拦截
  正文：他按住了 3 秒确认。如果您不放心，建议打个电话。
  ```

### 4.3 为什么是"按住 3 秒"

骗子可以教老人"点一下那个按钮"。但**按住 3 秒不停手，这个指令很难在电话里说清楚**——而且老人一边被催、一边要看准进程条，基本做不到。

**我们不是在跟骗子的技术斗，是在跟他的话术成本斗。**

### 4.4 铁律

放行 ≠ 放弃监护。放行之后：子女照收通知，后续如果又出现开银行/验证码，**照样再次盖屏**。

## 附：这个产品的一句话立论（改的时候别偏离）

> 老人被骗时，骗子会说"别告诉家里人"。我们没法听他说什么，
> 但**钱动的时候手机自己会说话**——打开银行、验证码到手，这些动作藏不住。
> 所以我们的产品不是"监听通话"，而是**在钱动的那一刻，让女儿的声音先到。**

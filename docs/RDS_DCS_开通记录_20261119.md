## 三、DCS（Redis 6.0 单机 1G）

| 项 | 值 |
|---|---|
| 接口 | `POST https://dcs.cn-north-4.myhuaweicloud.com/v2/{project_id}/instances` |
| 实例名 | `yindun-redis-1119` |
| 实例 ID | `fc5524c5-ca55-4ca7-a1fd-bd39e3282a69` |
| 规格 | `redis.single.xu1.large.1`（1G，0.29 元/时） |
| 内网地址 | `192.168.0.138:6379`，密码鉴权 |
| 返回 | HTTP 200，`status=CREATING` → 约 2 分钟 `RUNNING` |

**踩坑 2（这次真正的坑）**：DCS v2 的可用区参数名是 **`az_codes`**，不是 `available_zones`。
传 `available_zones: ["cn-north-4a"]` 会报 `HTTP 400 DCS.4042 This AZ does not exist`——
**报错说"可用区不存在"，其实可用区没问题，是字段名不对**，换 4a/4b/4c/4g 全一样报错。
改成 `"az_codes": ["cn-north-4a"]` 立刻 200。

**踩坑 3**：`GET /v2/{project_id}/flavors` 返回 944 条规格，但**没有 `product_id` 字段，`az_codes` 也全是空数组**；
`GET /v2/{project_id}/products` 直接 404（`APIGW.0101`）。所以"先查 product_id 再创建"这条路走不通，
**创建时不要传 `product_id`，服务端自己匹配**。

**连通性实测（同一安全组内）**：
```
redis-cli -h 192.168.0.138 -a *** ping        → PONG
set/get/del                                   → OK / ok / 1
--latency                                     → 0.45 ms
```

## 五、两条给材料的提醒

1. **`health.storage.rds=true` 不等于"上了云数据库"**。切之前 `.env` 里 `RDS_HOST=127.0.0.1`，
   连的是 ECS 本机 MySQL，这个字段只代表"连得上"。要证明真的用了 RDS，得给**实例 ID + 内网地址 + 迁移前后对数**，
   本文第二节那几张表就是干这个用的。
2. **费用**：RDS 0.40 元/时 + Redis 0.29 元/时 ≈ **0.69 元/时**。做完演示就删实例，
   按 4 小时算不到 3 元。别放着过夜。

## 六、KooCLI 接线实测（2026-11-19 20:05，为包 C 做准备时发现）

包 C 要甲用码道 Skills 开通，前提是 KooCLI 能跑。实测出三个必须知道的东西。

### 6.1 `--password` 与 KooCLI 系统参数同名，命令行走不通

RDS 和 DCS 的创建接口都有 `password` 参数，而 KooCLI 自己也有一个系统参数叫 `password`。
直接写 `--password=xxx` 会立刻退出：

```
目标API中存在与KooCLI系统参数password同名的参数,无法识别--password的位置.
请确认该参数为:KooCLI系统参数(a);目标API参数(b);兼为两者(c):
```

**解法：用 `--cli-jsonInput=<file>` 传整个 body**，密码写在 JSON 里就绕开了。
（`huawei-rds` 的 SKILL.md 也记了这条，并说明 `printf "b\n"` 那个管道绕法在 7.2.12+ 已失效。）

### 6.2 两份 CreateInstance 的 JSON 结构已用「非法名探测」验证

把 `name` 故意写成 `"1"`（不满足 4~64 位、字母开头），让服务端先报名字错——
**错误落在名字上，就说明其余参数（VPC/子网/安全组/规格/可用区/密码/计费）全部被正确解析了**。
且名字非法会被直接拒绝，**不会真的创建实例、不产生费用**。

| 服务 | 实测返回 |
|---|---|
| RDS | `{"error_msg":"Invalid instance name length.","error_code":"DBS.280649"}` |
| DCS | `{"error_msg":"Invalid DCS instance name...","error_code":"DCS.4010"}` |

两份可直接用的 JSON 见 `docs/包C_给甲_码道开通RDS与DCS.md` 附录 A / B。

### 6.3 三个参数名细节

| 项 | 正确写法 | 错误写法会怎样 |
|---|---|---|
| DCS 可用区 | `--az_codes.1=cn-north-4a` | 写成 `available_zones` → `DCS.4042 This AZ does not exist`（**报错说可用区不存在，其实是字段名错**，换哪个区都一样） |
| RDS 区域 | body 里 `"region"` 与 `--cli-region` 必须同为 `cn-north-4` | 缺 body 的 region → `DBS.280243` |
| RDS 单机 | JSON 里 `"ha": {"mode": "single"}` | 不传会按默认走 |

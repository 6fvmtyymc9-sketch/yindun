# 银盾改造方案：去掉 DeepSeek、SFT 做核心、补齐赛题硬性要求

> 写于 2026-11-18，给开发同学照着改。每一步都写了**改哪里、怎么改、怎么算做完**。
> 前一个阶段的验收没过，不要开始依赖它的下一个阶段。
> 行号以 `cf09550`（融合规则改为需要附和）为准，代码变了以函数名为准。

---

## 〇、为什么要改

1. **判定要靠我们自己的模型，不能只是调 API。** 现在通话复盘的结论由 DeepSeek 决定（`CallAudio.js` 中只要 `ai` 存在，`stage = ai.stage`），
   这在答辩时含金量不高。改完后，产品里**不再有任何大模型 API 调用**，判定只靠三样东西：
   规则、端侧 TinyBERT、我们部署并微调的 AntiFraud-SFT。
2. **SFT 是核心。** 通话录音经 ASR 转成文字后，统一交给 SFT 判定。SFT 跑在学校 GPU 上，华为云业务服务器通过隧道调用它。
3. **赛题有两条硬性要求还没满足**（`docs/赛题符合性自查.md` 第 31、32 行已记录）：
   - 要用 CodeArts 智能体 + Skills **开通 RDS、Redis 等华为云服务**。现在的 MySQL 和 Redis 是在 ECS 上用 apt 自己装的，不算。
   - 要用 CodeArts 智能体 + Skills **部署到华为云**。现在是手工 scp + systemd。

**不是硬性要求的**：MaaS 和大模型（赛事只是说代金券「可以」买）。所以去掉 DeepSeek 不违反任何规则。

## 一、改完之后的架构

```
┌─────────────── 老人手机（离线也能用，这一层不变）────────────────┐
│  规则 rules.json  +  端侧 TinyBERT（MindSpore Lite，45 MB）        │
└───────────────┬──────────────────────────────────────────────────┘
                │ 拿不准的短信 / 通话录音 / 上报截图
                ▼
┌─────────────── 华为云 ECS（业务，配置低也够）──────────────────────┐
│  Node 服务  ── RDS for MySQL ── DCS Redis   ← CodeArts + Skills 开通 │
│     │  录音 → 华为云 SIS 转文字                                       │
│     │  截图 → 华为云 OCR 转文字（新增）                               │
│     │  文字 → http://127.0.0.1:8099/risk                              │
│     ▼                         ▲                                      │
│  融合：规则阶段 + SFT 得分     │ 反向 SSH 隧道（由学校这边主动连出来）│
│  类型 / 证据 / 话术：模板      │                                      │
└───────────────────────────────┼──────────────────────────────────────┘
                                │
┌─────────────── 学校 GPU 容器（L40，仅校园网内）──────────────────────┐
│  sft_server.py：AntiFraud-SFT + 我们的 LoRA，监听 127.0.0.1:8000      │
└──────────────────────────────────────────────────────────────────────┘
```

**为什么用反向隧道：** 华为云访问不到学校内网（10.8.110.x），但学校容器可以访问外网。
所以让学校容器**主动**连到 ECS，把自己的 8000 端口「映射」成 ECS 上的 `127.0.0.1:8099`。
对 ECS 上的 Node 来说，SFT 就像跑在本机一样，`cloud/src/Sft.js` 一行都不用改。

**学校容器不在线时**：`Sft.js` 调用失败或超时（`SFT_WAIT_MS=8000`）后返回 `null`，
自动降级为「规则 + 端侧 TinyBERT」。功能照常，只是效果变差。现有代码已经支持这条降级路径。

## 二、阶段 A：打通「华为云 → 学校 SFT」（约 1 天）

### A1. 先确认学校能连到 ECS

在学校容器里执行（SSH 登录方法见 [GPU 容器 SSH 使用说明](GPU容器SSH使用说明.md)）：

```bash
timeout 5 bash -c '</dev/tcp/123.249.25.139/22' && echo 22端口通 || echo 22端口不通
```

- 通：继续 A2
- 不通：在 ECS 的 `/etc/ssh/sshd_config` 里加一行 `Port 443`（保留 `Port 22`），然后执行 `systemctl restart ssh`，
  在安全组里放开 443，再测一次 443。下面命令里的 `-p 22` 相应改成 `-p 443`

✅ 已确认（2026-11-18）：学校允许容器向外建立这种出站长连接。

### A2. ECS 上建一个只能做端口转发的账号

```bash
# 在 ECS 上，root 执行
useradd -m -s /usr/sbin/nologin tunnel
mkdir -p /home/tunnel/.ssh && chmod 700 /home/tunnel/.ssh
touch /home/tunnel/.ssh/authorized_keys && chmod 600 /home/tunnel/.ssh/authorized_keys
chown -R tunnel:tunnel /home/tunnel/.ssh
```

### A3. 学校容器生成隧道专用密钥，把公钥登记到 ECS

```bash
# 学校容器里
ssh-keygen -t ed25519 -N '' -f ~/.ssh/tunnel_ed25519 -C school-gpu-tunnel
cat ~/.ssh/tunnel_ed25519.pub
```

把输出的那一行加到 ECS 的 `/home/tunnel/.ssh/authorized_keys`，**前面加上限制选项**，整行写成：

```
restrict,port-forwarding,permitlisten="127.0.0.1:8099" ssh-ed25519 AAAA...（公钥） school-gpu-tunnel
```

这样这把钥匙**只能**在 ECS 的 `127.0.0.1:8099` 上开一个转发：不能登录 shell，也不能监听其他端口，更不能对公网开放。
（`permitlisten` 需要 OpenSSH 7.8 及以上，Ubuntu 22.04 自带 8.9。）

### A4. SFT 服务只在容器本机监听

现在服务是用 `--host 0.0.0.0` 启动的，校园网里谁都能访问。改成只在本机监听（`sft_server.py` 的默认值本来就是 `127.0.0.1`）：

```bash
pkill -f sft_server.py
cd ~/yindun && SFT_DEVICE=cuda ANTIFRAUD_DIR=$HOME/models/JimmyMa99/AntiFraud-SFT \
  nohup python3 tools/sft_server.py --host 127.0.0.1 --port 8000 > ~/sft.log 2>&1 &
```

以后同学想在自己电脑上测试，用 SSH 端口转发：`ssh -p 43998 -L 8000:127.0.0.1:8000 zkpk@10.8.110.32`，
然后访问本机的 `http://127.0.0.1:8000`。

### A5. 启动隧道并保活

容器里没有 autossh，用一个循环脚本代替。新建 `tools/sft_tunnel.sh` 并提交到仓库：

```bash
#!/usr/bin/env bash
# 学校容器 → ECS 反向隧道：把本机 8000 映射成 ECS 的 127.0.0.1:8099
ECS_HOST=${ECS_HOST:-123.249.25.139}
ECS_PORT=${ECS_PORT:-22}
while true; do
  ssh -N -p "$ECS_PORT" -i ~/.ssh/tunnel_ed25519 \
      -o ServerAliveInterval=15 -o ServerAliveCountMax=3 \
      -o ExitOnForwardFailure=yes -o StrictHostKeyChecking=accept-new \
      -R 127.0.0.1:8099:127.0.0.1:8000 tunnel@"$ECS_HOST"
  echo "$(date '+%F %T') 隧道断开，5 秒后重连" >&2
  sleep 5
done
```

```bash
nohup bash ~/yindun/tools/sft_tunnel.sh > ~/tunnel.log 2>&1 &
```

### A6. ECS 上接入

`cloud/.env`：

```bash
SFT_URL=http://127.0.0.1:8099
SFT_TIMEOUT=15000
SFT_WAIT_MS=8000
```

执行 `systemctl restart yindun`。

### A7. 容器重建后一键恢复

学校容器一旦「删除实验」，磁盘会被**整个清空**（已实测）。新建 `tools/school_gpu_setup.sh`，把下面这些事串成一个脚本，以后重建容器只需执行这一个脚本：

1. 起 2222 端口的 SSH 服务（只允许密钥登录，配置写法见《GPU 容器 SSH 使用说明》第五节）
2. `pip install -i https://pypi.tuna.tsinghua.edu.cn/simple 'transformers>=4.45,<4.50' accelerate soundfile 'modelscope<1.30'`
   （**这两个版本上限都必须保留**：新版 modelscope 下载时报 `HubConfig._logged_out`；transformers 4.50 以上的参数名和我们的代码不一致）
3. 从 ModelScope 下载 `JimmyMa99/AntiFraud-SFT` 到 `~/models`
4. 拉取我们自己的 LoRA 权重（阶段 D 产出，放在 ModelScope 私有仓库）
5. 启动 `sft_server.py`（监听 `127.0.0.1:8000`）
6. 启动 `sft_tunnel.sh`

隧道私钥 `~/.ssh/tunnel_ed25519` **不要提交到仓库**，由管理员保管，重建后手动放回去。

```bash
# 在 ECS 上执行（RDS 只对内网开放）
mysql -h <RDS内网地址> -uyindun -p yindun < cloud/sql/schema.sql
mysql -h <RDS内网地址> -uyindun -p yindun < cloud/sql/migrate_20261111_event.sql   # 必须执行，Db.js 依赖它加的列
# 迁移旧数据
mysqldump -h127.0.0.1 -uyindun -p --no-create-info yindun > /tmp/old.sql
mysql -h <RDS内网地址> -uyindun -p yindun < /tmp/old.sql
```

注意：`schema.sql` 开头有 `CREATE DATABASE` 和 `USE yindun`，如果 RDS 账号没有建库权限，就先在控制台建好库，再把这两行去掉后执行。

`cloud/data/` 目录（`pairs.json` 配对数据、`voice/` 家人语音）**不在数据库里**，原样保留在 ECS 上。

### C5. 改 `.env` 并切换

```bash
RDS_HOST=<RDS内网地址>
RDS_PORT=3306
RDS_USER=yindun
RDS_PASS=<密码>          # 注意是 RDS_PASS，不是 RDS_PASSWORD
RDS_DB=yindun
REDIS_URL=redis://:<密码>@<DCS内网地址>:6379/0
TZ=Asia/Shanghai         # 连接池没有设置 timezone，按进程本地时区存时间，必须和以前一致
```

`systemctl restart yindun`。**改完一定要重启**：`Db.js` 只在启动时检查一次连接，连不上会一直使用内存，不会自动重试。

确认无误后，停掉并卸载 ECS 上自己装的 MySQL 和 Redis（`systemctl disable --now mysql redis-server`），
腾出 2 GB 机器上的内存。

## 七、风险与注意事项

| 风险 | 对策 |
|---|---|

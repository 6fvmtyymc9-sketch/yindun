**跑之前先确认配额**，这一步不能跳：

```bash

# 必须看到 "reportPerDay":3000
# 还是 1200 → 停手，在群里问一句，不要跑
```

再核对两处你自己的东西：**BASE 地址是 `123.249.25.139:8080`（不是 localhost）**、
**1,070 条的输入文件路径对**。

```bash
node <你的脚本> --dry-run --no-cache --limit 50 --concurrency 2
```

看三件事，任何一个不对就先别往下走：

| 看什么 | 正常值 | 不对的话 |
|---|---|---|
| HTTP 429 | **0 条** | 配额没生效，停手 |
| `ok: false` / 超时 | **≤ 1 条** | 贴报错原文给我 |
| 单条耗时 | 1~3 秒 | 超过 8 秒说明服务端在排队，并发要降 |

50 条里如果出现「429 或超时」，**先别跑全量**——全量只会把这个比例放大 20 倍。

## ② 全量 1,070 条

```bash
node <你的脚本> --dry-run --no-cache --concurrency 3
```

- **`--dry-run` 必须有**：判定照走、模型照调，但不落库、不生成预警、不推子女端
- **并发 3，不要 4、更不要 8**。ECS 是 1 核 2G、可用内存 1.2G，并发 4 连续跑 1000 多条
  可能把内存吃到底，表现是**跑到一半 `health` 打不开**——那不是脚本坏了
- **只跑一次**，不要跑第二轮比数

**中途断了怎么办**：别整体重跑。把已完成条数、失败条数、最大 index 发我，我们只补缺的那一段。
（`--no-cache` 意味着重跑会全部重算，白烧时间和配额。）

## ④ 跑完还有一件：把脚本提交进仓库

我翻了仓库，`cloud/test/run.js` **只有 50 行**，只调本地 `Judge.scoreSms`、只认 `.json` 参数——
**它是规则回归测试，不是评估流水线**，没有 `--dry-run`、没有 `--concurrency`、不发网络请求。

也就是说：**能跑出那张表的脚本，只在你机器上，仓库里没有。**
评委 / 老师 clone 下来，只能看到一堆数字，找不到产出这些数字的东西。
「评估可复现」这一条就立不住，报告里那张表的分量会打折。

所以要你提交到 **`cloud/test/eval/`**，四样东西：

```
cloud/test/eval/
├── run.js            # 你改过的评估脚本
├── README.md         # 输入格式、参数说明、怎么复现那张表（一条命令）
├── inputs.jsonl      # 1,070 条的 id + 文本 + label（或只放 id 清单 + 获取方法）
└── results-20261119.json   # 这次跑的原始结果（可以只放前 50 条样例，全量太大就说明存放位置）
```

**两条注意**：
- **脚本里如果有 token / 密钥 / 内网地址，删掉再提交**，改成读环境变量
- **数据本体**（Fraud-R1 那 1,070 条全文）如果体积大，就只提交 id 清单 + 一段复现下载的说明，
  别把几十 MB 数据塞进仓库

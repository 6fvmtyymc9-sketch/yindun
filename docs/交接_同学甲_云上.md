## 三、第一阶段：写部署脚本（今天就能开始，不等任何人）

这块**不碰服务器**，纯写脚本，所以可以立刻开工。

### 目标

写一个脚本，让一台**全新的、什么都没装的机器**，跑一条命令就能把银盾服务跑起来。

### 产出

```
deploy/
├── install.sh       # 一条命令从裸机到服务起来
└── README.md        # 前置条件、需要开放哪些端口、.env 怎么填
```

### 脚本要干的事（按顺序）

1. 检查系统（Ubuntu 20.04+ / Debian 11+），不满足就报错退出
2. 装 Node.js 18 或更高（`apt install nodejs npm` 或 NodeSource 源都行）
3. 建目录 `/opt/yindun`、建运行用户
4. 拉代码（`git clone` 或从本地拷，两种都支持更好）
5. `npm install --production`
6. 检查 `.env` 是否存在、必填项是否为空（**只检查，不要代填**）
7. 写 `/etc/systemd/system/yindun.service`（下面有现成模板）
8. `systemctl daemon-reload && systemctl enable --now yindun`
9. `curl http://localhost:8080/api/health` 确认返回 `"ok":true`

### systemd 服务模板（仓库 `cloud/README.md` 里有，直接用）

```ini
[Unit]
Description=YinDun Guard Service
After=network.target mysql.service redis-server.service
Wants=mysql.service redis-server.service

[Service]
Type=simple
WorkingDirectory=/opt/yindun
ExecStart=/usr/local/bin/node src/server.js
Restart=always
RestartSec=3
LimitNOFILE=65535

[Install]
WantedBy=multi-user.target
```

**上面这份是从线上服务器 `cat /etc/systemd/system/yindun.service` 抄下来的，别自己改。**

两个具体差异，照抄网上的模板会踩：

- **`ExecStart` 写的是 `/usr/local/bin/node`，不是 `/usr/bin/node`**。NodeSource 源装出来在
  `/usr/local/bin/`，`apt install nodejs` 在 `/usr/bin/`。写死任何一个，换一种装法就起不来。
  **脚本里请用 `NODE_BIN=$(command -v node)` 动态取**，再写进单元文件。
- **没有 `EnvironmentFile`**。`cloud/src/env.js` 会自己解析 `/opt/yindun/.env`，
  再加 `EnvironmentFile` 会造成两套加载逻辑打架（.env 里有值的写法差异会出问题）。

### 三条铁律

1. **脚本里绝对不能出现密码、Key、AK/SK**。`.env` 由人在服务器上手填，脚本只检查"有没有填"
2. **必须幂等**：重复跑不报错，已经装好的不重装
3. **不假设任何东西已存在**：没有 Node、没有目录、没有用户，都要能自己搞定

### 提交方式

开分支 `feat/deploy-infra`，只提交 `deploy/` 目录，提 PR 等队长合。

## 四、第二阶段：开通 RDS 和 Redis（服务器已可登录）

### 4.0 先拿服务器权限（这一步做完才能往下）

**队长不会把 root 密码给你**，改用密钥。你这边做两步：

**第一步**，在自己电脑上生成密钥（已有就跳过）：

```bash
ssh-keygen -t ed25519 -C "yindun-ops"
# 一路回车。如果提示已存在，说明你以前生成过，直接用现成的
```

**第二步**，把**公钥**内容发给队长（注意是 `.pub` 结尾那个，不是私钥）：

```bash
cat ~/.ssh/id_ed25519.pub
```

队长加完会告诉你，然后你这样登录：

```bash
ssh ops@123.249.25.139
```

**私钥绝对不要发给任何人**，也不要提交进 git。

现在这台机器上的东西（**这是你迁移前的基线，先记下来**）：

| 项 | 现状 |
|---|---|
| 服务 | `yindun.service`（systemd，`/opt/yindun`） |

### 操作方式（这条最重要）

**全程在 CodeArts 码道里用自然语言让智能体去做**，不要自己在控制台手点。

比如："帮我在华北-北京四开通一个 RDS for MySQL 实例，最小规格，虚拟私有云选 `vpc-default`、
子网选 `subnet-default`，内网访问，不要开强制 SSL。"

### 网络参数（已实测核对，照着填，别自己猜）

| 项 | 值 |
|---|---|
| 区域 | 华北-北京四 |
| **VPC** | **`vpc-default`**，网段 `192.168.0.0/16`，ID `8f452f90-f5bd-4b51-ad48-4eb1d101552f` |
| **子网** | **`subnet-default`**，网段 `192.168.0.0/24` |
| 现有服务器私网 IP | `192.168.0.211`（同一个子网里） |

**⚠️ VPC 下拉框里可能同时出现好几个长得像的名字。选之前对 ID**，
要的是 `8f452f90-...` 那个。RDS 的 VPC 建完不能改，选错只能删了重开。

### 具体要开两个

| | RDS for MySQL | DCS for Redis |
|---|---|---|
| 版本 | MySQL 8.0 | Redis 6 或 7 |
| 规格 | **单机版**最小（1核2G 或 2核4G） | **单机版** 1GB |
| 网络 | **`vpc-default`** / **`subnet-default`** | 同样 |
| 访问 | 内网 | 内网 |
| 密码 | 自己设，记下来 | 自己设，记下来 |
| ⚠️ 关键 | **不要开"强制 SSL"** | — |
| 计费 | 按需 | 按需 |

**为什么不能开强制 SSL**：我们的数据库连接代码没配 ssl 参数，开了直接连不上，这个坑踩过。

**为什么必须同 VPC 同子网**：不同 VPC 内网连不通，只能走公网，慢且不安全，等于白开。

### 然后迁移数据

```bash
# 1. 先备份！这一步不能省
mysqldump -u root -p --databases yindun > /root/yindun_backup_$(date +%F).sql
# 备份文件再拷一份到本地电脑，别只放服务器上

# 2. 建表（两个文件都要执行，顺序不能反）
mysql -h <RDS内网地址> -u <用户名> -p yindun < sql/schema.sql
mysql -h <RDS内网地址> -u <用户名> -p yindun < sql/migrate_20261111_event.sql

# 3. 导入旧数据
mysql -h <RDS内网地址> -u <用户名> -p yindun < /root/yindun_backup_xxxx.sql
```

**`migrate_20261111_event.sql` 必须执行**，因为代码依赖它新加的列，不执行会报错。

### 改配置、重启

编辑服务器上的 `/opt/yindun/.env`（**这个文件不进 git**）：

```
RDS_HOST=<RDS 内网地址>
RDS_PORT=3306
RDS_USER=<用户名>
RDS_PASS=<密码>
RDS_DB=yindun
REDIS_URL=redis://:<Redis密码>@<Redis内网地址>:6379/0
TZ=Asia/Shanghai
```

注意是 `RDS_PASS`，不是 `RDS_PASSWORD`（写错会静默降级成内存存储，看起来能跑但数据不落库）。

```bash
systemctl restart yindun
curl http://localhost:8080/api/health
```

`"storage":{"rds":true,"redis":true}` 才算成功。

### 最后一步：关掉旧的自装服务

```bash
systemctl stop mysql redis-server
systemctl disable mysql redis-server
```

**顺序不能反**：先确认 RDS 连上了、数据都在，再关本机的。反了就是事故。

## 五之二、关于「阶段 A 反向隧道」——你不用做

老师方案里阶段 A（打通华为云到学校 GPU 的隧道）原本建议给你，**但这一块队长已经接管并做完了 ECS 这一侧**，原因很实际：

隧道要**两边配合**，容器那一侧只有队长有 SSH 权限（学校分配的容器，密钥在队长手上），
你进不去。所以这块拆不了，全程由队长做。

**已经完成的（队长做的，你不用管）**：

- ECS 上建了专用账号 `tunnel`（只能做端口转发，不能登录 shell）
- 学校容器生成的受限公钥已登记，`permitlisten` 锁死在 `127.0.0.1:8099`
- 实测学校容器能连到 ECS 的 22 端口

**你需要知道它是什么**，因为答赛题时会问：

> 学校那台 GPU 在校园网内，公网进不去。所以反过来，让学校那台主动连到我们的 ECS，
> 在 ECS 的 `127.0.0.1:8099` 上开一个口子，指回容器内的 SFT 服务。
> 这样对公网只暴露一个端口转发，学校那台不开任何入站端口。

**对你有影响的两点**：

1. 隧道起来之后，ECS 的 `.env` 里会多一行 `SFT_URL=http://127.0.0.1:8099`。
   你迁移或者重新部署时，**这一行要原样保留**，它的作用是让云端能调用学校的模型。
2. 演示前如果 `/api/health` 里 `sft.enabled` 是 `false`，说明隧道断了。
   **这不是你弄坏的**，告诉队长重启容器侧就行。汇报时如实说「模型服务待接入」。

## 六、几个会翻车的地方（都在我们身上真实发生过）

| 坑 | 后果 | 怎么避 |
|---|---|---|
| `.env` 写成 `RDS_PASSWORD` | 静默降级成内存，看着能跑，重启数据全丢 | 逐字对一遍键名 |
| RDS 开了强制 SSL | 直接连不上 | 开通时不要勾 |
| VPC/子网选错 | 内网不通，只能公网访问 | 选 `vpc-default` / `subnet-default`，按 VPC ID 核对 |
| 没执行 event 迁移脚本 | 启动报错 | 两个 sql 都跑 |
| 先关本机 mysql 再连 RDS | 中间断档，数据可能丢 | 顺序反着来 |
| 迁移前没备份 | 出问题无法回滚 | 先 mysqldump |
| 录屏太晚，代码已改 | 录的和交的不是同一版 | 等 tag 再录 |

## 七、怎么汇报

每天在群里发一句话就够：

> 今天做了 X，卡在 Y，需要 Z。

例如："部署脚本写完，在本地虚拟机跑通了；卡在 ECS 密码，等你给。"

遇到不确定的（尤其是"这个参数该选什么"），**先问再操作**。云上开错规格可以退，但选错 VPC 只能删了重开，浪费时间。

## 二、系统架构

```
┌──────────────────────── 老人手机（银盾 App） ────────────────────────┐
│                                                                      │
│  短信广播 ──┐                                                        │
│  通知监听 ──┤                                                        │
│  通话状态 ──┼──→  判定引擎 Judge（本地，读 rules.json）              │
│  前台应用 ──┘            │                                           │
│                          ├──→ 四级判定 → 浮条 / 红屏 / 震动 / TTS     │
│                          └──→ 上报 ──┐                              │
└──────────────────────────────────────┼──────────────────────────────┘
                                       │ HTTPS
                          ┌────────────▼────────────┐
                          │   云端服务（ECS）        │
                          │  Express + MySQL         │
                          │  同构 Judge.js 复核      │
                          │  SSE /api/stream 推送    │
                          └────────────┬────────────┘
                                       │ SSE 长连接
                          ┌────────────▼────────────┐
                          │   子女端网页             │
                          │  短信栏 / 通话栏自动切换  │
                          └─────────────────────────┘
```

设计上的两个关键选择：

**判定放在端上，不放在云上。** 断网时手机照样能判、能拦。云端只做复核、留档、转发。
实测断网状态下浮条照常弹出，子女端那条推送会显示"云端没回话，这条还没发出去"，恢复后重试成功。

**规则只有一份，两端同构。** `rules.json` 同时被 `Judge.java` 和 `Judge.js` 读取。
改规则不用改代码，也不用重新训练模型。

## 三、功能清单

### 3.1 四个防线

| 功能 | 触发条件 | 老人端表现 | 子女端表现 | 状态 |
|---|---|---|---|---|
| 短信实时判定 | 收到任何短信 | warn 以上弹浮条；验证码弹专用浮条 | 收到卡片（含原文与判据） | 已完成 |
| 微信消息判定 | 微信发出通知 | warn 以上弹浮条（静默，无提示音） | 收到卡片（含发送人与摘要） | 已完成 |
| 陌生来电预警 | 陌生号码响铃 | 响铃卡「这号码不认识？」 | 立即收到「妈妈接到陌生号码来电」 | 已完成 |
| 通话超时复问 | 通话满 5 分钟 | 全屏复问卡 + 持续振动，点按钮才停 | 收到提醒 | 已完成 |
| 通话中收验证码 | 陌生通话中收到验证码 | 立即盖屏（防念出验证码） | 收到阻断级告警 | 已完成 |
| 银行转账拦截 | 通话中打开银行 App | 全屏红屏 + 震动 + 抖动 + TTS + 6 秒自动拨号 | 收到阻断级告警 | 已完成 |
| 反诈演练 | 主动或定时触发 | 陪练流程（模拟骗局对话） | 收到演练结果 | 已完成 |

### 3.2 判定分级

| 级别 | 阈值 | 老人端 | 是否推子女端 |
|---|---|---|---|
| none | < 25 | 无 | 否 |
| watch | ≥ 25 | 首页「最近一次提醒」记一笔 | 否 |
| warn | ≥ 45 | 弹浮条（橙框） | 是 |
| high | ≥ 70 | 弹浮条 + 震动 | 是 |
| block | ≥ 90 | 全屏盖住 + 持续震动 + TTS + 自动拨号 | 是（阻断级） |

### 3.3 诈骗阶段识别

判定结果除级别外还带一个阶段，用于告诉子女"骗子走到第几步"：

| 阶段 | 门槛 | 含义 | 典型话术 |
|---|---|---|---|
| S0 | 0 | 无风险 | — |
| S1 | 15 | 套近乎 | "我是社保局的""工号 0371" |
| S2 | 25 | 制造紧张 | "你的账户被冻结""涉嫌洗钱" |
| S3 | 40 | 隔离 | "先不要告诉家里人""别告诉子女" |
| S4 | 45 | 要钱 | "转到安全账户""验证资金清白" |

## 四、判定引擎

### 4.1 打分规则

```
总分 = Σ(命中的关键词权重) + Σ(命中的反例权重，为负) + 发送方加权 + 链接加分
```

- **关键词**：159 条，覆盖冒充公检法、钓鱼链接、客服退款、贷款刷单、投资理财、冒充亲友、中奖补贴
- **反例**：31 条，银行通知、快递取餐码、正常验证码话术等，命中会减分
- **发送方**：陌生号码 +15，服务号 +0，通讯录 +0
- **链接**：正文含 `http(s)://`、`www.` 或 `t.cn/xxx` 裸短链，+20 并保底 S2
- **验证码**：按发送方区别对待——服务号发的验证码是正常业务不加分；陌生人要验证码是 S4

### 4.2 灰区复审（可选）

本地分数 30–45 之间的短信，且发送方不是服务号时，会送华为云盘古大模型复审一次。
规则很硬：**模型只能升级，不能降级**——模型说是诈骗就提高等级推子女端，
模型说不是就什么都不做，绝不撤掉已经报出去的警报。

## 六、部署

### 6.1 App

```bash
cd app
./gradlew assembleDebug      # 或 bash build2.sh
adb install -r release/Yindun.apk
```

安装后必须手动授予四项权限，缺一项对应防线失效：

| 权限 | 作用 | 缺失后果 |
|---|---|---|
| 短信权限 | 收短信广播 | 短信防线完全失效 |
| 悬浮窗权限 | 弹浮条、盖红屏 | 所有视觉提醒都出不来，只剩子女端收到 |
| 通知使用权 | 读微信通知 | 微信防线失效 |
| 使用情况访问 | 识别前台应用 | 银行拦截失效 |

另外建议加入电池优化白名单并锁定后台，否则国产 ROM 会杀进程。

### 6.2 云端

```bash
cd cloud
npm install
cp .env.example .env        # 填 DB_HOST / DB_USER / DB_PASS / DB_NAME / PORT
mysql -u root -p < sql/schema.sql
node src/server.js
```

可选依赖：

- **MySQL**：必需，存告警、事件、演练记录
- **Redis**：可选，缺失时降级为单机内存
- **华为云盘古**：可选，缺失时跳过灰区复审，本地规则照常工作

健康检查：`GET /api/health` 会自报规则版本与各依赖连接状态。

### 6.3 签名

仓库不含密钥。`build.gradle` 从 `local.properties` 读四项：`yd.storeFile`、`yd.storePassword`、
`yd.keyAlias`、`yd.keyPassword`，缺任何一项会直接抛 `GradleException`（不会静默用 debug 签名）。
换成自己的密钥后重新构建即可，注意包名不变才能覆盖安装。

## 七、已知缺陷

按严重程度排序，全部是真实存在的，不是"待优化项"这种模糊说法。

1. **不能自动挂断电话。** Android 没有给第三方 App 挂断他人通话的权限。系统 API 只允许挂断自己发起的通话。
   所以防线设计成"截住资金动作"——盖屏、拦银行、通知子女，而不是挂断。
2. **微信聊天界面内是盲区。** 通知监听读的是通知，老人正开着聊天窗口时微信不会重复发通知。
   补这个需要无障碍读全屏文字，误报高、耗电、隐私也讲不清，所以没做。
3. **银行识别靠包名白名单。** 没有银行接口，只能靠 `QUERY_ALL_PACKAGES` 读前台包名与标题。
   换一家没收录的银行就不生效，需要扩表。
4. **语音是 TTS 合成，不是真人录音。** assets 里没有预录音频，靠系统 TTS 念固定话术，音色取决于机型。
5. **无自启动引导。** 已申请前台服务与电池白名单，但国产 ROM 的自启管理需要用户手动去设置里开，没有做跳转引导。
6. **模拟器需要软件渲染。** 该模拟器 GPU 不可用（`eglChooseConfig failed`），WebView 硬件渲染会让主线程
   卡在 `syncAndDrawFrame` 导致 ANR，已强制 `LAYER_TYPE_SOFTWARE`。真机不需要这个开关，页面很轻，
   走软件渲染也不慢。
7. **子女端历史记录的时间筛选不可靠。** 服务器存 UTC、浏览器本地 +8，之前的 `created_at` 过滤会差 8 小时，
   现在改成"默认取最近 20 条"绕过这个问题。正确做法是服务端统一转时区，尚未做。

## 八、演示中哪些是模拟的

必须说清楚，避免答辩时被追问。

| 环节 | 真实部分 | 模拟部分 |
|---|---|---|
| 短信 | 真短信进系统短信库、真通知、真判定、真浮条 | 由 `adb emu sms send` 注入，不是另一部手机发的 |
| 来电 | 真来电界面、真通话状态、真判定 | 由模拟器注入 |
| 微信 | 真系统通知、真通知监听、真判定 | 微信本身是壳（装在模拟器里，登录不了真微信） |
| 银行 | 真前台应用、真包名识别、真红屏 | 银行 App 是壳（没有工行接口与账号） |
| 云端 | 真 Node 服务、真 MySQL、真 SSE | 无 |

换到真机只需要：把 `adb emu sms send` 换成另一部手机发短信，把模拟器来电换成真电话。
代码一行不用改。微信和银行壳要换成真 App，需要扩银行的包名表，微信不需要改（通知格式一致）。

## ① 【今晚必须做】把每日配额临时抬到 3000

**为什么**：`/api/report` 每日限次，按 IP + 北京时间日切，**`dryRun` 照样计次**
（代码里故意的，`server.js:564` 注释：「不然谁加个 dryRun 就能无限刷模型调用」）。
线上现在是 **1200/天**（`health` 里 `limits.reportPerDay`），乙明天要跑 **1,070 条**，占 89%，
只剩 130 次余量。并发一有失败重试就会在最后几十条撞 429 ——
表现是「前面九百多条都有分，后面一片失败」，**分母不全，整张表作废**。

```bash
sudo cp /opt/yindun/.env /root/env.bak.$(date +%F_%H%M)
sudo sed -i 's/^RATE_REPORT_PER_DAY=.*/RATE_REPORT_PER_DAY=3000/' /opt/yindun/.env
grep RATE_REPORT_PER_DAY /opt/yindun/.env                        # 要显示 3000
sudo systemctl restart yindun
curl -s localhost:8080/api/health | grep -o '"limits":{[^}]*}'   # 要显示 reportPerDay:3000
```

- `.env` 里**没有**这一行，就手动加一行 `RATE_REPORT_PER_DAY=3000`
- 改完**在群里发一句「配额已 3000」**，乙看到才开跑
- **明早乙跑完、我们核完库，改回 1200 再重启一次。别忘了。**

**验收**：`health` 里 `reportPerDay:3000`，群里已通知。

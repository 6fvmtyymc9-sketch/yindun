### 最阴的坑：时区

我们的数据库连接代码（`cloud/src/server.js:115`）**没有设置 `timezone` 参数**，
时区完全由 MySQL 服务器自己决定。

- 旧的库：装在本机上，跟着系统时区走，是 +08
- 新的 RDS：华为云默认参数组通常是 **UTC**

如果不管，迁移完所有时间戳**整体差 8 小时**，子女端时间线全是错的，而且不会报任何错。

**做法**：RDS 创建后 → 「参数修改」→ 找到 `time_zone` → 改成 `+08:00`。这是动态参数，改完即时生效，不用重启。

验证：
```sql
SELECT NOW(), @@time_zone, @@system_time_zone;
```
`NOW()` 应该等于北京时间。

## 三、安全组怎么配

RDS 用**安全组**，DCS 用**白名单**，两者规则不一样，别混。

**RDS 安全组（入方向）**

| 协议端口 | 源地址 | 说明 |
|---|---|---|
| TCP 3306 | `192.168.0.211/32` | 只放 ECS 这一台 |

**DCS 白名单**：填 `192.168.0.211`，别填 `0.0.0.0/0`。

**⚠️ 顺手检查现有 ECS 的安全组**：入方向如果有 `0.0.0.0/0` 开 22 端口，改成只放你自己的 IP。
现在这台机器在公网上开 SSH，谁都能试密码。

## 四、开通后先验证，再迁移

**不要一开通就直接迁数据。** 先在 ECS 上确认能连上：

```bash
# 1. 网络层通不通（3306 / 6379）
timeout 5 bash -c '</dev/tcp/<RDS内网地址>/3306' && echo "RDS 端口通" || echo "RDS 不通"
timeout 5 bash -c '</dev/tcp/<Redis内网地址>/6379' && echo "Redis 端口通" || echo "Redis 不通"

# 2. 账号能不能登
mysql -h <RDS内网地址> -u yindun -p -e "SELECT VERSION(), NOW(), @@time_zone;"
```

**端口不通就是 VPC 选错了**，别往下走，回去看第一节那张表。

## 七、迁移顺序（顺序错了就是事故）

```
1. mysqldump 备份（放 ECS 上，再拷一份到本地）
2. 在 RDS 上建库建表：schema.sql → migrate_20261111_event.sql
3. 导入备份
4. 改 .env（RDS_HOST / RDS_PASS / REDIS_URL / TZ=Asia/Shanghai）
5. systemctl restart yindun
6. curl /api/health → 看 storage.rds / storage.redis 都是 true
7. 重启一次服务，确认告警记录、上报记录还在（证明真读到了 RDS）
8. 上面都对，才停本机的 mysql、redis-server
```

**第 8 步放最后。** 先停本机再连 RDS，中间那段时间数据是断的，出问题没法回头。

**别在本地用 mysql 客户端往 RDS 导数据**——5 Mbit/s 带宽，几十 MB 的 dump 会传很久。
在 ECS 上直接导入，走内网，几秒钟的事。

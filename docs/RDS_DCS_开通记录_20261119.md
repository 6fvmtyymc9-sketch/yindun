## 三、DCS（Redis 6.0 单机 1G）

| 项 | 值 |
|---|---|
| 接口 | `POST https://dcs.cn-north-4.myhuaweicloud.com/v2/{project_id}/instances` |
| 实例名 | `yindun-redis-1119` |
| 实例 ID | `fc5524c5-ca55-4ca7-a1fd-bd39e3282a69` |
| 规格 | `redis.single.xu1.large.1`（1G，0.29 元/时） |
| 内网地址 | `192.168.0.138:6379`，密码鉴权 |
| 返回 | HTTP 200，`status=CREATING` → 约 2 分钟 `RUNNING` |

**踩坑 2（这次真正的坑）**：DCS v2 的可用区参数名是 **`az_codes`**，不是 `available_zones`。
传 `available_zones: ["cn-north-4a"]` 会报 `HTTP 400 DCS.4042 This AZ does not exist`——
**报错说"可用区不存在"，其实可用区没问题，是字段名不对**，换 4a/4b/4c/4g 全一样报错。
改成 `"az_codes": ["cn-north-4a"]` 立刻 200。

**踩坑 3**：`GET /v2/{project_id}/flavors` 返回 944 条规格，但**没有 `product_id` 字段，`az_codes` 也全是空数组**；
`GET /v2/{project_id}/products` 直接 404（`APIGW.0101`）。所以"先查 product_id 再创建"这条路走不通，
**创建时不要传 `product_id`，服务端自己匹配**。

**连通性实测（同一安全组内）**：
```
redis-cli -h 192.168.0.138 -a *** ping        → PONG
set/get/del                                   → OK / ok / 1
--latency                                     → 0.45 ms
```

## 四、数据迁移（本机 MySQL → RDS）

ECS 本机 MySQL 8.0.46，`yindun` 库 2.52 MB，`mysqldump` / `mysql` 客户端都在。
脚本 `D:\华为ict\.tmp\migrate_import.sh`：备份 → `mysqldump --single-transaction --databases yindun` →
导入 RDS → 六张表逐张对数（`yd_alert` / `yd_report` / `yd_drill` / `yd_event` / `yd_user` / `yd_known`）。
**导入阶段不改 `.env`**，线上仍跑本机库；切流量单独一步，随时可回滚。

## 五、两条给材料的提醒

1. **`health.storage.rds=true` 不等于"上了云数据库"**。切之前 `.env` 里 `RDS_HOST=127.0.0.1`，
   连的是 ECS 本机 MySQL，这个字段只代表"连得上"。要证明真的用了 RDS，得给**实例 ID + 内网地址 + 迁移前后对数**，
   本文第二节那几张表就是干这个用的。
2. **费用**：RDS 0.40 元/时 + Redis 0.29 元/时 ≈ **0.69 元/时**。做完演示就删实例，
   按 4 小时算不到 3 元。别放着过夜。

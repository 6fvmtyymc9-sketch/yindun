# AntiFraud-SFT「恒答是」现象：旧打分方式下的产物，叠加训练集缺负样本答案

> ⚠️ **2026-11-20 22:58 老师复核后更正（以此为准，优先于本文原有措辞）**
>
> 老师在学校 GPU 上新增 `/judge` 接口（提交 `f967ffe`，说明见 `docs/SFT接口说明.md`），
> 按模型训练时的原生两轮问法判定。实测结果：
>
> | 输入 | 条数 | `/judge` 判对 | 旧 `/risk` |
> |---|---|---|---|
> | demo 三段录音（音频） | 正常 1 / 诈骗 2 | **3 / 3** | 物业停水误报 |
> | 5 秒静音 | 1 | 被过滤 | p=0.62，判诈骗 |
> | holdout 诈骗（文本） | 20 | **20 / 20** | — |
> | holdout 正常（文本） | 15 | **9 / 15** | 误报 14/15 |
> | CGoDial 真实政务热线 | 30 | **3 / 30**（误报 27） | — |
>
> **所以要把两件事分开说，不要再混成一句「模型恒答是 / 权重坏了」：**
>
> 1. **「恒答是」是 `/risk` 打分方式的产物，不是权重坏了。** `/risk` 强行让模型「只答一个字」，
>    再比较「是/否」两个 token 的概率——这个数和输入内容基本无关，连静音都能拿到 0.62。
>    模型从没被训练成「只答一个字」，这么问等于换了个任务。
> 2. **本文的数据统计仍然成立，而且正好解释「换成 `/judge` 后为什么还是误报高」。**
>    训练集里进 loss 的 `is_fraud` 只有 true（7,177 次）、false 0 次，
>    模型**见过** 6,211 条「这是诈骗吗？」的提问、却没被告知答案可以是 false。
>    结果就是：正常话术也能判对一部分（9/15），但机构来电、政务热线这类
>    「要核实身份 / 提公积金医保」的会大量误判（CGoDial 27/30 误报）。
>    老师的判断一致：这批误报正是 `SFT下一步计划.md` 第 3、4 步要补的负样本。
>
> **因此本文不应再被引用为「模型不可用」的依据**；正确说法是：
> 旧接口问法不可信 + 训练集负样本答案缺失 → 误报偏高，暂不能单独判定，只能抬分且需第二票。
>
> 以后所有评估一律用 `/judge` 重跑，不再用 `/risk` 的 `p`。

## 一、铁证：`is_fraud: false` 在训练集里出现 0 次

`audio.zip` 与 `sft.zip` 下载完成后，直接解析 `sft/train.jsonl` + `sft/test.jsonl`：

```
样本总数                        33,953
assistant 消息总数              27,742
  ├─ 场景分类答案（含 "scene"）  20,565
  ├─ "is_fraud": true            7,177
  └─ "is_fraud": false               0   ← 一次都没有
```

**模型在训练中从未见过「不是诈骗」这个答案。**

## 二、结构错位：79% 的样本末尾没有 assistant 回答

比标签统计更能说明问题的是 messages 的角色序列分布：

| 角色序列 | 条数 | 占比 | 对应的标签 | 实际训到了什么 |
|---|---|---|---|---|
| `system, user` | **10,711** | 31.5% | 场景类（咨询客服等） | **什么都没有**——没有 assistant，零 loss |
| `system, user, assistant, user` | **13,388** | 39.4% | `fraud` 7,177 / `normal` 6,211 | **只有第一轮场景分类**；第二轮问「是否诈骗」，但没有答案 |
| `system, user, assistant, user, assistant, user` | **7,177** | 21.1% | 7 种细分诈骗 | 场景分类 + `is_fraud: true`，**第三轮又问了「诈骗类型」但没答案** |

### 这意味着什么

1. **每一条样本的最后一条消息都是 `user`，没有对应的 `assistant`。**
   标准 SFT 只对 assistant 的 token 计算 loss，最后的提问自然不产生任何训练信号。
2. 答案被放在**独立的 `answers` 字段**里（字符串，如 `"fraud"` / `"normal"` / `"咨询客服"`），
   而训练框架读的是 `messages`。**`answers` 字段不进 loss。**
3. 于是 `answers=normal` 的 **6,211 条负样本**，模型看过它们的问题（「这是诈骗吗？」），
   **但从来没被告知答案可以是 false**。

### 那 7,177 条 `is_fraud: true` 从哪来的

来自 7 种细分诈骗（客服 2,521 / 银行 2,040 / 投资 995 / 钓鱼 551 / 彩票 517 /
绑架 416 / 身份盗窃 137，合计 7,177）。**全是正样本，一条负样本都没有。**

> 顺带解开一个巧合：`answers=fraud` 也是 7,177 条，`7 种细分诈骗` 也是 7,177 条。
> 两者数字相同但不是同一批——前者是 `(s,u,a,u)` 结构（答案没进训练），
> 后者是 `(s,u,a,u,a,u)` 结构（`is_fraud: true` 进了训练）。正是这个巧合
> 让此前按 `answers` 字段做的「41.8% vs 58.2% 基本配平」统计得出错误结论。

## 三、为什么之前的三个归因全错了

### 3.1 「正样本占绝对多数 → 类别失衡」——**错，且方向反了**

此前统计 `answers` 字段得到：fraud 21.09% + normal 18.37% + 7 种诈骗 20.7% = 诈骗类 41.8%，
于是结论「41.8% 对 58.2%，基本配平，不是失衡导致坍塌」。

**这个统计看错了字段。** `answers` 只是元数据，真正进入 loss 的是 `messages` 里的
`is_fraud`。按后者统计：**正 7,177 / 负 0 = 100% 正样本。**

所以：不是「比例失衡」，是「负样本数量为零」。做任何过采样、重加权、类别平衡都无效，
因为负样本的**答案文本**压根不在训练语料里。

### 3.2 「训练 48k、线上 8k，信道不匹配」——**错，实测无差异**

用 FFT 累积分能量的 95% / 99% 分位频率衡量**真实有效带宽**（容器采样率不算数，
ChatTTS 的输出可能装在大容器里但内容仍是窄带）：

| 素材 | 容器采样率 | 有效带宽 f95 | 有效带宽 f99 | 4 kHz 以上能量占比 |
|---|---|---|---|---|
| TeleAntiFraud TTS（8 条抽样） | **48,000 Hz** | 657 ~ 1,828 Hz | **1,886 ~ 4,436 Hz** | 0.14% ~ 1.41% |
| MagicData 真实电话（3 条） | 8,000 Hz | 1,251 ~ 1,700 Hz | **1,580 ~ 2,855 Hz** | 0.00% |
| MagicData 16k 朗读（2 条） | 16,000 Hz | 603 ~ 660 Hz | 3,113 ~ 3,544 Hz | 0.20% ~ 0.60% |

**TTS 的有效带宽和真实电话几乎重合，甚至更窄。** 文件头写着 48 kHz，里面并没有 4 kHz
以上的实际内容。→ 模型不可能靠「高频有没有能量」区分真假输入。**频带假设作废。**

### 3.3 「线上问法与训练不一致 → 恒答是」——**是真问题，但不是根因**

确实不一致，且这点已确证（见第四节）。但**即使把问法完全改成训练时的样子，答案也只会是
「是」**——因为 `is_fraud: false` 从未在训练中出现过。换问法无法凭空造出它没学过的答案。

### 3.4 一个补充实测：输出对「音频长度」都敏感到能翻转结论

在训练域原生格式的 TTS 音频上跑音频模式（同一问法、同一条素材族的诈骗样本）：

| 输入 | 时长 | 真值 | p | 判为 |
|---|---|---|---|---|
| TTS-POS | 22 秒 | 诈骗 | **0.3208** | normal ✗ |
| TTS-POS | 10 秒 | 诈骗 | **0.9149** | fraud ✓ |

**同一个模型、同一种问法、同样是诈骗内容，只因长度从 22 秒变 10 秒，p 差了 0.59 并翻转判定。**
一个真正在做内容判别的模型，不会因为截短一半而把结论翻过来。

这与「训练里只有 `true`」完全吻合：输出不是在回答「是不是诈骗」，
而是在没有判别依据的情况下由长度、能量、token 数等无关因素驱动的抖动。

## 四、附带确证：线上问法与训练问法确实不一致（工程缺陷，需修）

`sft/train.jsonl` 里的训练输入是**两轮对话 + JSON 输出**：

```
轮1  system  你是个有用的音频理解助手。
     user    <audio> + 「判断通话场景属于 7 类中的哪一种」
     asst    {"scene": "咨询客服", "reason": "...", "confidence": 0.8}

轮2  user    「判断其是否涉及诈骗…」
     asst    {"reason": "...", "confidence": 0.9, "is_fraud": true}
```

而 `tools/sft_server.py` 第 46 行的 `AUDIO_PROMPT` 是：

```
这是一段电话通话录音。请判断打电话的人是不是在实施诈骗，只回答一个字：是，或者否。不要解释。
```

| 维度 | 训练时 | 线上 |
|---|---|---|
| 对话轮数 | 两轮（先场景分类） | 单轮 |
| system prompt | 有 | **无** |
| 输出形态 | JSON 字段 `is_fraud: true/false` | **单个汉字「是/否」** |
| 推理依据 | 第二轮显式引用第一轮的场景结论 | 无 |

`_probe()` 比较的是词表里「是」「否」两个 token 的 logits，而这两个字在训练时
**从来不是答案形式**。所以读数本身也不可靠。

而且 `tools/build_sft_data.py` 的 `TEXT_PROMPT` 用的是同一句「只回答一个字」，
注释还写着「与 sft_server.py 保持一致，改一处必须改两处」——
**我们自己造数据也会继承这个错模板**，老师六步计划的第 3 步要特别当心。

**修法**：把线上问法改成训练同构的两轮 + JSON，读 `is_fraud` 字段而不是「是/否」两个 token。

## 五、训练配置也在放大问题

`D:/models/AntiFraud-SFT/args.json`（ms-swift 训练参数存档，直接读，非推测）：

| 参数 | 值 | 问题 |
|---|---|---|
| `train_type` / `lora_rank` | lora / **32** | 不算小 |
| `num_train_epochs` | **10.0** | 激进 |
| `learning_rate` | 5e-05 | 配 10 epoch 偏大 |
| **`split_dataset_ratio`** | **0.0** | **没有验证集** |
| **`load_best_model_at_end`** | **False** | 交付的是**最后一步**，不是最优步 |
| `freeze_vit` | **True** | 音频编码器一个参数都没动 |
| `freeze_aligner` | **True** | 音频-文本对齐层也冻结 |
| `dataset` | 单一 `total_train_wpd.jsonl` | 无外部数据混合 |

三点后果：

1. **音频编码器完全没训**（`freeze_vit=True`）→ 模型"听"到的表示全来自 Qwen2-Audio 基座，
   LoRA 只学了 LLM 层面「这类 token + 这个 prompt → 输出 true」的映射。
2. **无验证集 + 取最后一步** → 没有任何机制能发现过拟合，也没机会回退。
3. 配合「is_fraud 只有 true」，最省力的解就是把输出无条件推向 true —— **loss 降得最快**。

## 七、结论与处置

### 7.1 结论改写

此前表述：「模型恒答是，阈值/prompt/校准都救不了，是权重问题」。

**应改为**：

> 该模型的微调数据集在构造时把答案写进了 `answers` 字段而没有拼进 `messages`，
> 导致 33,953 条样本中 `is_fraud: false` 出现 **0 次**，13,388 条样本末尾缺 assistant 回答。
> 模型因此从未学过「不构成诈骗」这一类别，无论输入什么都倾向输出「是」。
> **这是数据构造缺陷，不是模型能力上限，也不是推理接入方式能修的。**

这个表述更准、更有据、也更经得起追问 —— 而且它指向**可修**。

### 7.2 该做什么

| 事项 | 结论 |
|---|---|
| 线上 `SFT_URL` | **继续留空**。现有权重不可用，接上只会引入恒真票 |
| A6（接隧道） | **继续禁止**。理由比之前更充分 |
| 重训 | **值得做**，且成本不高：把 `answers` 拼成最后一条 assistant 消息即可 |
| 老师六步计划 | 第 1、2 步（评估集 + 基线表）照做；**第 3 步造数据必须加一条校验：**
|  | 每条样本 `messages` 最后必须是 `assistant`，且正负标签数量都要打印出来 |
| 第 4 步微调 | 必须划验证集（`split_dataset_ratio≥0.05`）、开 `load_best_model_at_end`、epoch 降到 2~3 |

### 7.3 一句话给老师

> 训练集 `total_train_wpd.jsonl` 里 `is_fraud: false` 出现 0 次，13,388 条样本的
> messages 末尾是 user 没有 assistant 回答——答案是写在 `answers` 字段里的，没进 loss。
> 所以模型不是"学不会"，是**没学过负样本**。把 answers 拼回 messages 末尾重训，
> 大概率能解决恒答是。

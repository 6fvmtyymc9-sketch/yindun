## 背景

「银盾」是一个反诈守护 App，给独居老人用：拦截陌生号码通话中的转账操作、收到验证码时遮蔽、
把风险预警推给子女端。这是要交付参赛的真实工程，不是演示原型。

技术栈：
- 老人端：Android 原生 **Java**，`minSdk 24` / `targetSdk 34` / `compileSdk 34`，JDK 17。
  **纯手写 View，没有 XML 布局**；除一个本地 `mindspore-lite-java.jar` 外没有第三方依赖。
- 云端：Node.js + Express + MySQL(RDS) + Redis，单进程。

## 这次改动做了什么

**① 一次事件的完整回放。** 一通电话里会发生七八件事（陌生号响铃 → 聊满 5 分钟复问 →
通话中收到验证码 → 挂断后打开手机银行 → 红屏拦住 → 自动打给女儿 → 录音复盘）。
原来在子女端散成七八张互不相干的卡片，看不出"这是一次诈骗"。现在每通电话生成一个
`callId`，这一场里的每条上报都带上它，云端按 id 归组，子女端可以点开一条时间轴。

两个关键决定，请重点审是否站得住：
- **id 在响铃那一刻生成，接通时复用**，不新开一场。否则时间轴第一格"陌生号打来"会永远
  孤零零在外面，恰好丢掉最重要的信息。
- **通话结束后 id 保留 30 分钟**，不是立即清空。因为骗子最常说的是"您先挂了，去银行 App
  里操作"，最要命的一步发生在挂断之后。

**② 被骗套路 → 次日专属演练。** 录音复盘判为高危时，记下诈骗类型（**只记类型，不记原话**），
次日 10:00 单独提醒一次「上次那通「冒充熟人」，陪您再练一遍」，点进去自动开局。3 天过期。

**③ 顺带修的真 bug。** 原来的上报函数 `pushToBackend` **从来没带 `elderId`**，云端一律按
`demo` 落库，多老人场景会全部串进同一个桶。现在带上了。

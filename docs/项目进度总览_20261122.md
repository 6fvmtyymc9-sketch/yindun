## 三、第 2 步的实测结果（五组，四条独立路径）

| 配置 | 诈骗召回 | 正常误报 | 备注 |
|---|---|---|---|
| 规则 + DeepSeek（两票，当前线上配置） | **15 / 15** | **0 / 15** | 中位 13.3 秒 |
| SFT 音频模式（`/judge` 原生两轮） | 15 / 15（p≥0.85） | 0 / 15 | 不依赖转写 |
| SFT 文本模式（同一模型，换 ASR 文本） | 15 / 15 | **2 / 15** | **声音里确实有文字丢掉的信息** |
| 三票全开 | 15 / 15 | 0 / 15 | **与两票完全一致，第三票没改变任何一条结论** |
| CGoDial 难负样本（规则 11.7% 误报） | — | 压到推算 **2.9%** | 红屏 111 条 → 1 条 |

第二行与第三行是本轮最有价值的一组对照：**同一份权重、同一批音频，只把输入从声音换成转写文本，误报就从 0/15 变成 2/15。** 这证明音频路线不是"多此一举"，它拿到的信息文本里没有。

第四行的结论要照实说：三票**不是**提高了准确率，而是三条独立路径互相验证、结论一致。

## 四、附带查清的一件事：SFT 之前为什么恒答「是」

这是数据构造 bug，不是模型能力上限：

- 原始 `sft.zip` 33,953 条里，assistant 出现 `"is_fraud": true` **7,177 次，false 0 次**
- 另有 13,388 条 messages 以 user 结尾、没有 assistant（答案放在独立 `answers` 字段，不进 loss）
- 结果：模型只见过"是"，**从没学过"不构成诈骗"**

已修：`tools/fix_sft_data.py` → `sft_fixed/`，train **21,422**（true 5,724 / **false 4,987**）、test 5,354。顺带查出 `SUAU-fraud` 与 `SUAUAU` 两个目录 audios 完全相同（重复 5,724 条），脚本默认丢弃其中一份。

## 七、必须连带的边界说明（引用数字时请一并引用）

1. **30 通是小样本。** 100% 召回 / 0% 误报只能说明"在这 30 通上没错"，不足以代表真实分布。基线文档第 4 节列了九条局限。
2. **三票不等于更强**，只是三条独立路径结论一致。
3. **线上目前不接 SFT**（`SFT_URL` 留空）。原因已从"模型不可用"更正为"现有权重是在有标注 bug 的数据集上训出来的"，所以在重训完成前不接入。
4. **文字与录音是分工不是替换**：线上文字走 DeepSeek，录音走 SFT。已实测 SFT 判文字漏报仅 0.2% 但正常短信误报 93.3%，文本模式对 SFT 没有判别力。
5. **Demo 页在线依赖华为云 ECS**。材料若引用访问地址，需保证 ECS 与弹性 IP 保留至评审结束。

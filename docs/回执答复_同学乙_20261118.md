## 二、配额：是"每个 IP 每天"，不是每个老人账号

代码在 `cloud/src/RateLimit.js`，键是：

```
yindun:rl:report:{IP}:{北京日期}
```

- 按**调用方 IP** 计数，按**北京时间零点**重置（`Intl.DateTimeFormat('en-CA', {timeZone:'Asia/Shanghai'})`）。
- 计数落在 Redis（线上 Redis 通着），所以服务重启不清零。
- 所以：你一台机器跑，就是 60 次/天，跟 elderId 传什么无关。你的判断没错，只是原因不是账号。

**处置：评估期临时提到 1200/天，评估跑完回落到 60。**

- 改的是 `.env` 的 `RATE_REPORT_PER_DAY`，不动一行代码。
- 钱上有上限：单次约 ¥0.0007，1200 次 = **¥0.84/天**，封顶。1,070 条一天跑完，成本约 ¥0.75。
- 为什么不做 IP 白名单：你家宽带是动态 IP，白名单会天天失效；而且这个限制本来防的是"有人写脚本刷我们的模型钱"，不是防你。
- **你不用改脚本。** 你现在"撞配额就停"的处理是对的，留着。

## 三、音频：不用装 Whisper，三条路里最省的那条你漏了

你的结论是"音频没有转写稿就进不了评估表"，前半句成立，**后半句不成立**。

### 1）MagicData 自带转写稿，这是零成本的路

每个 wav 同名 `.txt`，格式长这样（accent 包）：

```
[8.273,11.632]	SPK002	男	北京爱数智慧语音采集。
[12.260,12.880]	SPK002	男	嗯。
```

（meeting 包是 `[start,end]  1  男,普通话  文本`，`0 / none` 那几行是 `[ENS]` 噪声标记，要丢掉。）

把文本拼起来直接喂 `/api/report` 就能打分，**不用跑 ASR，不用装环境，也不用改产品代码**。
我已经写好脚本，你直接跑：

```bash
cd cloud
node test/eval-magicdata.js "D:/华为ict/外部数据集/magicdata"
```

它会自动：找所有 `.txt` → 按"一通对话"归并（双路只留一路）→ 丢掉 `[ENS]` → 拼文本 → 过规则引擎 →
输出每通的得分、级别、命中词，以及**误报了几通**。退出码非 0 表示有误报，能直接进 CI。

### 2）真要跑 ASR，通道是 `/api/callaudio`，不是 `/api/report`

你试的 `/api/report` 确实不收音频（设计如此：它是短信/截图入口）。但线上**早就有一个收录音的接口**：

| | `/api/report` | `/api/callaudio` |
|---|---|---|
| 收什么 | 文字 + 图片 | **录音 base64** + 可选 demoText |
| 转写 | 不转，`cloud/src/Ocr.js` 只做图片 OCR | **转**，`cloud/src/Asr.js` → 华为云 SIS 一句话识别 |
| 上限 | — | 25 MB（base64 解码后），express body 限 40mb |
| 身份 | elderId | 未认证只能传 `elderId: demo` |

`GET /api/callaudio/ping` 现在返回 `"asr":"sis"`，说明线上 AK/SK 是配着的、SIS 是通的。
这条链路 2026-11-11 实测过：42.8 秒录音转写 2.2 秒，85.5 秒自动切两段、整次复盘 5.7 秒。

**注意**：SIS 单次限 60 秒，服务端按 55 秒自动切段（`cloud/src/AudioSplit.js`）；
但 **25 MB 的体积上限在切段之前**，30 分钟的 8k wav 约 28 MB，会被 413 顶回来。
要跑就先切成 3 分钟以内的片段。

**建议**：全量用第 1 条（自带转写），另外**抽 2~3 段切片走 `/api/callaudio` 真跑一次 SIS**，
留个"真录音→转写→判定"的完整证据给答辩。两条都要，成本很低。

### 3）所以 (a)(b)(c) 三个选项都不用选

不需要新写 ASR 接口，不需要装 Whisper，也不需要写"样本待补"。

## 四、你说的规则漏洞：确实存在，而且比你说的更精确

我复现了，同一句话换一个动词，判定就跨两档：

| 文本 | 得分 | 级别/阶段 | 命中词 |
|---|---|---|---|
| 我是你领导，明天来我办公室，先帮我**转**笔钱给客户 | 45 | block / S4 | 帮我转:30 + 陌生号码:15 |
| 我是你领导，明天上午九点来我办公室一趟，现在有个事需要你先帮我**垫**一笔钱 | **15** | **watch / S1** | 只有 陌生号码:15 |

原因：词表里有「帮我转」30 分、「垫付」30 分，但**没有「帮我垫」**——口语原话恰好是动词 `垫` 不是 `转`。
而且「我是你领导」「来我办公室」这两个身份冒用词也一个都没有，所以身份信号是 0。

**已改（规则 3.5 → 3.6，关键词 217 → 220）**：

| 新增词 | 权重 | 阶段 | 理由 |
|---|---|---|---|
| 我是你领导 | 25 | S1 | 单句只到关注级，必须和要钱词叠加才报警，避免冤枉「我们领导」 |
| 来我办公室 | 20 | S1 | 冒充领导的标配钩子 |
| 帮我垫 | 30 | S4 | 和「帮我转」对齐 |

改完的判定：

| 文本 | 改前 | 改后 |
|---|---|---|
| 陌生号 + 我是你领导…帮我垫一笔钱 | 15 watch | **90 block / S4** |
| 通讯录里的同一条（骗子存在通讯录里） | 0 none | **55 block / S4** |
| 「领导让我明天去办公室开会」（正常） | 15 watch | 15 watch（不报警） |
| 「小王，来我办公室一趟，带报表」（正常，通讯录） | — | **0 none** |
| 「我们领导说下周组织体检」（正常，通讯录） | — | **0 none** |
| 「儿子，帮我垫一下水电费」（正常，通讯录） | — | **8 none** |

**顺手还修了两个误报源**，是你那份 300MB 录音暴露出来的（我按第 1 条跑了 9 通真人对话）：

| 词 | 改前 | 改后 | 为什么 |
|---|---|---|---|
| 今天下午 | 15 / S2 | **8** / S2 | 真人对话里"今天下午"加陌生号 = 30 分 warn，老人一天说好几遍这四个字 |
| 急需 | 20 / S2 | **12** / S2 | 正常工作讨论里"急需报数、急需发货"直接 warn |

**改完的实测数字（你可以自己复跑复核）**：

```
node test/run.js                     → 诈骗 59 条 漏报 0 / 正常 40 条 误报 0

```

误报从 2/9 降到 0/9，漏报仍是 0。这就是"正常通话会不会误报"这个问题的第一版答案。

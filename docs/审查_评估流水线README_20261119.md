## 二、分层命名错了：S1 不会推给子女

他写的表：

| 层 | 口径 | 含义 | 漏报 |
|---|---|---|---|
| 识别层 | `local.level !== 'none'` | **子女端收到提醒** | 18.9% |
| 拦截层 | `stage >= 3` | 红屏阻断 | 50.0% |

「子女端收到提醒」这半句是错的。App 端的推送门槛在 `SmsReceiver.java:171`：

```java
// 分数够高就当成一条预警推给子女端
if (!"none".equals(r.level) && !"watch".equals(r.level)) {
    EventBus.pushAlert(...);
    Notifier.alertChild(...);
```

`levelOf()` 的映射是 `S1 → watch`，而 `watch` 被这一行**显式排除**。
也就是说 **S1 既不给子女推送，也不给老人弹浮条，只写一条日志**。

服务端的 `isFraud = local.level !== 'none'` 只表示「服务端算它算诈骗」，
`server.js:658` 推预警的条件是 `result.isFraud && result.stage >= 3`。

### 真实是四层，不是两层

| 层 | 条件 | 产品行为 | 云端口径（who=''） | App 口径（who=stranger） |
|---|---|---|---|---|
| 判定层 | `level !== 'none'`（S1 起） | 服务端记 isFraud，**不惊动任何人** | 18.8% | 4.2% |
| 推送层 | `level ∈ {warn,high,block}`（S2 起，`SmsReceiver:171`） | **子女端收到预警** + 老人端浮条 | 35.2% | 22.1% |
| 拦截层 | `stage >= 3`（`server.js:658`） | 红屏阻断 + 推子女 | 49.8% | 41.9% |
| 阻断层 | `stage >= 4` | 替换通知栏 / 自动挂断 | 54.7% | 48.5% |

（本地复跑 1,070 条 Fraud-R1，`stage` 分布：who='' 为 S0 201 / S1 176 / S2 156 / S3 52 / S4 485；
who='stranger' 为 S0 45 / S1 192 / S2 211 / S3 71 / S4 551）

### 这条错误的方向反了

他上一版报的 **S2 起 35.3%**，被他标成「脚本自设阈值，已废弃」。
**它不是错数，它就是「子女端收到提醒」那一层。** 恰恰是产品最该报的数字——
银盾的卖点就是「提醒子女」，18.9% 这一层老人和子女都感知不到。

建议改法：把 35.3% 请回来，改名叫**推送层**，18.9% 改叫**判定层**并注明「不产生用户可见行为」。

## 三、可重复跑和 `--no-cache` 打架

他第三节写「三条硬要求：可重复跑 —— 同批数据跑两次，指标一模一样（靠 `.cache/`）」，
但前面又写「正式跑分一律加 `--no-cache`」。**两条同时成立不了。**

`Pangu.js` 里 `temperature` 默认 **0.2**，多数调用用 **0.1**，都不是 0。
融合路的 `isFraud` 来自在线模型，重跑会在边界样本上抖动几条。

老实写法：

> 带缓存时可逐条复现；`--no-cache` 重跑时规则路完全一致，
> 融合路因模型 temperature=0.1~0.2 可能有 ±N 条抖动。

---

## 四、`误报率 0.0%` 应该写 `0/9`

负样本只有 9 通真人对话。写 **0.0%** 会被问「9 条怎么算出小数点的」。
9 条全对，95% 置信区间的上限约 **28%**。写成 **0/9** 既准确又不会被追。
他在 caveat 3 提了「用的是自带转写稿」，但没提样本量不足这件事。

---

## 五、SFT 那行理由要更新

他写：`| SFT | 音频模态，不适用文本 | -- | -- |`

11-19 复核结论是：这个权重**对任意输入恒答「是」**（喂静音 p=0.62、正弦波 0.85、
14 段正常通话 14/14 判诈骗，「是」稳定 rank 1/151k）。见 `docs/SFT模型可用性复核_20261119.md`。

建议改成：

> `| SFT | 音频模态不适用于文本；且该权重 11-19 复核为恒答「是」，暂不可用 | -- | -- |`

不写会出问题：另一处说「SFT 不可用」，这一处说「不适用文本」，两句话对不上，
评委会顺着问「那音频能不能用」。

## 六、`dryRun` 扣配额是设计，不是坑

他写「**坑**：dryRun 照样扣 reportPerDay 配额」。

这是我刻意做的：限流在写库之前，否则任何人都能用 `dryRun:1` 无限刷模型调用、
直接把 MaaS 额度烧光。**别把它当 bug 修。**

实操影响：1,200/天 只够跑一轮全量（1,079 条）。
评估期要么只跑 dryRun 一轮，要么把 `RATE_REPORT_PER_DAY` 临时提到 2,400。
另外重置是按北京时间 **00:00**（Redis key 带日期），不是 00:01。

## 七、行号会漂移

他引用 `server.js:597`、`server.js:635`。我 11-19 给 `/api/report` 加了 `dryRun`

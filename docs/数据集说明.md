# 数据集说明

> 对应《模型选型》4.1：「训练数据 = ChiFraud + cases.json + 自行收集的正常短信」，
> 「必须用 cloud/test/holdout.json 评估，训练时不能用留出集」。
> 本文是这条要求的执行记录：数据从哪来、怎么标、现在覆盖到什么程度、还缺什么。

## 一、四份数据的分工

| 文件 | 条数 | 构成 | 用途 | 进训练 |
|---|---|---|---|---|
| `cloud/test/cases.json` | 99 | 诈骗 59 / 正常 40 | 训练主集（人手整理） | 是 |
| `cloud/test/synthetic.json` | 447 | 诈骗 300 / 正常 147 | 训练扩充（大模型换说法） | 是 |
| `cloud/test/holdout.json` | 35 | 诈骗 20 / 正常 15 | **唯一评估集** | **否，一行都不许进** |
| ChiFraud（外部） | 411,434 | 诈骗 59,106 / 正常 352,328 | 难负样本池 | 可选，抽 0~1000 条 |

划分是硬性的：`train_tinybert_ms.py` 里训练只读 `cases.json` + `synthetic.json`，
`holdout.json` 只在最后打分时读一次。

### ChiFraud 为什么没有当正样本用

文档把它列为第一项训练数据，我们下全了（95 MB，sha256 与官方 `metadata.json` 一致，
411,434 条与官方登记的 59,106 + 352,328 完全吻合）。但打开数据后：

| 官方类别 | 条数 | 实际内容 |
|---|---|---|
| 招嫖色情 | 26,187 | `广州白云区哪些足疗店(可以做服务【威v心=…】` |
| 赌博博彩 | 10,693 | `幸运飞艇微信群赛车群【…】` |
| 虚假证明 | 7,073 | `秦皇岛市医院诊断证明都办休假的不？【Q/薇:…】` |
| 违禁药品 / 虚假办卡 / 违规提现 / 办假证 / 手机卡 / 黑贷 | 15,153 | 卖银行卡四件套、黑户下款 |

59,106 条诈骗里，「安全账户」出现 **0** 次、「注销校园贷」**0** 次、「通缉」2 次、
「洗钱」7 次、「刷单」8 次、「涉案」11 次。含 2 个以上电信诈骗词的仅 76 条，
剔除「留微信号/代办/套现」广告体后只剩 **7 条**。

反过来验：留出集 20 条诈骗里，**13 条在 ChiFraud 中一个词都不命中**，包括冒充公检法
（"资金核查""国家指定账户"）、冒充亲友（"爷爷我是你孙子"）、刷单返利、数字人民币。

**它的正负样本边界是「有没有在推销黑产、留微信号」，不是「有没有在骗人转账」。**
照字面把 59,106 条当正样本训练，模型学到的是错的分界线。所以：
- **正样本**：只用 cases + 合成（同域）
- **负样本**：可以抽它的正常文本当「难负样本」（网页/广告/推销，形似推销但无欺骗），
  用 `--chi-neg N` 控制条数，抽多少要在报告里写明

## 二、标注口径

一条短信判为**诈骗**，必须至少命中一条：

1. 要求把钱转到指定账户、平台、二维码
2. 索要短信验证码、银行卡密码、身份证号
3. 要求下载软件、开屏幕共享、远程协助
4. 先制造恐慌或紧迫（涉案、停用、限时、亲人出事），再要求配合操作

**不算诈骗**（即使提到钱、即使来自陌生人）：

- 纯商业推广，无欺骗成分（装修、卖房、促销、招聘）
- 机构正常通知：账单、到期、续费、安检、体检、津贴发放
- 亲友日常联络
- 反诈宣传短信本身（内容含"诈骗"二字，但不是诈骗）
- 陌生人正常联系：邻居、社区、快递、维修、上门服务、老年大学、报刊订阅

**边界处理约定**

| 情形 | 标为 | 理由 |
|---|---|---|
| 正经贷款广告，未收前期费用 | 正常 | 骚扰但没骗，误报会消耗信任 |
| 让加微信的兼职信息，没提垫付 | 正常 | 只有诱导，没有资金动作 |
| 冒充熟人但只寒暄没提钱 | 正常 | 单条不足，靠规则积累、靠多轮 |
| 银行短信带短链接（官方域名） | 正常 | 不能因有链接就判诈骗 |
| 银行短信带短链接（非官方域名） | 诈骗 | 域名是判定依据 |

## 四、正常短信覆盖（这是真正的缺口）

| 类型 | cases | 合成 | 训练合计 | 留出 |
|---|---|---|---|---|
| 银行通知 | 5 | 17 | 22 | 1 |
| 验证码 | 2 | 0 | 2 | 1 |
| 生活服务 | 10 | 18（快递） | 28 | 2 |
| 政务通知 | 4 | 18 | 22 | 1 |
| 反诈宣传 | 2 | 0 | 2 | 1 |
| 家人 | 6 | 18 | 24 | 2 |
| **陌生正常** | **11** | **0** | **11** | **7** |
| 医院健康 / 物业社区 / 电商订单 / 招聘求职 | 0 | 18×4 | 72 | 0 |

**「陌生正常」这一类，训练集只有 11 条，合成数据里一条都没有，而留出集占了 7/15。**
这就是误报全部落在这里的原因——模型没见过「陌生人主动联系老人、但事情本身正常」的长相。

三条漏网样本（新模型，p 值）：

```
p=0.711  老张，下周老年大学书法班开课，记得带毛笔
p=0.996  您好，我是银行大堂经理，您的存单下周到期，有空可以来网点办理续存
p=0.980  您的报纸订阅明年续订价格不变，有需要可以到邮局办理
```

对照同类却判对的（p≈0.001）：燃气入户安检、社区网格员上门登记、菜市场订排骨、
维修师傅上门——这些在训练集里有，那三条没有。

**结论：瓶颈是负样本的场景广度，不是正样本数量。** 与文档「工作量主要在整理、
清洗、标注数据」一致。

## 五、缺口与采集计划

`陌生正常` 需要按子场景铺开，目标每场景 ≥8 条，共约 100 条：

| 子场景 | 现在 | 目标 |
|---|---|---|
| 邻居 / 街坊 / 广场舞 / 楼下小店 | 2 | 8 |
| 社区网格员、居委会、上门登记 | 3 | 8 |
| 老年大学、兴趣班、老年活动 | 0 | 8 |
| 报刊订阅、邮局、邮政业务 | 0 | 8 |
| 银行柜台业务（到期、续存、回单） | 0 | 8 |
| 保险回访、体检回访、慢病随访 | 0 | 8 |
| 水电气暖、有线电视、宽带续费 | 1 | 8 |
| 家政、维修、废品回收、送水送奶 | 2 | 8 |
| 亲友的同事/同学/司机代传话 | 2 | 8 |
| 村委/街道通知、红白事、邻里互助 | 1 | 8 |

**采集来源按干净程度排序：**

1. **真人手机里的真实短信**（最干净）——自己和家人的收件箱，去掉姓名号码即可，标注 `source: 真实收集`
2. **公开政务/银行的标准短信模板**——官网、公告里常见，标注 `source: 公开模板`
3. **大模型按场景扩写**（现用办法）——标注 `source: deepseek-gen` 且 `synthetic: true`，
   报告里必须写明是合成数据
4. **ChiFraud 正常文本**——分布是网页新闻，只能当难负样本，不能当短信负样本

第 3 条能补量，但补不了「真实场景的长相」。第 1 条才是最该做的，也最便宜：
拿几张手机截图就行。模板见 `cloud/test/collect_normal.csv`。

## 六、评估纪律

1. **留出集只评不改。** 训练脚本不加载它，生成脚本只拿它查重（4-gram Jaccard ≥ 0.3 丢弃）。
2. **改了数据要报轮次。** 第一轮（仅 cases）与第二轮（+合成）的数字分开写，
   不能只报最好的那次。
3. **不许照着留出集的错误补样本再报同一份留出集。**
   这样报出来的数会虚高。要做就必须：或另建一个没碰过的第三集，或在该行明确写
   「第二轮针对性调优，数字偏乐观」。
4. **合成数据必须标 `synthetic: true`。** 它和真实收集的样本分布不同，
   报告里要分开报。

## 七、复现

```bash
# 1. 生成合成样本（只读 cases.json，holdout 仅用于查重）
node cloud/test/gen-synthetic.js

# 2. 训练 + 评估（训练集 = cases + synthetic，留出集只打分）
PYTHONPATH= D:/models/.conda-ms/python.exe tools/train_tinybert_ms.py \
    --graph --epochs 12 --lr 1e-4 --max-len 96 --tag syn

# 3. 掺入 ChiFraud 正常文本当难负样本
PYTHONPATH= D:/models/.conda-ms/python.exe tools/train_tinybert_ms.py \
    --graph --epochs 12 --lr 1e-4 --max-len 96 --chi-neg 1000 --tag syn+chi
```

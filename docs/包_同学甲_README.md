## 三、六处改动（详细改法在清单里）

| # | 原来 | 现在 | 不改会怎样 |
|---|---|---|---|
| 1 | 基线 353 告警 / 7 上报 | **428 / 32** | 迁移成功也会被判失败，然后瞎折腾 |
| 2 | 先建表+迁移、最后导 dump | **先导 dump，再 schema，最后两个迁移** | dump 里带 `DROP TABLE`，前面的迁移全作废 |
| 3 | 提了两个 sql 文件 | **三个**（漏了 `migrate_20261110_callaudio.sql`） | 录音复盘的上报被 MySQL 截断成空串，**不报错** |
| 4 | 新机器 scp 旧 `.env` | **必须改** `RDS_HOST`/`REDIS_URL` | 新机器连自己 localhost，`rds:false` 但看着像成功 |
| 5 | RDS 只放 `192.168.0.211/32` | 新机器 IP 要**再追加**（或放宽到 `/24`） | 新机器连 RDS 超时，录屏现场卡住 |
| 6 | `systemctl stop mysql` 就算完 | 还要**摘掉 unit 里的 `Wants=mysql`** | 每次重启 yindun 都把 mysql 拉回来 |

第 6 条的原理：`Wants` 是显式依赖，跟 `enable/disable` 无关。unit 里那两行是
「数据库和代码装同一台机器」阶段的写法，迁到 RDS 之后就不成立了。

## 四、一条铁律

**老机器上不要跑 `install.sh` 覆盖 `/opt/yindun`。**

脚本第 5 步是 rsync 覆盖。你手上那份代码快照是 11-18 之前的，而线上今天 21:21 刚把规则从
3.4（212 词）升到 **3.6（220 词）**、还新上线了 OCR。跑一次就把这些全冲掉。

- `install.sh` **只用于第三阶段的新机器**（那台是干净的，覆盖无所谓）
- 老机器上要更新代码，我这边推，推完看 `/api/health` 里的 `rules.version`

## 五、建议顺序

1. 先登上去跑 `〇-1` 那段，把 **428 / 32** 和五项基线截图存好
2. 开 RDS（记住内网地址）→ 开 DCS
3. 按 v2 清单第三节的**四步顺序**导库，导完核对 428/32
4. 改 `.env` → 重启 → `health` 里 `rds/redis` 双 true
5. 重启一次再确认记录还在 → 这时才停本机 mysql，并摘掉 unit 里的 `Wants`
6. 第三阶段等队长说「代码冻结」，用 `deploy/install.sh`，`.env` 换成 RDS/DCS 内网地址

有卡住的地方直接把报错贴回来，别自己猜着改。

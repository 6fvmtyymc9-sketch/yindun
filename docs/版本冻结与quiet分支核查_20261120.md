# quiet 分支核查 + 版本冻结（2026-11-20）

> 起因：我先前判断 `SmsReceiver.aiReview()` 里的 `quiet` 分支是「永远不执行的死代码」，
> 据此提出三种改法（放宽 / 收窄 / 删除）。**这个判断是错的**，本文记录核查过程与更正。
> 结论：**代码不改**，与 `docs/模型选型.md`（老师 11-09 提交）和《SFT 下一步计划》均不冲突。

## 一、我错在哪

我当时只看了下面这一行：

```java
boolean quiet = "none".equals(localLevel);
```

再结合「陌生号最低 15 分 = watch」，就推出「`none` 永远不成立、这条分支永远不走」。
**漏掉了一个前提**：`aiReview` 的入参 `localLevel` 不只来自陌生号。

## 二、实际的可达路径

`SmsReceiver.shouldReview()`（第 335~373 行）的门槛是：

```java
boolean belowWarn = "none".equals(r.level) || "watch".equals(r.level);
if (!belowWarn) return false;

boolean stranger   = NumberInfo.STRANGER.equals(who);
boolean longEnough = text != null && text.length() >= 15;
if (!stranger && !longEnough) return false;      // ← 关键：非陌生号也能过，只要够长
```

所以 `localLevel == "none"` 的路径是**通讯录号码 + 正文 ≥ 15 字 + 本地一分未中**。
实测三条（`cloud` 下 `node -e` 直接调 `Judge.scoreSms`）：

| 短信 | who | 分数 | 等级 |
|---|---|---|---|
| 妈，我明天下午三点到，你帮我把钥匙放门口，我拿了就走 | contact | 0 | **none** |
| 老婆，我今天加班到八点，你先吃不用等我 | contact | 0 | **none** |
| 【银行】您的账户涉嫌洗钱，请配合核查 | service | 50 | warn |

前两条都是 0 分 / none、长度都过 15 字 → **会送云端复核**，且 `localLevel="none"`
→ `quiet=true` → 只推子女、不弹老人。**这条路是活的，而且走的正是它该走的场景。**

## 三、为什么现状是对的

把三条线摊开看，quiet 分支的位置正好合理：

| 本地判断 | 送不送云端 | 云端说可疑时 |
|---|---|---|
| warn 及以上 | 不送（警报已发） | — |
| **none**（毫无依据，绝大多数是家人/通讯录的日常长消息） | 送 | **只推子女，不弹老人** |
| watch（已经有词命中） | 送 | 弹老人 |

设计意图（原注释写的「快递取件、社区体检通知、医院预约」）里那几类其实都是**陌生号**，
走的是 watch 那一栏（陌生号基础分 15），所以注释举的例子和代码实际拦的对象并不完全对应 ——
但**行为本身没错**：本地毫无依据时把线索交给人判断，本地有依据时才惊动老人。

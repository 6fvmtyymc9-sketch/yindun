## 二、三条判定有误的（附实测证据）

### 2.1 第 2 条｜`.so` 压缩方式 —— **判断方向相反**

**码道原话**：
> 「AGP 在 `useLegacyPackaging=true` 时对 `.so` 用 STORED（不压缩）。
> 这是最可能导致真机安装失败的问题。」
> 并给出改法：`z.write(..., zipfile.ZIP_STORED)`

**实测**（`unzip` 读两种产物的 `compress_type`）：

| 文件 | build2.sh 产物（改前） | Gradle 产物 |
|---|---|---|
| `lib/arm64-v8a/libmindspore-lite.so` | DEFLATED | DEFLATED |
| `lib/arm64-v8a/libmindspore-lite-jni.so` | DEFLATED | DEFLATED |
| `lib/armeabi-v7a/libmindspore-lite.so` | DEFLATED | DEFLATED |
| `lib/armeabi-v7a/libmindspore-lite-jni.so` | DEFLATED | DEFLATED |

**结论**：两条构建路线本来就一致，都是 DEFLATED。`useLegacyPackaging=true` 的语义是
**「沿用旧的打包行为」= 压缩**，码道把语义理解反了。

**照它改的后果**（我真改了，然后测出来的）：

```
改 STORED 后：APK 54M，build2 与 Gradle 的 .so 压缩方式不一致
改回 DEFLATED：APK 48M，两路线一致
```

体积凭空多 6M，还制造了它本想消除的那种不一致。

**另一条反证**：真机 9/9 全通过的那一版，`.so` 就是压缩的。
「压缩的 `.so` 在国产 ROM 上 `System.loadLibrary` 失败」是 Android 2.x 时代的传说，
当前 manifest 声明 `extractNativeLibs="true"`（安装时解压到 `nativeLibraryDir`），
这种模式下压不压缩系统都能正确提取。

**处置**：保持 DEFLATED，并在 `build2.sh` 里写了一段注释记录这次实测，
避免以后有人再被同一条意见带偏一遍。

### 2.2 第 4 条｜`READ_SMS` 能不能删 —— **只看了一半代码**

**码道原话**：
> 「`READ_SMS`：银盾只需要接收短信（`RECEIVE_SMS`），不需要读取短信数据库。
> `SmsReceiver` 通过广播接收短信正文，不需要读 SMS provider。」

**实测**：它只看了 `SmsReceiver`，漏了举报页：

```java
// ReportActivity.java:322
Cursor c = cr.query(Uri.parse("content://sms/inbox"),
        new String[]{"address", "body"}, null, null, "date DESC");
```

`pickFromSms()` 读收件箱最近 10 条，让老人自己挑「哪条看着不对」再上报。
这是举报页两条入口之一（另一条是手动粘贴），删掉 `READ_SMS` 会直接砍掉它。

而且这段代码有明确的产品理由，注释就写在上面：

> 「不筛发件人、不做本地预判 —— 让老人自己决定"哪条看着不对"，
> 我们不能替他判断，也不能因为本地规则觉得没事就不给他看。」

**处置**：保留 `READ_SMS`，在 Manifest 里补注释写清两条短信权限各自的用途
（`RECEIVE_SMS` 管「新短信进来」，`READ_SMS` 管「翻已收到的」），
并注明「国内应用市场对短信类权限审核最严，提审时要写清用途」。

### 2.3 第 5 条｜明文 HTTP 改白名单 —— **忽略了地址可配**

**码道原话**：
> 「`networkSecurityConfig` 只对该 IP 放行明文是最合理的方案。」

**实测**：云端地址是**用户可配的**：

```java
// DrillNet.java:44
static final String DEFAULT_BASE = "http://123.249.25.139:8080";

// DrillNet.java:53
static String base(Context c) {
    String v = sp(c).getString(K_BASE, "");
    if (v == null || v.trim().length() < 8) return Notifier.getBackend(c);
    return v.trim();
}
```

`DrillNet.java:27` 的注释还写着「同一 WiFi：`http://192.168.x.x:8080`」——
部署的人可能填局域网 IP 做演示。

**如果把明文限制成只对 `123.249.25.139` 放行**，改地址的场景会**静默连不上**：
App 不报错、不提示，只是所有云端功能没反应。对 70 岁的用户来说这是最难排查的故障。

**处置**：不改，在 `AndroidManifest.xml` 里写清三条约束
（裸 IP 无证书 / 地址可配 / 自签证书老人装不了），
并注明「将来有了域名和证书，改成 networkSecurityConfig 白名单即可，改一个文件」。

## 三、采纳并已改的四条（部署侧，码道全对）

### 3.1 第 7 条｜systemd 单元没有 `User=`（真缺陷）

**原状**：`install.sh` 建了 `yindun` 用户、`chown -R` 了整个 `/opt/yindun`，
但生成的单元里只有 `Type/WorkingDirectory/ExecStart/Restart/RestartSec/LimitNOFILE`
——**服务实际以 root 运行**。建了用户却不用，这个自相矛盾迟早被评审看出来。

**已改**（`deploy/install.sh:236~257`）：

```ini
[Service]
User=yindun
Group=yindun
...
MemoryMax=768M

NoNewPrivileges=true
PrivateTmp=true
ProtectHome=true
ProtectSystem=strict
ReadWritePaths=/opt/yindun
RestrictSUIDSGID=true
CapabilityBoundingSet=
```

**与码道建议的两处差异**：

| 项 | 码道建议 | 实际取值 | 理由 |
|---|---|---|---|
| `MemoryMax` | 512M | **768M** | 服务正常 150~300MB，但跑模型调用峰值约 500MB；512M 会在正常业务下误杀 |
| 加固项 | 列了 7 项 | 全加 | 无差异 |

另按码道提醒补了 `.env` 权限：`chmod 640` + `chown yindun:yindun`，
否则服务以 `yindun` 身份跑起来读不到 root 创建的 `.env`。

### 3.2 第 8 条｜`rsync` 不带 `--delete`（真缺陷）

**码道判断的风险准确**：新版删掉/改名的文件会残留在服务器上，
旧的 `rules.json` 还在 `require` 路径上 → 线上实际加载的规则与脚本打印的版本号不一致。

**已改**（`deploy/install.sh:123~130`）：

```bash
rsync -a --delete \
  --exclude '.env' --exclude '.git' \
  --exclude 'node_modules' \
  --exclude 'data' --exclude '.drill-last' \
  --exclude 'tools' \
  "$pick"/ "$APP_DIR"/
```

**排除清单与码道建议的差异**（我按实际代码核过，不是照抄）：

| 码道说排除 | 实际目录 | 说明 |
|---|---|---|
| `data/` | ✅ `cloud/data/` | 含 `data/pairs.json`（配对关系）+ `data/voice/`（语音文件） |
| `voice/` | ❌ 不存在独立目录 | `Voice.js:63` 用的是 `path.join(__dirname,'..','data','voice')`，已在 `data/` 内 |
| `drill/` | ❌ 不存在 | 实际是 `cloud/.drill-last` 单个文件（`Drill.js:302`） |
| `node_modules` | ✅ | 不排除则每次部署都要重装 |
| — | ➕ `tools/` | 运维脚本（`check_storage.js` 等），不属于发布物 |

排除清单是按 `grep -rn "writeFileSync\|mkdirSync" cloud/src/*.js` 全扫后确定的，
所有运行期写入点只有三处：`Pairs.js:48/49`、`Voice.js:64/120/142`、`Drill.js:309`，全部覆盖。

另加了一道保险：`[[ -f "$pick/src/server.js" ]] || die` ——
路径判断错了就拒绝执行 `rsync --delete`，避免删错目录。

### 3.3 第 9 条｜`Restart=always` 无速率限制（真缺陷）

**已改**：

```ini
[Unit]
StartLimitIntervalSec=60
StartLimitBurst=5
```

60 秒内最多重启 5 次，超过进 failed 等人工处理。不加的话 `.env` 写错会变成
「每 3 秒重启一次」的无限循环，1 核 2G 的机器会被拖到 SSH 都登不上。

码道的健康检查判断我也认同并保留：`rds:false` / `redis:false` 只 warn 不失败，
因为 RDS/DCS 可能临时不可用，服务能降级内存运行；判失败会导致反复重启，更糟。

### 3.4 第 10 条｜`env.js` 同名键取第一个值（真缺陷）

**原实现**（边读边写）：

```js
if (m && process.env[m[1]] === undefined) process.env[m[1]] = m[2];
```

`=== undefined` 判断让**同 key 的第二行被直接跳过**，与标准 `dotenv`（后者覆盖前者）相反。

**这不是理论风险，已经踩过**：2026-11-19 下午甲用 `>>` 追加
`RATE_REPORT_PER_DAY=3000`，重启后 `health.limits.reportPerDay` 仍是 1200，
排查了半天才发现是取值语义问题。

**已改**（`cloud/src/env.js:24~35`）：先整理解析进 `Map`（后者覆盖前者），
再统一灌进 `process.env`（已存在的系统变量不动，保留「系统环境变量优先」这条规则）。

**单测**（三种情况全过）：

```
重复键取: second   (期望 second)  ✅
系统变量优先: from_system (期望 from_system) ✅
普通键: ok        (期望 ok)      ✅
```

**保留了码道没提的一点**：系统环境变量仍然优先于 `.env`。
码道建议「直接换成 `require('dotenv').config()`」，但标准 dotenv **默认是 `.env` 覆盖系统变量**
（除非传 `override:false`），换库会改变现有行为。自实现只改取值顺序，是最小改动。

## 四、不采纳的第 1 条与部分采纳的第 4 条

### 4.1 第 1 条｜双构建收敛 —— 方向对，但改法有风险

**认同的部分**：Gradle 作主路，`build2.sh` 只作「不依赖 Gradle 网络」的应急备份。
`aapt2 link` 没传 `--compile-sdk-version` 只影响 `aapt2 dump badging` 的元数据，
不影响安装运行 —— 这两点判断准确。

**不采纳的部分**：「把 `javac -source 8 -target 8` 改成 `-source 17 -target 17`」。

原因：`build2.sh:50` 的 d8 调用是

```bash
"$BT/d8.bat" --lib "$PLATFORM" --min-api 24 --output $OUT/dex \
```

**没有显式的 desugaring 配置**。改成 source 17 后，javac 会生成 Java 9+ 的字节码形态
（`invokedynamic` 字符串拼接、nestmates 等），d8 能否全部正确处理没有验证过，
而 `--min-api 24` 对某些 desugar 结果有约束。

**现在代码不用 Java 9+ 语法，改它等于用一个未验证的风险换一个当前不存在的收益。**
真要用 Java 17 语法，正确做法是**切到 Gradle 构建**，不是改 build2.sh。

这条已记入「已知约束」：**代码必须保持 Java 8 语法兼容**（双构建的前提）。

### 4.2 第 4 条｜权限清单 —— 逐条核，三条不动、一条补理由

| 权限 | 码道建议 | 处置 | 依据 |
|---|---|---|---|
| `READ_SMS` | 去掉 | **保留** | `ReportActivity:322` 读收件箱（见 2.2） |
| `QUERY_ALL_PACKAGES` | 换 `<queries>` | **保留 + 补注释** | 见下 |
| `MANAGE_EXTERNAL_STORAGE` | 无替代方案（认同） | 保留 | 国产 ROM 通话录音在自定义路径，不在 MediaStore |
| `FOREGROUND_SERVICE_DATA_SYNC` | 考虑改 `phoneCall` | **保留 + 补注释** | 见下 |

**`QUERY_ALL_PACKAGES`**：码道说「识别银行 App 靠它」——这条**不准**。
银行识别走的是 `PACKAGE_USAGE_STATS`（`AppWatcher.java:168` 的 `UsageStatsManager`），
不需要包可见性。它真正被用的地方只有两处：

1. `InstallReceiver` 判断「是不是从应用商店装的」（`getInstallerPackageName`，**不需要**这条权限）
2. `InstallReceiver.label()` 拿新装 App 的显示名（`getApplicationInfo(pkg, 0)`，**需要**）

第 2 处有 `catch` 兜底，拿不到就返回包名。所以它**不是必需**，但去掉会让提示
从「刚装的那个「骗子理财」」退化成「刚装的那个「com.xxx.yyy」」——对老人不友好。

换成 `<queries>` + LAUNCHER intent 理论上可行（银行 App 都有启动图标），
但需要真机复验 `label()` 是否还拿得到，**当前是交付冻结前的稳定期，不值得为这点收益引入未验证的改动**。
已在 Manifest 里把这个取舍写清楚。

**`foregroundServiceType`**：码道提到 Android 15 起 `dataSync` 有严格限制，这个提醒有价值。
但改成 `phoneCall` 会**更糟**——Android 14+ 的 `phoneCall` 要求 App 是默认拨号器
或持有 `MANAGE_OWN_CALLS`，我们两者都没有，声明了服务直接起不来。

`GuardService` 实际做的是「轮询云端指令 + 上报事件」，`dataSync` 是当前唯一可行归类。
已在 Manifest 注明：targetSdk 升到 35 时要重新评估（届时可考虑 `specialUse` + 向市场说明用途）。

## 八、审查没提、但顺着它的提醒查出来的两个问题

### 8.1 `build.gradle` 缺签名配置直接抛异常 —— 评委 clone 下来第一条命令就失败

这不在码道的 10 条里，是它「做不了清单」第 6 条（`--offline` 在评委环境的可用性）
让我回头重看了构建入口，结果发现更硬的问题：

```groovy
// app/build.gradle（改前）
['yd.storePassword', 'yd.keyPassword'].each { k ->
    if (!localProps.getProperty(k)) {
        throw new GradleException("缺少签名配置 ${k}：请在 local.properties 中补齐 ...")
    }
}
```

而 `local.properties` 在 `.gitignore` 里。**新 clone 的工程一定没有它 → `./gradlew assembleDebug`
必然抛 GradleException → 评委拿到的工程根本构建不起来。**

更糟的是 **README 写的是「没有密钥就用 debug 签名，能装能跑」**——
和代码行为完全相反。这属于「文档说一套、代码做一套」，比单纯的缺陷更伤。

**已改**：缺配置时 `println` 一段醒目提示 + 降级到宿主机默认 debug 钥匙，不再抛异常。

**实测两种状态**：

| 状态 | 构建 | 签名 SHA-256 |
|---|---|---|
| 有 `local.properties` | ✅ BUILD SUCCESSFUL 42s | `1e10dabe`（项目钥匙） |
| 无 `local.properties`（模拟评委） | ✅ BUILD SUCCESSFUL 40s | `0640e853`（系统 debug 钥匙） |

无钥匙那版 APK 同样能装能跑，只是不能覆盖安装已发布版本——这正是 README 原本想表达的意思，
现在代码终于和它一致了。

### 8.2 README 的构建小节缺三件必须说清的事

1. **首次构建需要联网**（Gradle 发行版从腾讯镜像拉、依赖从阿里云镜像拉），
   `--offline` 只是我们本地加速用，写进 README 会让评委以为必须离线
2. **`ANDROID_HOME` 要设**，否则 AGP 找不到 SDK
3. **`sdk.dir` 也是 `local.properties` 的一项**，原来只提了签名四项

三条都补进去了，另加一条「代码必须保持 Java 8 语法兼容」的约束（双构建的前提）。

## 九、这批审查的教训（答辩可用）

1. **审查工具的判断必须落到实测**。10 条里 3 条结论反了，比例不低。
   它看的是「代码片段像什么」，不是「跑起来是什么」。
